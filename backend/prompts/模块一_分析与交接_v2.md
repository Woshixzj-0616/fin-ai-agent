# 模块一 V2 · 分析与交接阶段

这次调用只根据用户消息中的结构化年报事实进行有限分析，不重新猜测或改写抽取的数字。完整的财务分析规则和边界已在主提示中；没有保留原文和出处的内容不得当成事实。

请把分析写成可检查的链条：发生了什么变化 → 对应的分项、指标和期间 → 年报给出的解释 → 依据数据可以提出的有限分析 → 尚未证实的其他解释。收入增加不等于盈利改善；收入结构占比不等于利润贡献；销量、售价、份额、竞争优势只能在年报有对应资料时说明。

仅分析有证据支持的经营驱动、行业背景和战略结果；对行业/竞争叙述指出来源、时点和适用范围。风险条目是披露事项，不代表损失已发生。不能跨年度、范围或收入指标作比较。遇到缺少上期绝对值、单位或口径时提出待查问题，不能填补数字。

给出与事实直接相关的后续问题，分别指向盈利来源、资产质量与周转、利润现金兑现或债务资金压力。每个问题尽可能沿用事实中的 PDF 页码和原文摘录；不得增加输入事实中没有的页码或摘录。

只返回合法 JSON，字段限于：`growth_drivers`、`industry_context_analysis`、`strategy_analysis`、`follow_up_checks`、`summary`、`summary_source_pages`、`summary_evidence_quote`、`uncertainties`。其中 `industry_context_analysis` 项用 `topic`、`analysis`、`limitation`；`strategy_analysis` 项用 `aspect`、`analysis`、`limitation`。`growth_drivers` 项用 `driver`、`fact_type`、`description`、`source_pages`、`evidence_quote`、`limitation`；`follow_up_checks` 项用 `question`、`reason`、`next_module`、`source_pages`、`evidence_quote`。不要重复输出收入分项和事实表。
