# 项目说明与验收

工程位于`new`。这是学生竞赛的可检查原型：5个功能模块、1个测试文件，只保留`data`与`results`两个业务子目录。模块之间直接导入，不另建包、服务层或配置目录。

## 四步学习与接手

| 步骤 | 看什么代码 | 输入与处理 | 独立检查的成果 |
|---|---|---|---|
| 1. 固定首版范围 | main.py、run.ps1 | 贵州茅台2024年报，data/samples.json中的8句草稿及预填字段 | demo能运行；能解释核查项的公司、年度、指标、金额或同比 |
| 2. 材料与来源登记 | materials.py | 检查原有9份PDF的指纹、大小、可读页面、公司与年份；或查询巨潮下载 | manifest.csv能逐条找到文件；materials.jsonl保留历史观察 |
| 3. 财务证据抽取 | extract.py | 从清单选PDF，用表头文字和坐标确认年份、调整列、单位、币种和口径 | evidence.json保留原文与坐标；--render把对应原页直接存到results |
| 4. 确定性核查 | finance.py | 先检查可比性，再用Decimal换算、计算同比及比较陈述精度 | analysis.json保存操作数和依据；报告及test.py提供可复算结果 |

练习顺序：先运行demo，阅读报告；只修改samples.json里S1的金额，再运行观察变化；随后阅读两份2023年报中调整前后列顺序不同的例子；最后查看finance.py与对应测试的边界输入。

```python
from finance import convert, yoy, ratio, percentage_points, compare_amount

print(convert("1.23", "亿元", "万元"))
print(yoy("0", "100"))
print(yoy("50", "-100"))
print(ratio("1", "4", as_percent=True))
print(percentage_points("15", "10"))
print(compare_amount("170899152276.34", "元", "1708.99", "亿元"))
```

预期分别为12300万元、-100%、负基期需复核、25%、5个百分点、按陈述精度匹配。金额输入用字符串，避免浮点数精度损失。

## 材料登记

`materials.jsonl`是追加台账；`manifest.csv`是可重建的当前视图。相同公告ID与文件指纹对应同一材料，重复下载复用文件。不同公告或不同指纹分别登记，不覆盖原文件。读取时，接口时间戳核实记录优先于旧清单记录，同级选择最近一次。

| 字段 | 含义 |
|---|---|
| company_code / company_name / report_year | 公司和报告年度 |
| announcement_id / document_id / sha256 | 公告标识、材料身份和内容指纹 |
| local_file / source_url | 本地文件与外部来源 |
| disclosed_at / disclosure_date_status | 披露时间及其核实状态 |
| first_ingested_at / checked_at / retrieved_at | 首次入库、校验、真实联网获取时间；本地导入的retrieved_at为空 |
| version_policy / as_of / needs_version_review | 全文选择策略、检索截止日和版本复核标志 |
| license_status | 来源使用条款登记状态 |

旧清单的日期保留原值并标记未核实；接口时间戳统一转为北京时间。`first`和`latest`只决定选哪份全文，不能替代人工判断更正公告的会计影响。下载过程保存原始响应、候选公告和失败原因，接口异常不会当成成功。

## 证据字段与口径

| 字段 | 含义 |
|---|---|
| evidence_id / metric / original_label | 证据标识、程序指标与原文名称 |
| report_year / period_year | 报告年度和金额所属年度，二者可能不同 |
| period_start / period_end / duration_months | 完整年度期间，本版不混入季度累计值 |
| value / raw_value / unit | 可计算字符串、原文字符和原单位 |
| normalized_value / normalized_unit | 统一为元后的值与单位 |
| currency / currency_evidence | 币种及依据 |
| scope / scope_evidence | 归属口径及确认路径 |
| adjustment / comparison_group | before、after或as_reported，以及同一报告同一表的比较组 |
| source_file / source_sha256 / announcement_id | 材料引用及完整指纹 |
| page / page_label | 从1开始的PDF页序，以及可能为空的内部页标签 |
| value_bbox / label_bbox / table_bbox | 数值、原文名称与表格坐标 |
| year_header / adjustment_header / reported_yoy | 年份、调整表头、披露同比及其位置 |
| issues | 无法确认的字段或缺失项，留待复核 |

坐标以PDF页左上角为原点，格式为[x0,y0,x1,y1]，单位为PDF点。PDF页序可能不同于印刷页码。

归母与扣非归母的股东归属由原文名称确认，两个指标仍分别保存。营业收入和经营现金流本年金额与合并报表同名行交叉定位；历史列沿用同一摘要指标行的范围，该推断保存在scope_evidence。找不到依据时标记unknown。

调整前后数据都保留，同比优先同一报告的调整后上年列；没有唯一可比基期时不随意换用另一年报。`as_reported`表示当前所选报告列示的状态，不等于“未经调整”。证据和计算结果分别保存，计算不会改写原始证据。

## 计算与陈述核查规则

| 情形 | 规则 |
|---|---|
| 元、万元、亿元 | Decimal倍率分别为1、10000、100000000；不进行汇率换算 |
| 正基期同比 | (本期－上期)÷上期×100 |
| 本期0、上期100 | -100%，0不当作缺失 |
| 任一输入缺失 | missing，不填0 |
| 基期为0 | zero_base，不输出常规同比 |
| 基期为负 | 默认negative_base，明示扭亏、归零、减亏、亏损扩大或持平；不自动输出百分比 |
| 明确指定absolute策略 | 允许以abs(上期)作分母，结果保留策略；年度分析默认不开启 |
| 正基期转亏 | 常规公式仍有定义，可能低于-100% |
| 公司、币种、口径、期间或比较组冲突 | not_comparable，先处理可比性 |
| 上年调整前后并列 | 使用调整后；只有调整前且没有可比依据时不自动使用 |
| 比例分母为0 | zero_base |
| 10%变为15% | 增加5个百分点；相对增长50%，两种运算分开 |
| 陈述金额比较 | 先换为陈述单位，再按陈述小数位数ROUND_HALF_UP；1.005→1.01，-1.005→-1.01 |

结构化核查输出四类结果：证据支持、确认错误、证据不足、口径冲突／需人工复核。结果包含原句、核查项、证据标识、文件页码、计算过程、原因和修改建议。首版练习支持金额与年度同比；“约”“超过”等区间含义尚未解析。

归母减扣非差额、利润增长而现金流下降是辅助观察线索，不能据此认定财务错误或造假。

## 依赖和历史保存

第三方依赖只有PyMuPDF 1.26.7，版本在requirements.txt固定；其安装元数据声明GNU AGPL 3.0或Artifex商业许可。9份年报的具体来源与使用条款状态在来源台账中登记。公开披露材料不默认等于开放再分发许可。

程序源码、材料与结果都在new。Python支持范围固定为3.12.x（本机验证3.12.14），主入口和测试入口均检查版本；PyMuPDF继续锁定1.26.7，避免在调整Python时同时升级解析库。第三方环境和测试临时数据使用系统临时目录。

这里固定Python的目的是统一可复现环境，并非认定3.13/3.14必然不兼容。PyMuPDF官方说明wheel使用Stable ABI以支持后续Python版本，1.26.7在PyPI提供cp310-abi3的Windows wheel；因此不能仅凭“旧版本wheel装到新Python”就称为侥幸成功。本次终端的默认解释器实测为3.13.7。[安装说明](https://pymupdf.readthedocs.io/en/latest/installation.html)、[1.26.7发布文件](https://pypi.org/project/pymupdf/1.26.7/)。

history.zip保留最近20次完整运行，解压内容合计预算50 MiB，超限时优先淘汰更早的完整运行；若最新一次本身超过预算，保留其完整证据并清除更早历史。events.jsonl仅保留本次日志，历史日志在对应ZIP条目中。归档在同一results根目录通过临时文件校验并原子替换，不创建子目录。before_simplify.zip是固定备份，不自动增长，本轮保留。

本轮改动前已建立本地Git备份，提交d664cb5，标签before-conservative-fixes-20260929。Git保存长期版本，ZIP用于有限的日常运行回看。业务目录依然只有data与results；Git内部管理文件位于.git。

- 不补签人工参考答案：必须由团队成员独立对照PDF签字，程序不能代替该步骤。
- 不放宽指标标签：营业总收入与营业收入不自动合并；增加同义标签前需要新材料和人工口径确认。

## 接入模型：一条完整核查流程

接入前Git保存点为37940b2，标签before-llm-integration-20260929。新增llm_check.py，在main.py提供check-text命令；finance.py、extract.py及其原有判定口径保持不变。无新增第三方依赖。

流程为：读取纯草稿 → 按句编号 → 一次模型结构化录入 → 本地校验字段与原文 → 逐项check_one_claim → finance.check_claim → 保存JSON与Markdown报告。模型不接收年报财务数值，不计算、不决定判定结果，也不生成修改数值。

模型输出必须符合固定JSON Schema。默认请求严格json_schema；显式选择json_object时仍执行同一套本地校验。所有句子必须被核查项或“未拆出”状态覆盖；字段缺失、类型错误、额外字段、截断或拒绝不会被当作成功结果。参数含原文片段和必要上下文，公司、年度、指标及数值必须可回到原文；亿元/万元不得被模型简化为元。

公司通过固定别名白名单解析，不生成新代码。不明公司标记unresolved_company；库外指标标记unsupported_metric；约数或区间标记non_exact_claim；协议/原文对应问题另有model_parse_conflict等原因。报告展示四类业务判定及对应原因，避免把“没有该指标证据”和“模型拆解有问题”混为一谈。

项目默认上下文为人民币完整年度，收入和经营现金流采用合并口径；原文明示美元、母公司或季度时不可沿用默认上下文。普通净利润不自动映射为归母净利润。年度没有明确写出、公司无法识别、预测目标等均保留待复核出口。

现有finance.check_claim的程序建议使用calculation.value作为舍入后的正确值。llm_check.py将该值适配为expected字段；没有修改财务规则或让模型填写expected。发生错误时报告显示程序建议，并保留计算操作数、公式、证据ID、PDF页码、文件指纹和单元格位置。

密钥仅从本次进程环境或隐藏交互输入读取；不使用项目配置文件存储。接口只允许HTTPS，不跟随重定向转发认证。日志保存模型名、服务主机、模式、Token用量与核查结果，不记录请求头、API密钥和服务端原始错误正文。草稿或响应疑似包含凭证时拒绝保存。

data/draft.txt只是操作演示输入；新增自动化检查用于接口协议、程序接线、原文对应、失败分支和凭证不落盘，不是模型测评集。本轮不新增人工金标准、训练/测试集划分或准确率结论。

接入实现的62项功能与回归检查已通过。服务商、Base URL与模型名尚未明确，未将给定凭证发送给任何推测的服务地址，真实模型调用保持未验证状态。

结构化接口参考：[OpenAI结构化输出文档](https://developers.openai.com/api/docs/guides/structured-outputs)。第三方兼容服务是否支持某种模式，以该服务商文档和实际响应为准。
