# 模块五数据接口和结果说明 v1

此说明供调用模块工具的模型和集成人员使用。不要编造没有提供的事实 ID、单位、币种、页码、期间或范围。

## `submit_financial_facts`

一次提交一组对象。字段：

- `fact_key`：本次运行内稳定且唯一的短字符串；后续父/子组成关系用它引用。修订同一事实时沿用原 key，程序保留同一 fact ID 并递增 `revision`，同时使引用旧版本的计算失效；收到失效 ID 后必须重算。
- `label`：报告标签或指标的准确名称。
- `value`：可解析数字字符串；非数值事实填 `null`，不要把“未披露”写成 0。
- `unit` / `currency`：例如 `万元` / `CNY`。未知明确填 `unknown`；不确定的原单位写在 note，不进行规范化计算。
- `scope`：例如 `consolidated`、`parent`，或报告中明确的其他范围；未知填 `unknown`。
- `period_type`：`instant`（时点）、`duration`（期间）、`maturity_range`（原披露到期段）或 `unknown`。
- `period_start`、`period_end`、`as_of_date`：报告原文期间/日期。时点使用 `as_of_date`；期间和期限原段使用 `period_start`/`period_end`；无依据不推日期。
- `measurement_basis`：比如 `statement_carrying_amount`、`contractual_undiscounted_cash_flow`、`ending_balance`、`interest_expense`。全年经营现金流等期间流量用 `period_flow` 或 `statement_cash_flow`；不得标成时点余额。
- `liability_type`：选择 `financing`、`operating`、`cash`、`cash_restriction`、`cash_restricted_net`、`interest_expense`、`equity`、`other`。
- `included_fact_keys`：仅当当前事实是确实包括已建事实的合计时提供。留空表示没有声明组成。
- `evidence`：`[{"page": 12, "quote": "...", "role": "表格数值行"}]`；单位、表头在另一页则另加证据并说明 role。
- `source_context`：语义核对声明。表格使用 `{"kind":"table","row_label":"原文行名","column_header":"原文列标题","unit_label":"原文单位","semantic_status":"confirmed|ambiguous|unknown","review_note":"核对说明"}`；叙述性披露使用 `{"kind":"narrative","semantic_status":"confirmed|ambiguous|unknown","review_note":"如何确认主体、期间和会计含义"}`。对应锚点必须出现在提交的匹配摘录里。`PDF_TABLE_LAYOUT` 存在时，程序会核对行、列和值是否位于同一表格单元格；表格续页若没有重复表头，必须一并提交相邻页的表头证据，程序只在相邻页列结构相同的情况下沿用列位置。无布局或无法匹配时标记 `ambiguous`，不能猜测期别。
- `note`：适用范围、识别不确定性或金额性质。

程序仅接收明确完整读过的页面作为事实证据；初筛摘录不能冒充完整读页。程序检查摘录、数值及所声明的行名/列标题/单位锚点是否能在已读原文中找到。`calculation_eligible` 还要求模型提交语义确认说明，但它不证明 PDF 页面上的空间列关系，也不等同人工复核。表格文字丢失空白单元格、列归属无法判断时，必须标记 `ambiguous`；该事实保留在底稿里，但计算工具会拒绝使用。`not_yet_captured` 仅代表尚未登记，不得写成“未披露”。

## `calculate_solvency_metric`

参数字段随指标变化：

| `metric` | 需要的参数 |
| --- | --- |
| `debt_total` | `fact_ids`: 同范围、同一报告日、已确认的融资债务项目 |
| `operating_liability_total` | `fact_ids`: 同范围、同一报告日、已确认的经营性负债项目 |
| `cash_after_restrictions` | `cash_fact_id`、`restriction_fact_ids`；限制项须证明是同一现金项目的组成 |
| `net_debt` | `debt_fact_ids`、`cash_fact_ids`；展示所选债务/货币资金定义 |
| `net_gearing` | `debt_fact_ids`、`cash_fact_ids`、`equity_fact_id`；权益不为正时不可计算 |
| `asset_liability_ratio` | `fact_ids` 顺序为合并总负债、合并总资产 |
| `current_ratio` | `fact_ids` 顺序为流动资产、流动负债 |
| `quick_ratio` | `fact_ids` 顺序为流动资产、存货、流动负债，结果标注简化口径 |
| `short_debt_share` | `short_debt_fact_ids`、`total_debt_fact_ids`；前者必须通过 `included_fact_keys` 关系确认包含在后者中，且分子、分母须有相同且明确的 `measurement_basis` |
| `operating_cashflow_to_current_liabilities` | `fact_ids` 顺序为全年经营现金流、期初流动负债、期末流动负债 |
| `interest_coverage` | `fact_ids` 顺序为利润总额、对应期间费用化利息支出 |

工具根据事实完整性和可比性选择计算、报错或标明不适用。报告提供相应事实时，应调用全部适用指标；每次计算尝试都会进入 `calculations`，其 `status` 可能是 `calculated`、`not_applicable` 或 `not_calculated`，具体原因应展示并写入分析限制。`not_calculated` 记录不得被模型手算结果替代。运行记录保存自动匹配状态，但不代表行列、单位、范围、期间、会计含义已经人工复核。

## 最终结果

通过 `submit_final_analysis` 保存：

- `headline`：有证据支持的综合判断；资料不足时明确范围。
- `analysis_status`：`complete`、`partial` 或 `insufficient_data`。
- `calculations[]` 保留程序原始 `value/unit`，并增加便于展示的 `display_value/display_unit`；资产负债率、净负债率和短期债务占比用百分数展示，金额用亿元展示。页面应优先使用这两个展示字段。
- `findings`：本公司有意义的专题，不限条数。每项建议含 `title`、`claim`、`evidence_fact_ids`、`calculation_ids`、`analysis_type`（披露/计算/推断）、`alternatives`、`limitations`、`follow_up`。证据状态中的 `source_text_matched_semantics_unreviewed` 表示引用页文字匹配、财务语义仍未人工复核。
- `debt_structure`、`maturity_profile`、`funding_sources`、`cash_availability`、`support_metrics`、`obligations`：有可用数据时组织；缺少可核实内容时使用 `section_status=not_assessed`，不填造数据。每个含数字的条目都要在该条目上引用 `fact_ids`/`evidence_fact_ids` 或 `calculation_ids`；板块摘要可以继承其下条目的引用。引用无效、事实语义未确认、计算失败或含数字但没有结构化证据时标为 `needs_review`。指标若引用程序计算，会附 `program_result`/`program_results` 供页面展示程序计算值和公式。
- `calculations` 可列本次已登记计算 ID；完整输入输出由运行记录保存。
- `data_coverage`：核心数据逐项报告状态。已登记项由程序按事实底稿生成；其余可用 `not_yet_captured`、`not_found_after_search`、`not_disclosed`、`ambiguous`、`not_applicable`。除 `not_yet_captured` 外，必须给 `note` 和 `source_pages`，页码只能引用本次完整读过的页面。系统只检查页码是否读过，不会证明“未披露”搜索已穷尽；该状态仍需按原报告复核。`not_yet_captured` 不等于“未披露”。
- `limitations`：缺失信息及对结论的影响。
- `handoff_questions`：具体交接给模块三/四/六或综合分析的问题。
- 可自由增加 `additional_sections` 和其他对用户有价值的专业内容。

外层固定字段方便软件连接。模块内部的分析结构和专题由报告决定。提交 findings 时引用已登记事实 ID 和计算 ID。系统会检查引用存在、摘录匹配状态及已保留表格布局的行列和值；不能自动确认未提取布局的表格、范围、期间、会计解释或结论整体是否正确。
