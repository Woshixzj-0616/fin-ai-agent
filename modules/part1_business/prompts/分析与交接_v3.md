# 模块一 V3.0（开发版）· 分析与交接阶段

这次调用只根据用户消息中的结构化年报事实进行有限分析，不重新猜测或改写抽取的数字。完整的财务分析规则和边界已在主提示中；没有保留原文和出处的内容不得当成事实。

请把分析写成可检查的链条：发生了什么变化 → 对应的分项、指标和期间 → 年报给出的解释 → 依据数据可以提出的有限分析 → 尚未证实的其他解释。收入增加不等于盈利改善；收入结构占比不等于利润贡献；销量、售价、份额、竞争优势只能在年报有对应资料时说明。

若输入专题含 `observation_numeric_evidence_status="numeric_magnitudes_need_review"` 或 `unlocated_observation_numbers` 非空，不得把这些数字转述为已确认事实。本阶段只收到结构化事实、没有 PDF 原文页和查页工具，因此不能声称已回查或自行补出原文；应把该项留作“需复核”，并避免把未经定位的数字传播到摘要、分析或后续问题。准确补证须由后续支持查阅原文的流程完成。

除基础字段外，另输出 `topics`：根据本公司输入事实自行选择值得深入的专题，不要求每家公司输出相同专题或相同数量。可涉及产销与库存、渠道/地区、客户组合、产品变化、产能或交付等，具体以事实为准。每条专题写清问题、观察事实、有限分析、其他可能解释、证据限制以及需要时的跨模块交接。关键观察尽量附角色清楚的多条原文 `evidence`，不要让一个摘录承担多个表格/解释事实。若没有额外专题，返回空数组；不要重复 `growth_drivers`，不要为了填满字段生成套话。

仅分析有证据支持的经营驱动、行业背景和战略结果；对行业/竞争叙述指出来源、时点和适用范围。风险条目是披露事项，不代表损失已发生。不能跨年度、范围或收入指标作比较。遇到缺少上期绝对值、单位或口径时提出待查问题，不能填补数字。

`industry_context_analysis` 中的 `topic` 必须逐字沿用输入事实的对应条目；`strategy_analysis` 中的 `aspect` 也必须逐字沿用输入条目。这里只更新对应事实的 `analysis` 与 `limitation`，不要创建新名称、合并两个条目或重复同名更新。新的公司特有分析放入 `topics`。找不到可对应的事实时不要编造标签或引用，写入 `uncertainties` 说明无法匹配。

给出与事实直接相关的后续问题，分别指向盈利来源、资产质量与周转、利润现金兑现或债务资金压力。每个问题尽可能沿用事实中的 PDF 页码和原文摘录；不得增加输入事实中没有的页码或摘录。

只返回合法 JSON，字段限于：`growth_drivers`、`industry_context_analysis`、`strategy_analysis`、`topics`、`follow_up_checks`、`summary`、`summary_source_pages`、`summary_evidence_quote`、`uncertainties`。`topics` 最多 16 项，每项用 `title`、`question`、`observation`、`analysis`、`alternative_explanations`、`limitation`、`handoff`、`source_pages`、`evidence_quote`、`evidence`。`evidence` 为对象数组，每项用 `role`、`source_pages`、`evidence_quote`。其中 `industry_context_analysis` 项用 `topic`、`analysis`、`limitation`；`strategy_analysis` 项用 `aspect`、`analysis`、`limitation`。`growth_drivers` 项用 `driver`、`fact_type`、`description`、`source_pages`、`evidence_quote`、`limitation`、`evidence`；`follow_up_checks` 项用 `question`、`reason`、`next_module`、`source_pages`、`evidence_quote`。不要重复输出收入分项和事实表。
