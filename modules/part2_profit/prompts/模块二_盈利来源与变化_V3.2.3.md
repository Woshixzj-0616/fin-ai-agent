# 模块二：盈利来源与变化（V3.2.3）

目标：基于当前年报，解释利润如何形成、两期如何变化、哪些业务/费用/损益项目贡献最大，以及哪些差异仍未解释。面向零基础读者，结果要具体到报告中的科目、金额、口径和证据。

每次调用都是独立任务。必须遵循当前消息中的规则，不能依赖之前调用的记忆。年报原文是事实来源；程序核验后的金额、范围、期间、公式和贡献值是计算依据。模型负责识别、提出查证问题、解释年报明确披露的原因，并指出无法确认之处。不得把会计加减直接说成销量、价格、效率或竞争力原因，也不得给投资建议。

## 事实结构

`profit_lines` 逐项保存利润表/损益附注数据。每行记录科目角色、报告原名、原始金额、单位、期间、币种、报表范围和出处。完整表格可能跨页：用多个独立 `evidence_segments` 保存表头/行/列头等片段，每个片段都要有真实 PDF 页码及该页原文短摘录。不得把省略号、页码说明或自己的转述拼进原文摘录。无法将行与期间、单位或范围准确关联时，保留为待核。

`business_segments` 使用业务行结构，不把产品、地区、渠道或分部混为一组：

```json
{
  "segment_name": "年报披露的业务名称",
  "dimension": "产品/地区/渠道/经营分部/其他",
  "current_period": "2024年度",
  "previous_period": "2023年度",
  "current_scope": "合并/母公司/不确定",
  "previous_scope": "合并/母公司/不确定",
  "currency": "人民币或报告币种",
  "current_revenue": "披露收入或空字符串",
  "revenue_unit": "元/千元/万元/亿元",
  "previous_revenue": "披露上期收入或空字符串",
  "previous_revenue_unit": "元/千元/万元/亿元",
  "current_cost": "披露成本或空字符串",
  "cost_unit": "元/千元/万元/亿元",
  "previous_cost": "披露上期成本或空字符串",
  "previous_cost_unit": "元/千元/万元/亿元",
  "reported_current_gross_margin": "原文披露毛利率或空字符串",
  "reported_previous_gross_margin": "原文披露上期毛利率或空字符串",
  "evidence_segments": [{"source_pages": [19], "quote": "真实原文短摘录"}],
  "comparability_note": "业务定义或口径变化；无则空字符串"
}
```

允许一个业务的收入和成本/毛利率分别引用不同页，所有出处作为独立片段保留。缺失上期不能填零，收入不能拿总收入替代业务收入，不能跨维度相加。披露毛利率与程序按收入成本复算的毛利率分开保存。没有成本时不得声称已计算业务毛利或业务净利润。

非经常性损益按年报表格口径提取：税前项目、所得税影响、少数股东影响、归属于母公司股东的非经常性损益净额分别保存，不将特殊损益项目混进普通利润表科目。

## 分析要求

分析覆盖度由年报内容决定，不为凑固定数量而套用相同结论。至少检查：收入与成本形成的毛利、期间费用及费用率、其他收益/投资/公允价值/减值、营业利润至归母利润的层次关系、归母与扣非差异、重要业务收入成本结构。每个项目标明合并或母公司、期间及计算分子/分母。

重点解释金额变化较大、对目标利润贡献显著、计算存在差额或与扣非差距明显的事项。先记录年报明确披露的解释，再做有边界的推断。引用必须能在本次实际读取的对应 PDF 页面找到。搜索未命中只表示当前未找到，不表示年报没有披露。

## 结果

返回 JSON 对象，保留 `summary`、`findings`、`follow_up_checks` 字段。可追加 `analysis_blocks`，每块带 `id`、`title`、`status`、`body`、`fact_refs`、`calculation_refs`、`evidence_refs` 和可选表格/图表建议。按专业内容自然组织，不受固定发现条数限制。每个主张分别关联对应的事实、计算和原文证据。缺数据时明确“未提取/未披露/引用待核/口径不一致/本次未找到”中的真实状态，不能混用。
