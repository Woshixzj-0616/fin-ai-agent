# 林研 · 模块化财报分析系统

上传一份公司年报，从业务、盈利、资产、现金流、偿债和信息披露六个方面分析企业，并让结论能够回到财报原文中查证。

本项目以 DeepSeek 为分析引擎，将财报分析拆成六个专业模块。每个模块拥有自己的分析问题、工作流程、提示词、计算方法和结果页面，可以独立开发、运行和完善。

## 参赛方向

本项目面向 **2026 年北京市大学生金融人工智能竞赛的赛道一和赛道二**，以六个财报分析模块为共同基础，后续分别适配两个赛道的具体要求。目前尚未涉及赛道五。

## 项目思路

财报分析需要同时理解企业业务、财务数字及其相互关系。我们采用模块化方式，让每个模块围绕明确的问题深入分析，再逐步形成完整的企业判断。

系统由三个部分组成：

- **共同基底**：提供 PDF 读取、原文检索、DeepSeek 调用、证据与计算记录、任务状态和结果保存。
- **专业模块**：决定分析什么、查找哪些资料、如何计算和解释结果，并根据公司的具体情况增加专题。
- **交互界面**：接收用户上传的文件，展示分析进度，分别呈现各模块的结论、依据和待核实问题。

共同基底提供必要的技术工具，各模块保留专业流程和内容设计的自主性。

## 六个分析模块

| 模块 | 主要回答的问题 | 分析内容 |
| --- | --- | --- |
| `part1_business` 业务与经营 | 公司靠什么赚钱，业务发生了什么变化？ | 商业模式、收入结构、业务板块、经营变化及相关背景 |
| `part2_profit` 盈利来源与变化 | 利润从哪里来，为什么增长或下降？ | 收入与成本、费用、利润构成、非经常性因素及盈利变化 |
| `part3_assets` 资产质量与经营效率 | 资产是否有质量，经营资源使用得怎么样？ | 应收账款、存货、长期资产、减值及周转效率 |
| `part4_cashflow` 现金流与利润兑现 | 账面利润是否转化成现金？ | 经营现金流、利润与现金的差异、投资支出及资金流向 |
| `part5_solvency` 偿债与资金安全 | 公司有没有足够的资金应对债务？ | 债务结构、到期压力、流动性、融资及偿债能力 |
| `part6_disclosure` 披露与待核实事项 | 哪些披露值得进一步查证？ | 审计意见、会计政策与估计、关联交易、承诺及或有事项 |

各模块的结果允许采用不同的结构。需要详细拆解的问题可以展开为专题；资料不足的地方应说明缺口，保留待核实事项。

## 分析依据如何保留

系统围绕以下要求组织分析结果：

- 结论保留所依据的财报原文与页码。
- 指标计算保留输入数据、单位、期间及计算方法。
- 区分财报明确披露的事实、程序计算的结果和模型作出的判断。
- 对资料缺失、口径不一致和证据不足的情况明确说明。

这些能力需要随着真实财报的验证持续完善。

## 当前进度

目前已将共同基底和六个模块的开发成果整理到同一个分支，保存了专业代码、提示词、独立页面组件、启动脚本及交接文档。

六个模块已登记到共同入口，并配置了独立工作台的启动方式。当前工作台提供上传文件、配置 Key、查看任务状态和完整结果的基础界面；各模块已有的专业页面仍需逐步接入。

已通过共同入口分别运行六个模块。最近一轮本地真实年报运行中，六模块均返回了结果：盈利和现金流保留待复核标记，资产、偿债和披露为部分完成；业务模块返回完整结果，但没有统一的专业完成度字段。运行结束不代表所有分析结论已经验收。

**当前版本处于联调完善阶段。** 六模块一键统一分析、专业结果的完整展示及跨模块协同，仍需继续开发和验收。最新检查与已知问题见 [2026-10-10 进度检查](docs/integration/进度检查_2026-10-10.md)。

## 文件夹结构

```text
项目根目录/
├── backend/                   共同基底和后端入口
│   ├── core/                  配置、模型调用、上下文及记录工具
│   └── workbenches/           后端工作台接入代码
│
├── modules/                   各模块的专业分析代码与提示词
│   ├── part1_business/
│   ├── part2_profit/
│   ├── part3_assets/
│   ├── part4_cashflow/
│   ├── part5_solvency/
│   └── part6_disclosure/
│
├── frontend/                  页面与结果展示
│   ├── common/
│   ├── src/
│   ├── part1_business/
│   ├── part2_profit/

│   ├── part4_cashflow/

│   └── part6_disclosure/

├── docs/                      架构说明、开发记录和交接文档
├── tests/                     测试与核对样例

├── data/                      数据索引与案例记录
├── README.md
├── requirements.txt
├── .env.example
└── .gitignore
```

`backend/`、`modules/` 和 `frontend/` 并列，分别负责共同技术支持、专业分析和页面展示。

例如，模块一的分析代码与提示词在 `modules/part1_business/`，页面代码在 `frontend/part1_business/`。两者共同组成模块一，并使用 `backend/` 提供的基底能力。

## 独立工作台入口

完成依赖安装后，可通过 `launchers/` 中对应的启动文件打开模块工作台：

| 模块 | 启动文件 | 默认本地地址 |
| --- | --- | --- |
| 模块一 | `start_part1_business.cmd` | `http://127.0.0.1:8101` |
| 模块二 | `start_part2_profit.cmd` | `http://127.0.0.1:8102` |
| 模块三 | `start_part3_assets.cmd` | `http://127.0.0.1:8103` |
| 模块四 | `start_part4_cashflow.cmd` | `http://127.0.0.1:8104` |
| 模块五 | `start_part5_solvency.cmd` | `http://127.0.0.1:8105` |
| 模块六 | `start_part6_disclosure.cmd` | `http://127.0.0.1:8106` |

API Key 在本地配置。实际 Key、上传的 PDF、运行数据库、日志及依赖缓存不随代码提交。

启动与依赖说明见 [工作台启动说明](launchers/README.md)。

## 后续建设

1. 逐个验收六个独立工作台，确保专业分析内容能够完整呈现。
