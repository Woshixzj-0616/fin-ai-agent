# 林研 · 金融财报分析模块化方案

这是从 V3.0.1 共同开发基底整理出来的本地模块化工作区，服务于后续六个财报分析模块的独立开发、独立运行和最终合并。

## 目录怎么理解

- `backend/`：共同技术底座。放配置、年报读取、DeepSeek 调用、运行记录、模块注册和以后真正的总入口。
- `modules/`：专业能力。每个 `partX_name` 是一个可以独立演进的分析模块，专业流程、提示词、计算和结果字段由模块自己决定。
- `frontend/`：页面。`common/` 放以后抽出来的公共外壳，各 `partX_name/` 保存对应模块的独立工作台页面。
- `docs/`：架构、来源版本、模块交接和验收材料。
- `launchers/`：启动文件。`start_part1_business.cmd` 至 `start_part6_disclosure.cmd` 是当前统一独立工作台入口；`source/` 是旧任务启动脚本来源。
- `tests/`：按模块保存的已有测试样例。

## 当前整理边界

本次只做本地归档和结构迁移，不上传 GitHub，也不修改原来的 V3.0.1 或六个并行任务目录。模块代码按当前工作树复制，因此保留了各任务中尚未提交的改进；来源、提交点和脏工作区状态见 [模块来源清单](docs/architecture/module_source_manifest.md)。

现在的代码已经有六模块注册表和六个独立端口的最小工作台。页面先采用统一的上传、Key 配置、状态和 JSON 结果外壳；各模块的专业结果仍由自己的 `payload` 决定，后续再逐个替换成专业呈现组件。

## 开发原则

1. 共同底座只提供工具和生命周期，不规定专业模块的分析顺序。
2. 模块可以增加自己的专题、指标、追问和呈现，只要能登记来源和证据。
3. 所有模型调用都从统一工具进入，结果保留原文出处、计算输入和模块版本。
4. 任何 `.env`、PDF、数据库、日志和前端依赖都不进入版本库。
