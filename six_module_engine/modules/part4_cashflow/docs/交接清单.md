## 给总控任务

在公共 `backend/module_registry.py` 的 `registrations()` 内增加：

```python
from backend.modules.cashflow.entry import MODULE_ID as cashflow_id
from backend.modules.cashflow.entry import MODULE_VERSION as cashflow_version
from backend.modules.cashflow.entry import run as cashflow_run
```

并在返回字典加入：

```python
cashflow_id: ModuleRegistration(cashflow_id, cashflow_version, cashflow_run),
```

不要把本模块的 `dev_run.py` 或模块工具循环复制到公共入口；公共 `ReportContext` 已经提供 PDF 页读取、全文检索、模型调用、运行记录和进度回调。

## 给前端任务

`result.sections` 固定有五项，按 `key` 区分：

1. `cash_overview`：现金全貌
2. `profit_to_cash`：利润到经营现金
3. `operating_cash`：经营现金收付
4. `investment_cash`：投资现金
5. `financing_cash`：筹资与现金余额

每项都有 `title`、`status`、`summary`、`detail`、`fact_ids`、`calculation_ids`、`source_pages`；可选 `tables` 应完整渲染，不能只取 `summary`。结果顶层的 `facts` 与 `calculations` 是这些编号的详情，`review_flags` 是来源或口径仍需复核的事项，`topics` 是公司专属专题。新版本还可能提供 `validated_amount_claim_count`，表示摘要、详情和总评中带币种/金额单位的阿拉伯数字经过了引用事实/计算的换算核对。

`calculate_cashflow` 新增 `yoy_bridge`：它给出净利润、各调节行对经营净现金同比变化的贡献，并返回 `details.reconciles` 和 `details.reconciliation_difference`。只有 `reconciles=true` 才能称为完整归因。每个板块必须填写自己的非空 `fact_ids`；金额检查拒绝提交后，模型可在后续修正轮调用计算器补算并重新提交。未被接受的结果不能当作完成结果展示。失败回退会保留候选板块并标记 `needs_review`；正文金额匹配出的编号只是复核线索，不代表验收通过。

`status=insufficient_evidence`、`needs_review` 或 `analysis_completeness=complete_with_review_flags` 时，页面应显示具体限制和来源，不把结果渲染为无条件结论。`source_pages` 是 PDF 物理页码，不是报告印刷页码。
