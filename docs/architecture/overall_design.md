# 总体架构

## 一条主线

用户上传一份年报后，由共同底座建立报告上下文；模块只从上下文取原文、事实、计算和模型工具，然后按自己的专业流程产出结果。未来总入口负责调度模块，不把六套专业流程拼成一套僵硬模板。

```text
年报 PDF
  ↓
backend/core（配置、读取、检索、DeepSeek、证据与运行记录）
  ↓
modules/part1 ... part6（各自的专业流程）
  ↓
统一外层结果 + 模块自己的专业结果
  ↓
frontend/common + frontend/partX（展示）
```

## 三层边界

### 共同底座

只解决重复的技术问题：文件和页码身份、原文读取、检索、模型调用、计算登记、证据登记、运行状态和结果保存。

### 专业模块

负责提出本模块要回答的问题、选择指标、组织推理、识别异常、设计追问并解释结论。模块可以拥有独特字段和专题，不要求和其他模块同形。

### 外层产品

负责选择模块、展示进度、呈现各模块结果和以后处理“只有财报 / 财报加研报草稿”两类输入。外层不替专业模块提前下结论。

## 当前状态

本地已经完成六模块注册和独立工作台的最小运行壳。模块一、二已有共同基底接入经验；三至六保留各自专业工作流。下一步是在这个不改变专业流程的壳上逐个接入专业页面和结果卡片。
