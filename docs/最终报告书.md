## 摘要

我们实现了一个**依据原始年报、可被查账的投研核查智能体**：

- 从 70 份真实年报抽取带页码定位的财务数字；
- 用本地确定性计算核对研报草稿中的每个数字；
- 输出**表格 + 点击溯源 + 审计日志**，而不是聊天记录；
- 自建错误注入评测，**精确率 / 召回率均为 100%**（168 项）。

核心口径：**可核验 · 可追溯 · 可复现**。大模型只拆句，**判定与计算全部本地 Python**。

## 1. 赛题理解

| 要求 | 我们的落点 |

| 现场实时处理 | `python agent/main.py live --pdf …` 一键登记→抽取→报告 |

## 2. 系统架构

```
原始年报 PDF
   │  来源登记（公告ID / 指纹 / 许可证）
   ▼
证据抽取（三通道合流）
   ├─ 表格线网格（bbox / 调整列 / 披露同比）
   ├─ words 级几何（聚行切列 / 折行标签 / 续表）★稳健主路径
   └─ 利润表补「营业总收入」
   ▼
财务指标长表（14 指标 · 页码定位）
   ▼
草稿陈述核查
   ├─ LLM：只拆句 → 结构化 JSON（不看数、不算、不裁）
   └─ Python：Decimal 单位换算 / 同比 / 按披露精度比对
   ▼
可核验审计台（Web）+ 运行留痕
```

### 2.1 模块地图

| 模块 | 职责 |
| --- | --- |
| `agent/materials.py` | 来料登记、指纹校验、运行留痕 |
| `agent/words.py` | words 级表格几何（**单一事实源**） |
| `agent/extract.py` | 三通道抽取 + 去重补全 + 合并口径旁证 |
| `agent/finance.py` | Decimal 计算与「按陈述精度」比对 |
| `agent/llm_check.py` | 模型拆句协议 + 本地判定 |
| `agent/main.py` | CLI：import / fetch / extract / analyze / demo / live / check-text / check-gold |
| `scripts/eval/` | 错误注入评测集与 P/R 评分 |
| `scripts/site_build.py` | 从 results/ 打包审计台 |

### 2.2 架构铁律

1. **模型不裁决**：只做自然语言 → JSON 的翻译；对错由本地规则给出。
2. **证据优先**：数值、单位、年份、口径都要能在原文定位，否则拒绝判定（宁可「证据不足」）。
3. **口径显式**：营业总收入 ≠ 营业收入；东财历史数是重述值；同比按披露精度核对。
4. **可复现**：同一输入重跑，结论一致；变更必留痕。

## 3. 数据与实验

### 3.1 数据底板

| 项 | 规模 |
| --- | --- |
| 年报 | **70 份**（14 家 × 2021–2025） |
| 行业 | 白酒 / 乳制品 / 家电 / 医药 / 汽车 / 能源 / 金融 / 地产 / 科技制造 |
| 指标 | **14 个**（营收、归母、扣非、经营现金流、EPS、ROE、总资产…） |
| 长表 | **710 行**，每条带页码与命中文本 |
| 核心 4 指标覆盖 | **70 / 70** |
| 与东财对账 | 650 项一致 573（88.2%）；差异回原文核后均为重述值或东财错格 |

### 3.2 抽取质量（决赛加固）

| 修复前 | 修复后 |
| --- | --- |
| 394 条证据中 **125 条**带 unit/scope 待复核字段 | **0 条** |
| 网格路径优先却缺单位 ⇒ 假报 `unit_unknown` | 去重时从 words 路径补单位并重算归一值 |
| 美的「2024 年度合并及公司利润表」认不出 | 报表标题归一（年份 / 续表 / 合并及公司） |
| 比亚迪利润表「千元」与摘要表「元」搜不到 | 旁证跨单位缩放检索 |

### 3.3 错误注入评测

**目的**：证明「能算分」——埋进去的错能不能查出来、会不会冤枉正确的。

| 错误类型 | 条数 | 精确率 | 召回率 |
| --- | --- | --- | --- |
| 数值篡改 | 32 | 100% | 100% |
| 单位错误（数量级） | 32 | 100% | 100% |
| 年份张冠李戴 | 24 | 100% | 100% |
| 同比符号反转 | 24 | 100% | 100% |
| 准确稿（应放行） | 56 | — | 放行 56/56 |
| **总体** | **168** | **100%** | **100%**（F1 = 1.0） |

口径：确定性核查器对结构化陈述的判错能力；gold 来自抽取证据值上的受控扰动。

### 3.4 测试

| 套件 | 结果 |
| --- | --- |
| 单元 + 集成 | **65 项全绿** |
| 真实年报集成 | 9 份 PDF：证据、同比按披露精度一致 |

## 4. 创新点

| # | 创新点 | 说明 |
| --- | --- | --- |
| 1 | **模型不裁决，计算归本地** | 避免「AI 瞎编」；每条结论可重算 |
| 2 | **证据指纹全链路** | 页码 + bbox + SHA-256，点行即溯源 |
| 3 | **双通道抽取合流** | 网格护 gold、words 保稳健；去重时字段互补 |
| 4 | **错误注入可计量** | P/R/F1 硬指标，不是「感觉还行」 |
| 5 | **交付物是审计台** | 对齐赛题「不得仅交自然语言对话」 |
| 6 | **现场一键 live** | 新 PDF 登记→抽取→报告，一条命令 |

## 5. 现场演示流程（约 5 分钟）

1. **环境**：`pip install -r requirements.txt`，跑 `python -B agent/test.py` 显示 65 绿。
2. **现场新数据**：`python agent/main.py live --pdf 样例.pdf --code … --name … --year …`
3. **看证据**：打开 `live_report.md` + `evidence.json`（页码、坐标）。
4. **审计台**：`python scripts/site_build.py`，点行 → PDF 高亮。
5. **评测**：`python scripts/eval/run_eval.py`，屏幕打出 P/R = 100%。

详见 `docs/运行说明.md`。

## 6. 合规与来源

- 年报 PDF 全部来自**巨潮资讯网**（上市公司公开公告）。
- 来源 URL、公告 ID、文件 SHA-256、页数、获取时间登记在 `data/manifest.csv` 与 `data/sources/`。
- 每次取数留痕 `logs/fetch_runs/`（含脚本自身指纹）。
- 第三方数据（东方财富）**仅交叉验证**，不作唯一真源。
- 开源库：`pymupdf`（见 `requirements.txt`）；其余 Python 标准库。
