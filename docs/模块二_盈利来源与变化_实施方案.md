# 模块二：盈利来源与变化——实施方案

状态：设计方案日期 2026-10-03；本方案现已在独立 V3.2.0 工作副本中开始实施。功能已接入上传、任务记录、结果展示和追问；确定性计算用例已补齐。真实年报模型联调与人工金标准验收仍待完成。V3.1.2 保留为基线。

## 1. 本模块回答什么

模块一回答公司经营什么、收入从哪里来、业务怎样变化。模块二回答：本期利润是多少、利润在哪些业务和项目形成、同比变化在会计上怎样分解、年报提供了哪些经营解释、特殊收益和损失有何影响、还有哪些原因不能证实。

核心交付物是可回查的利润结构表、利润增减解释表，以及与证据关联的发现卡。不能仅把收入、毛利率、净利率列出来，再写一段业绩好坏评价。

本轮使用单份 A 股年度报告中的本期和上期比较列，先支持可提取文字、按企业会计准则编制的普通非金融企业年报。银行、保险、证券等专属利润表先明确标记为尚未支持。非金融集团有财务公司等子公司时，不能遗漏合并利润表中实际列示的金融收入等项目。

输入只需要年报，无需研报草稿。研报主张核查与赛道展示继续作为外层能力。现金兑现、资产回收、偿债、估值及杜邦分析交由相应后续模块。

## 4. 事实字段及来源优先级

每个值保存：文件哈希、PDF 物理页码、表名、项目原名、标准指标键、原始文本、原始数值、符号、币种与单位、本期/上期期间、合并/母公司范围、是否重述、摘录及引用核验状态。

原始值与单位保留。另用 Decimal 换算到明确的统一单位参与计算，不用浮点数或模型心算。未披露、未找到、表内空白、明确为零、不可比较分开标记。表内空白不能简单当“没找到”，也不自动制造一个零值；按披露说明确认其含义，仍不明确时保留缺口。

完整利润主表优先用于利润层次勾稽；年报主要指标表用于核对归母和扣非；分部表及附注用于对应细分项目。不同表冲突时保留双方出处，先判断指标及范围是否不同；不能偷偷选取更方便计算的一个数。

上期优先取同份年报中可比较的调整后列。调整前/后数据、其他年度、其他范围禁止直接混算。多页表格要检查续表，不能读到营业利润就漏掉下一页所得税、净利润和少数股东损益。

## 5. 程序怎样计算与核对

### 5.1 当前利润及两期变化

先识别报告实际的父子行、小计及加减关系。营业总收入及其收入子项、营业总成本及其费用子项不能在同一层重复相加。

在报告适用且数据齐全时分别核对：

1. 已披露的收入、成本、费用及其他损益按主表加减关系，是否复现营业利润。
2. 营业利润 + 营业外收入 − 营业外支出，是否复现利润总额。
3. 利润总额 − 所得税费用，是否复现合并净利润。
4. 合并净利润 − 少数股东损益，是否复现归母净利润。
5. 归母净利润 − 扣非归母净利润，是否对应报告披露的归母口径非经常性损益净额。

损失按表内符号及该行加减角色处理。财务费用为负时，减去负费用会增加利润；“损失以负号填列”的损益项目已经带负号，不能再次统一取负。利息收入等费用明细与财务费用合计不可重复计入。

对每一层展示“报告值、已列项目复算值、差额、状态”。误差容许范围根据报告单位、显示精度及参与项目数量确定，并展示规则；不能用随意的百分比把差额忽略。数据齐全且差额在精度范围内只表示会计勾稽通过，不证明商业解释正确。

两期项目金额变化按加减角色形成会计贡献。营业利润、税前利润、合并净利润、归母利润各有自己的分解；跨层展示不得把中间小计与其组成项再次求和。未解释差额必须单列，不能把已找到的几项包装成完整分解。

### 5.2 毛利、比例及因素分解

- 营业业务毛利 = 同范围营业收入 − 对应营业成本。不能用营业总成本算毛利，也不能用含额外金融收入的营业总收入代替营业收入。
- 毛利率 = 毛利 / 对应营业收入。分母须为正且口径一致。期间费用率按各项费用 / 同范围营业收入计算，固定命名和分母。
- 合并净利润、归母净利润及扣非归母净利润分别命名，禁止交替叫“净利润”。净利率必须展示分子、分母；营业收入与营业总收入口径分别定义，不能悄悄替换。含金融子公司时说明该比率的构成限制。
- 毛利率和费用率变化用“百分点”。金额变化始终可展示；上期非正、零基数、由亏转盈或由盈转亏时不硬算普通增长率。
- 分业务收入与成本必须在同年度、同范围、同业务划分下匹配。不同拆分维度不相加。只有披露毛利率而没有成本时，原样展示披露值；不把由四舍五入毛利率推回的金额伪装成原始毛利。
- 不按收入占比摊集团费用给某产品，不能由分产品毛利直接声称该产品净利润或净亏损。
- 如两期可比较，毛利可分解为收入规模项与毛利率项。固定先规模后毛利率的顺序：`Δ毛利 = (R1 − R0) × m0 + R1 × (m1 − m0)`。这是可相加核对的数学分解；“收入规模项”不等于销量效应。只有同口径销量、价格及成本数据齐全时才进一步分析量价。
- 有效所得税负担只能在税前利润为正、范围一致时计算，并按实际所得税费用定义；不把其变化自动解释成法定税率调整。

### 5.3 非经常性损益

以本份报告披露的非经常性损益明细和分类说明为依据，核对税前项目、所得税影响、少数股东权益影响及归母口径合计。不能把所有投资收益、补助或减值自动归为一次性项目，也不能把全部特殊项目金额当成归母影响。

归母与扣非各自的变化可以事实对比；扣非不直接等同“真实利润”或“主营业务利润”。对持续性只能写证据支持的观察和待查条件，不能预测下年一定重复或消失。

## 6. 模型与程序的真实执行顺序

1. **准备材料与兼容性检查**：沿用 PDF 索引、页码、文档身份和本机 Key；定位合并利润表、分部表、主要指标、非经常性损益及对应附注。检索未命中不代表未披露。
2. **DeepSeek 提取利润事实**：独立阶段，提取字段、表格层级、期间和出处，允许按需搜索及读页，暂不写经营因果。
3. **程序校验及复算**：核查出处、符号、单位和口径；计算比率与贡献；形成勾稽差额、冲突及缺失清单。
4. **定向补查**：优先处理未勾稽、缺少续表或口径冲突，然后按已确认的金额影响选择最重要的解释问题。补查有次数和页数上限，失败保留阶段结果。
5. **DeepSeek 解释与交接**：传入本阶段规则、经检查的事实表、程序计算、相关年报解释及模块一业务信息。区分“金额变化”“公司说法”“有限推断”“尚未证实”；不能改写事实表或计算结果。
6. **保存与展示**：事实和计算先保存；解释阶段失败时仍能查看已得底表，并重试缺失阶段。全部完成后输出覆盖状态、发现卡和模块三/四/五/六的交接问题。

每次模型调用重组本阶段上下文，不能假设模型记得前一次。教材知识转成版本化问题、字段、校验及提示词，不把整本教材送给模型，也不建立给开发助手自己使用的分析 skill。

模型负责识别语义、查附注、解释并提出竞争解释；程序负责确定性计算、引用匹配、异常记录和结果保存。第一版不做模型微调。

## 7. 与模块一及现有程序怎样接

模块二可以直接接受年报，不强制先跑模块一。同一文件已有模块一结果时，可复用文档索引、带出处的业务分类和交接问题；金额仍需回到对应利润表核验。模块一的“有出处”状态不能替代模块二的数据适用性判断。

按文件哈希关联模块运行，记录各自模型、提示词及规则版本。复用数据必须同时核对期间、范围、指标定义和引用状态；不同模块结果冲突要记录，禁止静默覆盖。

后端增加独立的盈利工作流程及结果结构，通过已有任务分发入口接入；扩大模块选项及提示词版本记录。继续使用现有任务保存机制，优先在结果内增加字段，不为本模块另造一套上传或密钥系统。

前端增加“模块二：盈利来源与变化”任务选择和独立结果视图。单独运行与从模块一“继续分析盈利”两条路径都指向同一流程。历史模块一任务能继续打开，追问也按当前模块重新附规则。

## 8. 用户能看见的结果

1. **利润概览**：营业利润、归母、扣非及两期变化；范围与期间始终可见。
2. **利润形成表**：收入至归母的层次；原文、已匹配项目、勾稽差额可展开。
3. **利润增减解释表/图**：每项增加或减少多少；按重要性排列；残差明确显示。第一版先可靠表格，数据完备后用瀑布图辅助，不以图表掩盖缺口。
4. **业务毛利及费用表**：两期金额、比例、百分点变化、计算式、披露值与程序复算值的区别。
5. **归母与扣非对照**：两条变化线、特殊项目、税及少数股东影响；没有支持数据就明确缺口。
6. **发现卡和交接问题**：最重要且有证据的发现，数量按实际材料决定，不凑满固定数量。每卡有观察、贡献数据、公司解释、推断与替代解释、缺口和可回查出处。

不输出普适行业合格分数或投资评级。页面继续区分流程完成、出处匹配、会计勾稽及原因待复核四种含义。

## 10. 验收材料及标准

验收输入围绕真实用户上传的年报，不找“蹩脚研报”训练本模块。第一批使用伊利、宁德时代和隆基绿能已有年度报告；按实际披露挑选对应场景，并记录原版/修订版及文件哈希，不预设公司结论。

最低场景包括：收入和利润同向变化；收入下降但利润改善或反向；归母与扣非方向不同；减值/处置等项目影响显著；亏损及非正基数；财务费用或少数股东损益为负；营业总收入与营业收入不同；多页续表；重述或业务分类不可比；关键附注未定位。

真实报告制作人工参照表，至少逐字段核对主要利润指标、金额/单位、表格范围、符号、出处、各层勾稽及非经常性损益关系。人工参照不能直接复制 DeepSeek 输出。经营解释另评证据是否支持、是否混淆公司说法与推断，重要事项可请指导老师复核。

确定性规则另用小型构造数据覆盖重复求和、负号、零基数、单位转换和残差边界。这些是程序检查用例，不伪装成真实年报，也不代替整份报告的效果验收。

过关要求：

- 固定人工样例的主要金额、口径和计算应逐项一致；错项修复或明确显示待核，不能平均成一个“总体准确率”掩盖关键错数。
- 每个显示的计算能追到对应值及公式，关键结论能打开原 PDF；不匹配的引用不能标成支持结论。
- 归母、净利润、扣非不混用；明细及合计不重复求和；不可比情况不强行计算。
- 利润增减表能复现已确认的目标变化，不能解释的差额和原因始终可见。
- 多家公司真实模型请求可完成，并保存用量、耗时、输出、版本和人工差异。通过这些样例不外推为适用于所有行业。
- 模块一旧任务、独立启动和界面展示没有退化。

## 11. 用量与运行边界

本次模块一真实伊利任务的 API 返回用量是输入 102,129 tokens、输出 31,577 tokens。它说明不能在模块二每一步都重复传全文和大段已得结果；该单次记录不用于估计所有公司的费用。

新增流程仅传阶段所需字段与证据页，限制每阶段工具轮数、候选页、上下文及输出长度；保留足够的原文核对信息。超限、连接错误、输出截断都保存阶段结果并明确反馈，不无限等待或自动反复重跑整条链。用量显示以接口实际返回为准；重试累计到任务中，不只统计最后一次成功请求。

本方案只完成设计。下一版本的实际改动、运行端口、用量边界及最终验收结果应在执行记录中另行确认。
