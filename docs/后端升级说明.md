# 后端升级说明

本次仅升级后端可靠性。沿用 fin 的模块布局、依赖、工具参数、判定状态和计算规则；网页 HTML、JavaScript、CSS 保持不变。未导入 new 的历史产物、评测答案、指标词典或整套目录。

## 升级内容

1. **来源与版本留痕。** 本地上传用文件指纹生成 `LOCAL-` 身份，不伪造官方公告号；上传时间记为获取时间，未知披露时间留空。抽取证据携带来源信息，来源元数据变化使缓存失效。官方检索保存候选范围与选择凭证；重复公告字段变化显式失败。选择 `latest` 仅表示当前检索范围内的最新候选，不表示已查清更正、撤回与最新有效版本；`needs_version_review` 继续保留。
2. **证据限制贯穿入口。** `auto_usable=false`、非空 `review_reasons`、第二解析路径未确认一致，映射到 fin 的待复核问题。数值核查、同比环比、分析信号、估值、受限问答和 MCP 工具采用同一限制。旧证据缺少新增字段时按 fin 原规则处理；已知会计政策、合并范围或重述版本冲突时拒绝比较。资产负债表时点数及未定义为可加总流量的指标，不能用累计相减推导单季。
3. **请求与整篇任务控制。** 网络重试、协议修正和工具执行分别留痕。认证、参数、重定向及异常协议响应不作为临时网络错误反复重试。长文按章节及完整句子分块，全篇句子编号与位置唯一。一个分块失败保留其它结果；未完成部分不会标为已完成。单个超长句保留原文并标记未完成，不静默截断。

## 配置和默认值

配置文件为 `agent/backend_config.json`。新增通用模块为 `agent/backend_runtime.py`，回归测试为 `agent/test_backend.py`，均放在原有目录中。

| 配置 | 默认值 | 含义 |
|---|---|---|
| `http.timeout_seconds` | 60 | 每次连接/读取等待上限 |
| `http.request_deadline_seconds` | 240 | 一次逻辑请求含重试、退避的总时限 |
| `http.max_retries` | 3 | 网络重试次数，初次请求另计 |
| `http.max_output_tokens` | 8192 | 每次请求提交的输出 Token 上限 |
| `document.deadline_seconds` | 600 | 本次主动运行的整篇时限，恢复等待不计入 |
| `document.max_characters / max_sentences` | 240000 / 2000 | 整篇限制，超限明确拒绝，不截断 |
| `document.chunk_characters / chunk_sentences` | 12000 / 40 | 每块限制，保持完整句子 |
| `document.max_http_attempts` | 40 | 全篇物理 HTTP 尝试总数，含网络重试 |
| `document.token_budget` | 500000 | 全篇请求消耗预算，含恢复前消耗 |
| `tools.max_rounds / max_calls / max_repairs` | 5 / 30 / 2 | 每种分块协议的工具轮数、全篇业务工具调用次数、协议修正次数 |
| `sources.timeout_seconds / request_deadline_seconds` | 20 / 60 | 来源连接/读取与单请求含退避总时限 |
| `sources.task_deadline_seconds / max_http_attempts` | 600 / 120 | 一次来源获取任务总时限与物理尝试上限 |
| `sources.max_attempts / min_interval_milliseconds` | 3 / 1000 | 单请求最多尝试数与请求最小间隔 |
| `sources.max_redirects / max_bytes` | 5 / 104857600 | 允许域名内重定向次数与响应大小上限 |

配置严格拒绝未知字段、布尔预算和越界值。来源响应支持有界 gzip 解码；逐跳检查 HTTPS、允许域名及请求预算。模型响应最多 2 MiB，不跟随重定向。`Retry-After` 最多等待 30 秒且服从剩余时限。

使用 `FIN_AUDIT_CONFIG` 指定配置；CLI `check-text --config 配置.json` 优先。配置文件只放运行参数，密钥仅沿用进程环境 `LLM_API_KEY` 或 `--ask-key` 临时输入。不要把密钥放入 JSON、草稿或日志。

## 部分失败与恢复

```bash
python3 -B agent/main.py check-text --file 草稿.txt --evidence results/evidence.json
python3 -B agent/main.py check-text --file 草稿.txt --evidence results/evidence.json --resume
```

结果为 `text_checks.json`、`text_report.md`、`checked_draft.txt` 和平铺的 `text_checkpoint_<指纹>.json`。JSON 保存句子台账、分块状态、未完成句子编号、每次尝试、用量和实际返回模型名。CLI 部分完成返回 1；网页继续使用原有失败状态，并保留已完成核查项与报告。

恢复要求草稿、证据、所引用 PDF、业务代码、依赖和运行配置、服务地址、请求模型名、输出模式与执行方式保持一致；密钥不进入绑定，修正凭证后可以恢复。完成分块复用，失败分块重新执行，旧失败记录保留。请求、工具和 Token 跨恢复累计；整篇时限按每次主动执行计算，累计活动耗时另行报告。改变输入或配置，应开始新任务，不复用原检查点。

服务商返回真实用量时按返回值计费；未返回或失败的尝试保留“请求 UTF-8 字节数 + 输出上限”的保守预占，不按零消耗处理。该预占是预算策略，不能当作实际账单。检查点内容指纹用于发现损坏及不匹配，不是对用户自行改写内容的身份认证。

保存请求模型名、返回名、服务主机、调用时间和用量；返回名称变化产生事件。固定请求名称不能证明模型权重固定，记录中的 `immutable_weights_verified` 保持 false。源文件、检查点、用量与输出均不保存认证头。

## 验证与边界

```bash
python3 -B -m unittest discover -s agent -p 'test*.py'
```

本次验证沿用 fin 的真实九份年度回归、季度和半年度材料、公告及原有工具测试，并补充本地接口注入测试。模拟网络故障证明错误处理分支，不能证明实际供应商可用；长文用例验证全篇处理和恢复机制，不能证明模型拆解准确率。

“约”的默认相对容差仍为 **2%**，显式容差仍受 fin 的 **5% 上限**约束。未迁移 new 的宽指标抽取、附注事件、第二解析器、OCR 扩展与评测工程；本次仅消费已携带的质量标记。未取得新增独立事实来源，也未完成更正关系核验、人工复签或真实模型联通。本次测试和前端不变核验见 `results/backend_upgrade_report.md`。
