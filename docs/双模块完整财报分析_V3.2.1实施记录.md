# 双模块完整财报分析 · V3.2.1 实施记录

## 目标

上传一份年报后，结果不能只显示当前单独开发的模块二。完整分析要先展示模块一，再展示模块二，并把每一块做了什么、得出什么、哪些地方待复核，分别列清楚。

## 使用者能看到的内容

### 模块一 · 业务与经营背景

1. 公司如何经营及收入怎样形成。
2. 行业背景、公司战略与竞争特点。
3. 总收入与分部收入结构、收入变化及可比性。
4. 行业经营指标。
5. 经营变化与增长驱动因素。
6. 客户、供应商、产品或地区依赖及集中度。
7. 重大经营变化、年报披露的经营风险。
8. 交给后续模块的问题、覆盖检查、不确定项和年报出处。

### 模块二 · 盈利来源与变化

1. 程序复算的毛利率、费用率等指标。
2. 利润变化桥：目标利润变化、已识别会计贡献和未分类差额。
3. 营业利润、利润总额、净利润等层次勾稽。
4. 利润表事实及逐项出处。
5. 业务分部毛利资料、非经常性损益披露。
6. 有证据支持的变化观察、模块间交接问题、覆盖检查和待复核内容。

每项结果保留年报页码和原文摘录。当前没有整理出结果时，页面明确显示空项，不把“未检索到”写成“年报未披露”。

## 两个模块怎样衔接

系统完整分析时按顺序执行：

1. 模块一从同一份 PDF 提取业务环节、收入结构、经营变化和风险，并形成单独结果。
2. 系统将模块一中与利润分析相关的信息压缩成简要背景，保留可回查页码与摘录。
3. 模块二仍然从同一份年报提取利润事实、核对口径并执行程序计算，再根据年报证据解释变化。
4. 模块一只帮助模块二确定“该去核查什么”，不能代替利润数字验证，也不能单独证明经营因素造成了利润变化。
5. 两份模块结果分别保存、分别呈现；其中一块失败时，另一块已完成的内容仍会显示。

## 页面使用方式

- 新上传默认选择“完整财报分析：模块一 + 模块二”。
- 结果页先显示完整分析状态，再显示模块一、模块二的目录与各自状态，可点击跳转。
- 每个模块保留独立标题、分项、出处、覆盖检查和待复核项。
- 上传下拉框保留单独运行模块一、单独运行模块二的选项，方便定位具体模块问题。
- 旧任务保留原来的分析模式与结果，不自动改成完整分析。
