# 阶段二实施方案：持续工作的财报助手

## 目标

V2.0 把“上传一份年报后生成一次概览”升级为可回看、可补查、可追问的单文档工作流。DeepSeek 负责读材料和形成结论；本地程序负责 PDF 逐页索引、受控检索、精确计算、任务记录和证据展示。它不运行本地金融模型。

## 版本与数据边界

- V1.0 保存在 `D:\ChatGPT项目\金融AI智能体`，Git 本地标签为 `v1.0`，不自动推送远程。
- V2.0 在 `D:\ChatGPT项目\金融AI智能体_V2.0` 独立开发，网页默认使用 8001 端口；V1.0 使用 8000 端口。
- V2.0 复制公开样例年报、研报及本机 `.env`；`.env` 仍由 `.gitignore` 排除。
- V2.0 使用新建的 `data/app/runs.sqlite3` 和独立上传目录，不复制 V1.0 任务数据库。SQLite 旧记录含原目录绝对路径。
- V2.0 的网页依赖和构建产物放在 V2.0 目录；本机因依赖下载被网络策略阻止，当前启动器复用 V1.0 已安装的 Python 依赖，不复制其虚拟环境。V2.0 仍可在有包源访问的环境中自行创建 `.venv`。

## 用户流程

1. 上传 PDF 并校验格式、大小和页数。
2. 程序提取每页文本，保存到当前任务的本地逐页索引；首轮只把封面和关键候选页提交给 DeepSeek。
3. DeepSeek 可在有限工具轮数内请求搜索全文、读取指定页或计算同单位的两个数值。程序校验页码边界和参数，并记录调用工具、页码和分析步骤。
4. 结构化结果展示公司、期间、财务事实、单位、变化、短原文摘录和出处页码；数字展示可转换为“亿元”，原始数值保留。
5. 用户在结果页针对当前年报追问。每轮请求重新提供固定 V2 流程、当前任务摘要、已知事实、近期问答和新增原文；任务与对话写入本地数据库，刷新后可继续查看。

## 数据与接口

- `runs`：沿用 V1.0 的上传文件指纹、状态、页数、已读页码、结果等任务字段。
- `run_pages`：按任务和 PDF 页码保存可提取文字，供全文检索和后续页面读取。
- `analysis_steps`：保存“读取并索引、提取数据、按需补查、生成结果、回答追问”的步骤状态。
- `conversation_turns`：保存每轮问题、回答、状态、错误和工具调用记录。
- 新增 `/api/runs/{id}/conversation` 读写追问，`/api/runs/{id}/pages/{page}` 读取指定页文字；已有原 PDF 接口继续使用。
- `财报助手_v2.md` 作为版本化流程指令，每次 DeepSeek 请求都会重新带上。

## 工具边界与证据

- `search_pdf_pages` 只查当前任务中已上传 PDF 的文字页，最多返回少量候选页及片段。
- `read_pdf_page` 限定在本 PDF 页数范围内；成功提供给模型的页才可成为结果引用。
- `calculate_change` 接收纯数字和共同单位，使用 Decimal 算术。前期基数为零或负数时不计算普通同比。
- 每项事实保存页码和短摘录。页码必须属于本次已提供页面；摘录可与提取原文匹配并显示匹配状态。程序校验只能提高可回查性，不能证明模型的财务解释必然正确。
- API Key 和 PDF 都留在各自本机工作目录；仅选定页文字会随模型请求发送给 DeepSeek。

## 阶段二验收条件

1. 一份未用于页面硬编码的可读年报可上传，全文页数与页码保持一致。
2. 任务中可以按需检索首轮候选页以外的内容，并能点击来源页打开原始 PDF。
3. 两个可比数字的差额和同比由程序精确计算；单位或基期不适合时明确不算。
4. 追问继承当前文件、事实和最近问答；刷新页面后任务与问答仍在。
5. 密钥不出现在网页本地存储、日志或 Git；V1.0 的数据库、上传文件和源代码保持可用。
6. 对同一份样例报告记录 V1.0 与 V2.0 的输出差异、查阅页码、用量及需要人工复核项。
