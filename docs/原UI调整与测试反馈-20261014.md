# 原 UI 调整与测试反馈（2026-10-14）

项目：`fin-ai-agent`；本次功能修改仅在 `web/legacy/index.html`。

## 1. 结构化提取、财报分析

空白和错列的原因是表格与录入表单共用了 `.grid`，`display: grid` 把表头、表体排成了不同的网格列。

现在表单、表格使用独立样式；三张业务表恢复原生表格布局，设置列宽，表头与数据对齐。指标在左，数值右对齐，期间分行，证据 ID 移至末列。窄窗口在表格内部横向滚动，避免把中文挤成单字竖排。

## 2. 语义检索结果

使用本次年报原文重放两个查询，复现截图结果：

- “营业收入”：前八条均为 substring，分数 1，页码为 141、121、108、75、65、63、56、20。
- “经营活动产生的现金流量净额”：前三条分别在第 8、67、68 页，分数均为 81.7416，片段只有指标名。

检索可以返回结果，但排序与上下文质量存在缺口：

- `agent/retrieval.py` 按换行切段，PDF 表格的指标名与数值容易分离；BM25 倾向把完整匹配的短标题排在前面。
- `agent/audit/tools/search.py` 将逐页精确匹配不断插到列表头部，然后提前截断；大量精确匹配会挤掉 BM25 候选，形成倒序页码。最终又把 BM25 分数与固定的 substring 分数直接混排。
- 摘要窗口较短，没有完整保留年度、单位、表头和合并/母公司口径。“精确命中”只表示文字匹配，不表示金额已获验证。

建议后续按段落和表格行组织检索片段，保留相邻表头与口径；先汇总候选，再采用统一排序或按名次融合，最后去重截断。本次未修改检索后端。

## 3. 受限问答

增加“清除历史提问”；清空当前页面问答列表和提示后，可继续提问，不影响已提取证据。最新回答置顶，以蓝色边框和“本次回答”标识突出；旧回答自动取消高亮。

## 4. 纠错核查

编号、轨道、原句、结论、说明固定对应。原句完整显示，说明和核查范围分开；展开“修改片段”后，分别展示原片段、建议片段、修改后句子，避免长文本挤在一行。

## 5. C2、C6 年度误判：建议修复，本次仅诊断

依据运行 `20261014_144111_9357e3c4` 的保存记录及对应归档年报证据。两句模型提取的 `period_year` 都是 2024；错误发生在本地期间定位。

| 句子 | 原因 | 修改方向与预期 |
| --- | --- | --- |
| C2：贵州茅台2024年合并口径营业收入为1965.34亿元。 | `resolve_period` 用四位数字正则抓到 2024 和金额中的 1965，误认为多年度。 | 识别带日期/年度语义的位置，排除金额、小数、编号。该句应按 2024 年核查，判“确认错误”；对应营业收入约 1708.99 亿元。 |
| C6：贵州茅台2024年合并口径营业收入较2023年上升。 | 当前实现遇到多个年份直接返回 ambiguous，没有区分本期和比较基期。 | 从“2024年……较2023年”绑定本期/基期，保留公司、指标、期间及口径检查。按本次同一份年报证据，2024 年 1708.99 亿元高于 2023 年 1476.94 亿元，应为“证据支持”。 |

具体位置：`agent/audit/grounding.py` 的 `resolve_period`（第 239 行起）；`agent/audit/claim_check.py` 第 243–244 行把缺少定位的结果转换为通用“年度未明确”提示。

建议回归覆盖：金额 1965.34/2024.50、真正未写年份、正反顺序的年度比较、多句多年度、期间或口径不一致。不能简单选择最大年份，也不能直接信任模型年份跳过原文定位。
