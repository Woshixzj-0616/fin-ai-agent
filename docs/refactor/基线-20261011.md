## 四、现有 HTTP 接口

### 4.1 GET

| 路径 | 当前行为 |
| --- | --- |
| `/`、`/index.html` | 返回 `agent/webui.py` 内嵌的实时页面 |

### 4.2 POST

| 路径 | 当前行为 |
| --- | --- |
| `/api/prefill` | 解析 PDF，猜测代码、名称、年度和报告类型 |
| `/api/analyze` | 同步跑财务报告流水线，完成后一次性返回完整结果 |

| `/api/search` | 基于进程级 `LAST_DOCUMENT_TEXTS` 做页文本检索 |

当前没有 `/api/runs`、SSE 或取消接口。

## 五、现有运行与事件基线

### 5.1 Run

- `agent/materials.py` 的 `Run` 创建 `run_id`。
- 运行目录固定为仓库根 `results/`。
- 每次创建会把共享 `results/events.jsonl` 清空。
- 事件字段为 `time`、`run_id`、`event` 和附加数据。
- 没有事件序号 `seq`，没有订阅接口。
- `finish()` 会生成 `trace.json` 和摘要并更新 `history.zip`。

### 5.2 页面实时状态

- 前端使用 `setInterval` 每 2.5 秒切换预设阶段。
- 真实事件只在最终 HTTP 响应中通过 `payload["trace"]` 返回。
- 模型流式能力用于内部聚合，不向浏览器逐事件广播。
- 页面刷新不能按 `run_id` 恢复执行轨迹。

### 5.3 会话隔离

- `LAST_FACTS` 和 `LAST_DOCUMENT_TEXTS` 是 `agent/webui.py` 进程级变量。
- `/api/ask` 和 `/api/search` 没有 `run_id` 参数。
- 并发标签页或并发用户无法保证只访问自己的最近材料。

## 八、B0 反向检查

反向检查用于证明验收门能失败，不修改仓库文件。

### R1：测试门能识别失败

在内存中运行一个必然失败的单测，要求测试结果 `wasSuccessful()` 为假。若失败未被识别，则该命令退出失败。

### R2：指纹门能识别不一致

把一个真实文件指纹与全零期望值比较，要求得到 `HASH_MISMATCH`。若错误期望仍被判通过，则检查无效。

### R3：文档门能识别缺失

查询一个确定不存在的施工单路径，要求得到 `MISSING`。若不存在文件被报为存在，则完整性检查无效。

### R4：编译门能识别语法错误

对一个内存中的非法 Python 源码执行 `compile()`，要求出现 `SyntaxError`。若非法源码被接受，则编译门无效。
