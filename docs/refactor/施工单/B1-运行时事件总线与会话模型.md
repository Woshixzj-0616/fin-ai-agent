## 原目标

1. 一次运行有独立的运行上下文、目录、状态和单调递增的事件序号。
2. 事件可以实时订阅、按 `after_seq` 重放，并同步写入独立 JSONL。
3. 运行支持排队、执行、成功、部分失败、失败、取消和超时状态。
4. 运行明确归属会话，越权读取按“不可见”处理。
5. 既有 `materials.Run` 可通过最小适配器接入新事件镜像，默认行为不变。
6. 并发运行的事件、输出和状态互不串线。

## 用户可观察结果

本批不直接改变页面，但为 B2 和 B4 提供可观察能力：

- 后续前端可按 `run_id` 订阅真实事件。
- 多标签页并发分析时不会读取彼此的证据和事件。
- 页面刷新后可按序号恢复已经发生的事件。
- 取消和超时不再依赖前端定时器猜测。

## 接口与契约

### RunStatus

```text
queued
running
succeeded
partial_failed
failed
cancelled
expired
```

### RunEvent v1

```json
{
  "run_id": "...",
  "seq": 1,
  "timestamp": "...",
  "phase": "run",
  "event_type": "run_created",
  "actor": "runtime",
  "title": "创建运行",
  "summary": "...",
  "status": "queued",
  "duration_ms": null,
  "evidence_ids": [],
  "payload": {}
}
```

约束：

- `seq` 从 1 开始，同一 run 内严格递增且不重复。
- `timestamp` 使用 Asia/Shanghai 时区。
- 事件写入 `results/runs/{run_id}/events.jsonl`。
- 订阅者只接收目标 run 的事件。
- 重放条件为 `seq > after_seq`。

### RunContext

公开能力：

```text
id
session_id
root
folder
status
events
event(...)
output(name)
read(path)
start()
finish(status)
cancel(reason)
raise_if_cancelled()
snapshot()
```

### RunManager

公开能力：

```text
create_run(session_id, command, parameters)
start(run_id, target, *args, timeout=None, **kwargs)
wait(run_id, timeout=None)
get_run(run_id, session_id=None)
list_runs(session_id)
cancel(run_id, session_id=None, reason="user")
close()
```

会话隔离规则：

- 创建时必须绑定非空 `session_id`。
- 提供 `session_id` 查询时不匹配，抛 `RunNotVisible`。
- 不向调用方区分“不存在”和“无权限”。

## 反向检查

### R1：事件序号必须能检出冲突

对并发追加的事件集合做唯一性检查，并把一个人造重复序号喂给检查器，要求检查失败。

### R2：会话越权必须能失败

用 session A 查询 session B 的 run，要求抛 `RunNotVisible`。若成功返回，隔离门无效。

### R3：取消终态不能被覆盖

取消一个运行后再次调用 finish，要求状态仍为 `cancelled`。若被改成 `succeeded`，终态门无效。

### R4：旧钩子必须默认为关闭

不调用适配器时，旧 Run 只写原 `events.jsonl`，不出现运行时目录或额外事件。若默认产生镜像，适配边界失效。
