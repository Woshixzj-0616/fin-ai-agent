## 二、每批开工前必须完成

1. 复制下列模板，新建 `Bn-批次名.md`。
2. 填入本批唯一目标、用户可观察结果、范围和明确非目标。
3. 写清依赖、接口契约、事件契约和兼容线。
4. 指定验收命令、预期值、失败注入和回滚方式。
5. 至少列出一个“预期必须变红”的反向检查。
6. 把本表状态改为“已出”，对应施工单改为“施工单已冻结”。
7. 提交前先执行 `git diff --check`，确认施工单本身没有格式问题。

## 四、每批收工必须完成

1. 逐条填写“原目标兑现表”，状态只能是 `达标`、`未达标`、`口径已放宽`、`已取消`。
2. 记录实际执行的命令、退出码和关键摘要。
3. 给出独立信源状态。无外部来源时，写“独立信源：缺失”，并附只读命令输出。
4. 检查 Git diff，确认没有本批范围外的文件。
5. 确认回滚方式仍然可执行。
6. 更新本表对应批次状态。
7. 在项目记忆系统只写实质变化、真实坑和拍板，不写流水账。

## 六、状态词

| 状态 | 含义 |
| --- | --- |
| 未创建 | 尚未到该批开工时间 |
| 已出 | 施工单已存在，但尚未冻结范围 |
| 施工单已冻结 | 范围、契约、验收和回滚已确定，可以开工 |
| 实施中 | 正在修改代码或文档 |
| 待验证 | 实施结束，正在跑验收和反向检查 |
| 已收工 | 原目标已逐条结账，证据齐全 |
| 已阻塞 | 同一阻塞连续出现且无法在无外部输入下继续 |
| 已取消 | 有明确依据取消，不是暂时搁置 |
