## 一、批次目标与用户可观察结果

1. 用户在 `/app/` 提交真实 PDF 后立即看到本次运行，并持续收到服务端事件。
2. 阶段条只由真实运行状态和事件推进，不再使用前端定时器伪造进度。
3. 刷新页面后可按当前 `run_id` 恢复运行详情、SSE 轨迹和终态结果。
4. 轨迹展示阶段、标题、状态、耗时和经白名单整理的结构化摘要；不展示 token 级思维链、系统提示词、密钥或供应商原始响应。
5. 结果区展示证据、指标/裁决、报告、问题与终态；证据 chip 可打开对应页图并标出坐标。
6. 取消、失败、部分完成与断线重连均有明确状态；追问和检索只绑定当前 `run_id`。

## 四、接口、事件与数据结构契约

### 运行级页图

```text
GET /api/runs/{run_id}/images/{name}
```

- 必须携带当前 session Cookie。
- 仅允许 B2 页图命名白名单中的直接文件名。
- 跨 session、缺失文件、路径穿越和未知扩展统一返回 `404`。
- 成功返回 `image/png`，`Cache-Control: no-store`。

### 结果增强字段

`GET /api/runs/{run_id}?include_result=1` 中，页图相关记录补齐：

```json
{
  "page_image": "600519_2024_ab12cd34_p12.png",
  "page_image_url": "/api/runs/20261011_200000_ab12cd34/images/600519_2024_ab12cd34_p12.png",
  "page_width": 595.276,
  "page_height": 841.89,
  "image_scale": 1.6
}
```

坐标仍使用原 PDF point，前端用百分比定位，禁止猜测页面尺寸。

### 前端状态

状态容器至少包含：

```js
{
  runs: [],
  currentRunId: null,
  currentRun: null,
  events: [],
  result: null,
  connection: "idle",
  error: null,
  cancelPending: false,
  askHistory: [],
  searchResults: [],
  searchStatus: "idle"
}
```

### 事件展示边界

- 只展示服务端事件的基础字段、白名单 payload、结构化工具参数/结果摘要和 evidence IDs。
- 丢弃或摘要化：`messages`、`prompt`、`system_prompt`、`content_preview`、`raw_response`、`reasoning`、`thinking`、`chain_of_thought`、密钥和完整供应商响应正文。
- `model_parse` 只呈现主张数、未归属句子数和结构化计划字段，不呈现完整模型原文包。

### 浏览器端到端

- 真实上传一份本项目 `data/raw` 中的年报，确认表单提交、运行卡片、SSE 事件、终态结果可见。

## 六、回滚、保护线与风险

- 回滚：删除 B4 前端模块并恢复 B3 的 `main.js` 接线即可退出真实传输；旧页面和旧 API 不受影响。
- 保护线：B1/B2 事件、旧 API 响应和 `/` 兼容测试必须继续通过。
- 风险：真实 SSE 长连接与 `ThreadingHTTPServer` 的兼容性；用浏览器真实运行、断流和跨会话检查覆盖。
- 风险：页图坐标可能因 PDF 页面尺寸不同而偏移；服务端返回真实页面尺寸，前端按比例定位。
- 风险：旧流水线事件字段较多；服务端先做安全整理，前端再做字段白名单渲染。
