## 四、模块归属与接口契约

### 模块归属

| 模块 | 负责内容 | 关键导出 |
| --- | --- | --- |
| `extraction.catalog` | 指标目录与口径常量 | `METRICS`、`ALIASES`、`ADJUDICABLE`、`REQUIRED`、`PARENT_METRICS`、`CONSOLIDATED_METRICS`、`default_scope` |
| `extraction.grid` | find_tables 网格回退和财务报表旁证 | `box`、`cell_bbox`、`table_cells`、`header_for`、`amount_cell`、`label_for`、`metric_for`、`document_currency`、`_statement_title`、`statement_sections`、`corroborate_scope`、`parse_table` |
| `extraction.annual` | words 年度摘要表主路径与利润表补数 | `extract_via_words`、`extract_words_document`、`extract_total_revenue`、相关内部辅助 |
| `extraction.orchestrator` | 三通道合并、去重、扫描件提示、统一入口 | `_dedupe`、`_scanned_pdf_hint`、`_apply_scope`、`extract_material` |
| `extraction.__init__` | 包级显式导出 | 上述公开名和兼容私有名 |
| `extract.py` | 历史导入兼容门面 | 与原 `extract.py` 调用面一致的 name binding |

### 门面契约

- `extract.py` 必须使用 `from extraction... import ...` 或等价的显式 re-export；不得复制算法实现。
- 对调用方可见的对象应是同一个函数/常量对象，例如：
  - `extract.extract_material.__module__ == "extraction.orchestrator"`
  - `extract.METRICS is extraction.catalog.METRICS`
- `agent/test.py` 现有私有导入不可因迁移变成 `AttributeError`。
- 导入 `extract.py` 不得启动 PDF、网络、模型或运行目录副作用。
- `extraction/` 内部不得反向导入 `extract.py` 形成循环依赖。
- `words.py` 保持共享工具层，`extraction` 只单向依赖它。

### 数据与事件契约

- `evidence.json` 的字段、排序语义、`evidence_id`、页码、bbox、单位、scope、adjustment、issues 和 `extraction_method` 不得变化。
- `extraction_channel`、`extraction_dedupe`、`extraction_completed` 的事件名和计数不得变化。
- 缓存 key 继续包含 PDF `sha256` 和代码指纹；新增实现文件必须在指纹中。
- 结构化快照采用按 `evidence_id` 排序、固定键序的 canonical JSON，并记录 SHA-256；不能只用“条数相同”代替等价。
