### 工具规格契约

- 业务工具固定为七个，顺序不变：`list_catalog`、`find_evidence`、`compute_yoy`、`compare_claim`、`compare_companies`、`compute_trend`、`search_text`。

- `compare_claim` 和 `compare_companies` 仍是唯一可产生确定性对错 verdict 的工具。

### 工具事件契约

每次业务工具调用先发一次 `agent_tool_start`，再发一次 `agent_tool`。预算耗尽或工具返回错误也必须有成对事件；异常路径先发 `agent_tool` 错误完成事件，再按原行为抛出异常。

`agent_tool_start` 固定字段：

```json
{
  "round": 1,
  "call_id": "json_r1_1",
  "protocol": "json_multi_step",
  "tool": "find_evidence",
  "arguments": {},
  "budget_before": 30
}
```

`agent_tool` 固定字段：

```json
{
  "round": 1,
  "call_id": "json_r1_1",
  "protocol": "json_multi_step",
  "tool": "find_evidence",
  "status": "ok",
  "budget_left": 29,
  "duration_ms": 0.12,
  "arguments": {},
  "result": {},
  "evidence_ids": []
}
```

- JSON 协议缺省 call id 使用 `json_r{round}_{index}`；原生协议优先使用供应商 call id，缺省使用 `native_r{round}_{index}`。
- `status` 取值优先使用结果 `status`，其次 `verdict`，预算耗尽为 `budget_exhausted`，包装异常为 `error`。
- 两个循环产生的字段集合、事件顺序和每条调用的 evidence IDs 必须一致。
- `agent_tool` 原有字段 `round`、`tool`、`status`、`budget_left`、`arguments`、`result`、`evidence_ids` 保留，只新增 `call_id`、`protocol`、`duration_ms`。
- 现有 `llm_*`、`agent_loop_*`、`loop_*`、`tool_summary`、`model_parse`、`claim_gate`、`text_claim_checked` 名称和字段不变。

### 行为契约

- 优先原生 tools；原生失败且尚无工具调用时再试 JSON；仍失败则进入单次拆解并保留已有工具裁决。
- 无 `chat_tools` 时使用 JSON；无 `chat` 时使用单次拆解；`use_loop=False` 仍直接单次拆解。
- bundle 保持 `schema_version=2`，输出 `checked_draft.txt`、`text_checks.json`、`text_report.md`。
- `counts`、`tracks`、`tools_used`、`tool_results`、`parsed`、`sentences` 的字段结构不变。
- 工具裁决转成 `claim_check` 行时，仍保留 verdict、reason code、calculation、expected 和 evidence IDs；从 facts 补回报告引用时不得改变裁决。
- 报告继续包含“A. 确定结论”“B. 模型判断”“C. 需人工 / 证据不足”“工具调用链”四部分。
