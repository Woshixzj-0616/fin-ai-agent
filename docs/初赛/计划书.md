## 1. 项目摘要

我们做一个**能被查账的投研核查智能体**：给它一段研报草稿和对应上市公司年报，它把草稿里的每个数字拆出来，**逐条指回年报原文第几页**，用确定性计算判断对错，并输出「表格 + 点击溯源 + 审计日志」。

一句话：**不是让 AI 说得更好听，而是每个结论都能指回原文。**

| 项目 | 内容 |
| --- | --- |
| 赛题方向 | 方向 5（研报纠错核查，主攻）+ 方向 2（财报分析）+ 方向 1（数据结构化抽取） |
| 交付物 | 可核验审计台（表格 / 点击溯源 / 审计日志），**不做聊天框** |
| 核心口径 | 可核验 · 可追溯 · 可复现 |
| 技术路线 | 抽取 → 计算 → 挑错；**模型只拆句，判定与计算全部本地 Python** |
| 现有规模 | 70 份年报 · 14 指标 · 核心指标抽取 70/70 · 核查器 65 项测试全绿 · 错误注入评测 P/R = 100% |

## 2. 问题与动机

### 2.1 真实痛点

投研报告、公司点评、课程作业里，数字错误非常常见：

- **张冠李戴**：把 A 公司的营收写成 B 公司；
- **单位错误**：亿元写成万元，一差就是四个数量级；
- **口径混用**：「营业总收入」≠「营业收入」（某白酒龙头 2024 年两者相差 32.4 亿元）；
- **年份错位**：把上一年的数写成本年；
- **方向写反**：同比增长写成同比下降。

靠人眼校对，慢、漏、口径不统一；靠大模型「直接看」，又会**自信地编数字**，说不清依据。

### 2.2 赛题要什么

评分重心不在「AI 会不会分析股票」，而在：

| 要求 | 人话 |
| --- | --- |
| **可核验** | 评委问「这个数从哪来」，能点开指到年报第几页 |
| **可追溯** | 先读了哪份文件、走了哪条规则、算了哪几步，全程留痕 |
| **可复现** | 换台电脑按说明重跑，结果一致 |

**要的是草稿纸，不是答案。** 大多数队伍会把力气花在「让 AI 回答更聪明」，留痕和对账当收尾——那是我们的机会。

## 3. 解决方案

### 3.1 一条流水线

```
原始年报 PDF ──► 结构化抽取 ──► 财务指标长表 ──► 草稿陈述核查 ──► 审计台
   （巨潮）        三通道几何       14 指标          确定性比对        表格+溯源+日志
                   + 页码定位       + 同比/口径       + LLM 拆句
```

### 3.2 三个方向怎么合流

| 方向 | 做什么 | 落点 |
| --- | --- | --- |
| 方向 1 · 数据抽取 | 从年报 PDF 抠出带页码的财务数字 | `agent/extract.py` + `agent/words.py` |
| 方向 2 · 财报分析 | 算同比、核披露精度、找口径陷阱 | `agent/finance.py` |
| 方向 5 · 纠错核查 | 对草稿逐条判对错并给证据 | `agent/llm_check.py` + 审计台 |

### 3.3 架构铁律（创新点）

1. **模型只拆句，判定归本地**  
   大模型把自然语言草稿拆成结构化陈述（公司 / 年份 / 指标 / 数值 / 单位），**不看年报数字、不计算、不裁决**。  
   判对错、做换算、算同比全部是本地 Python（`Decimal`，可复现）。  
   ⇒ 每条结论都能解释、能重算，不会「模型说啥就是啥」。

2. **每个数字带证据指纹**  
   `evidence_id + 页码 + 坐标框 + 文件 SHA-256`。  
   审计台点一行 → PDF 页图上高亮数值格与标签框。

3. **可复现的数据底板**  
   年报全部来自巨潮资讯网公开公告；来源 URL / 公告 ID / 文件指纹 / 取数脚本留痕齐全。  
   抽取器双路径合流（表格线网格 + words 级几何），重跑结果字节级一致。

4. **可计量的对错**  
   自建**错误注入评测集**：在真实证据上注入错值 / 错单位 / 错年份 / 符号反转，量精确率与召回率。

## 4. 已完成工作

### 4.1 数据底板

| 项 | 规模 |
| --- | --- |
| 年报 PDF | **70 份**（14 家 × 2021–2025，覆盖白酒 / 乳制品 / 家电 / 医药 / 汽车 / 能源 / 金融 / 地产 / 科技制造） |
| 抽取指标 | **14 个**（营业收入、归母净利润、扣非归母净利润、经营现金流净额、EPS、ROE、总资产…） |
| 长表 | **710 行**，每条带页码与命中文本 |
| 核心 4 指标 | **70 / 70** 全覆盖 |
| 与东财对账 | 650 项一致 573（88.2%）；差异经回原文核对，均为「东财重述值」或「东财自身错格」 |

### 4.2 纠错核查器

- 材料登记 → 证据抽取 → `Decimal` 确定性核查 → LLM 拆句核查  
- **65 项测试全绿**（含 9 份真实年报集成测试）  
- 支持：金额核对、同比核对、单位换算、口径冲突拦截、约数/预测句拒判

### 4.3 可核验审计台（Web）

GitHub Pages 静态站，四栏：

1. **材料台账**（公司 / 年份 / 公告 ID / 指纹）  
2. **证据与点击溯源**（点行 → PDF 页图高亮）  
3. **陈述核查**（逐条判定与建议）  
4. **审计日志**（运行留痕）

### 4.4 错误注入评测（本阶段新增）

| 错误类型 | 条数 | 精确率 | 召回率 |
| --- | --- | --- | --- |
| 数值篡改 | 28 | 100% | 100% |
| 单位错误 | 28 | 100% | 100% |
| 年份错位 | 20 | 100% | 100% |
| 同比符号反转 | 20 | 100% | 100% |
| **总体** | **144**（含准确稿 48） | **100%** | **100%**（F1 = 1.0） |

> 口径：确定性核查器对结构化陈述的判错能力；gold 来自抽取证据，待团队人工复签。

## 5. 技术架构

```
fin-ai-agent/
├─ agent/                 核心智能体
│   ├─ materials.py       来料登记 / 指纹 / 运行留痕
│   ├─ words.py           words 级表格几何（单一事实源）
│   ├─ extract.py         三通道证据抽取
│   ├─ finance.py         Decimal 计算与比对
│   ├─ llm_check.py       模型拆句 + 本地判定
│   └─ test.py            65 项测试
├─ scripts/
│   ├─ data/              下载 / 抽取 / 对账
│   ├─ quality/           三源对账
│   └─ eval/              错误注入评测集与评分
├─ data/                  年报 / 台账 / 长表 / gold
├─ docs/                  文档 + GitHub Pages 审计台
└─ results/               运行产出（证据 / 报告 / 日志）
```

**依赖极少**：Python 3.11+ + `pymupdf`，其余标准库。换台机器 `pip install -r requirements.txt` 即可复现。

## 9. 数据来源与合规

- 年报 PDF **全部来自巨潮资讯网**（上市公司公开公告）；来源 URL、公告 ID、SHA-256 均已登记。
- 第三方数据（东方财富）**仅作交叉验证**，不作唯一真源；赛题要求「依据原始财务材料」。
- 开源库仅 `pymupdf`；其余为 Python 标准库。
- 每次取数留痕在 `logs/fetch_runs/`，含脚本自身指纹与候选公告清单。

## 10. 风险与应对

| 风险 | 应对 |
| --- | --- |
| 决赛现场是没见过的公司/版式 | 抽取器不按公司硬编码；三通道合流；现场先跑 `verify` + 抽取自检 |
| 评委质疑「AI 瞎编」 | 全链路证据指纹 + 点击溯源；模型明确「不计算不裁决」 |
| gold 仍待人工复签 | 初赛先报程序口径 P/R；复签后升格为正式参考答案 |
| 时间紧 | 初赛只交计划书+视频，编码窗口主要在 10/19 后 |
