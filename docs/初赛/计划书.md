# 金融投研智能体 · 项目计划书

2026 北京市大学生金融人工智能竞赛。参赛方向：数据结构化提取、上市公司财务报告分析、研究报告纠错核查。版本日期：2026-10-18。

## 项目摘要

金融投研工作的难点不只是找到一段文字，而是把材料中的数字、期间、单位和口径绑定到可复核的证据，再在该证据范围内完成计算、推理和报告。通用大模型能够理解自然语言，却容易在财务数字、页码引用和比较口径上产生看似合理但无法验证的结论。

本项目构建一个面向金融材料核查的智能体系统。系统从公告、年度报告、半年度报告和季度报告中提取带页码与文件指纹的字段，使用大语言模型拆解研究报告草稿并请求受限工具，再由本地 Python 与 Decimal 完成数值复算、期间门控和最终裁决。输出包括结构化 JSON、指标表、核查报告、原文页图、修改片段、执行轨迹和完整复现包。

系统的核心不是生成更多文字，而是让每条结论能够回答三个问题：依据来自哪里，数字怎样计算，过程能否复现。

## 业务场景与问题

金融研究员通常需要在短时间内完成材料整理、财务数据提取、比较口径确认、研报复核和报告撰写。人工流程存在四类高频风险：

1. 数字与期间错绑。金额中的四位数字可能被误认为年份，累计值可能被误作单季值，上年末余额可能被误作同比基期。
2. 单位与口径混淆。同一指标可能使用元、千元或百万元；营业收入与营业总收入可能不是同一口径；历史数据可能包含追溯重述。
3. 证据与结论脱节。报告中出现一个数值，但没有说明来自哪份文件、哪一页、哪个字段以及采用什么计算规则。
4. 模型越权判断。大模型可能直接给出投资结论，或把低质量抽取、缺失证据和未知口径当成确定事实。

本项目将这些风险转化为工程门控：无法唯一定位时不猜公司，缺少可比依据时不计算，证据不足时输出补证要求，程序失败时保留部分结果并标明未完成状态。

## 设计目标与原则

- 可核验：结论绑定文件 SHA、PDF 页序、印刷页码、字段原文和坐标。
- 可追溯：记录文件访问、抽取通道、工具调用、公式、操作数、门控和模型返回。
- 可复现：归档运行环境和源码指纹，提供结果、报告、分析过程及复现包下载。
- 可拒绝：证据不足、公司不唯一、期间冲突、单位不明或工具失败时明确停判。
- 分工清晰：模型负责语言拆解和受限工具请求，本地代码负责数值和规则裁决。
- 事实优先：事实、计算推论和模型解释分别标注，不把解释包装成审计结论。

## 系统架构

处理链路为：材料登记 → 文档解析 → 结构与字段抽取 → 证据归一 → 财务与期间计算 → LLM 拆句和受限工具请求 → 本地门控与裁决 → 报告与运行归档。

系统由六个层次组成：

1. 材料层：登记来源、披露时间、文件指纹、报告类型、公司和实际期间。
2. 解析层：读取文字层 PDF，按 words 级坐标恢复表格列、续表表头、单位与标签。
3. 证据层：保存 evidence_id、原文、页码、bbox、文件 SHA、期间、单位和口径。
4. 计算层：使用 Decimal 和显式规则计算同比、差值、占比、倍数和累计拆单季。
5. 智能体层：模型只输出结构化拆句和工具请求，不拥有最终裁决权。
6. 交付层：Web 工作台、CLI、结构化结果、报告、页图、轨迹和复现 ZIP。

## 核心机制

### 证据模型

每个关键字段保存材料身份、文件指纹、实际期间、原值、规范值、单位、币种、合并口径、调整状态、页序、印刷页码、bbox 和抽取通道。派生值额外保存全部输入 evidence_id 与计算公式。页序和印刷页码分开记录，避免把 PDF 第几页误写成报告印刷页。

### 文档与表格抽取

系统使用 words 级坐标恢复表格，而不是按文本行切分。已处理相邻列粘连、跨三行折行标签、续表页不重复年份表头、单位三种写法、百分号与元每股等固有单位。遇到未知版式时宁可标记缺失或待复核，不用其他公司的固定位置硬套。

### 财务计算与期间门控

累计流量可以先做同期间同比，再进行半年减一季度等合法拆差；EPS、ROE 和期末余额不采用累计拆差。比较前检查期间起止、长度、时点或流量属性、会计政策、合并范围和重述状态。缺少可比依据时保留操作数和尝试值，但不把结果标记为有效。

### 受限智能体循环

模型接收草稿和证据上下文，输出原子主张、公司、指标、期间、方向及工具请求。工具层只开放证据查询、指标比较、公式计算和文本检索等受控能力。模型返回的每个原子由本地代码再次核对公司、期间、单位和证据方向；冲突时转待复核，不允许模型修改程序裁决。

### 纠错与评分

核查结果分为证据支持、确认错误、需补证、需复核和执行失败。确认错误以“错误句”为正类统计 TP、FP、TN、FN，同时报告正确覆盖率、精确率、召回率和误报率。漏拆、缺证、超时和程序失败单独统计，不混入已判定正确率。

### 可复现与运行记录

每次运行保存模型名称、接口模式、参数、依赖版本、源码指纹、文件访问、工具输入输出、计算结果和终态。工作台支持运行切换、SSE 实时进度、断点恢复、长轨迹加载，以及 result.json、report.md、explanation.json 和 reproduction.zip 下载。复现包不包含访问本机会话的 Cookie 或密钥。

## 数据与评测计划

当前受控错误注入和固定答案回归证明的是确定性规则与工程链路，不等同于任意研报的独立准确率。下一阶段将建立分层评测集：

- 开发集：固定真实材料与历史错误注入，用于回归和定位。
- 留出集：未参与开发的真实研报、公告和报告版式，用于泛化测试。
- 固定答案复核：现有 24 条已完成 AI 辅助原文复核并由项目采用；未进行独立人工复签。
- 独立盲测集（后续）：由未直接参与规则设计的人员确认答案和证据，尚未完成。
- 稳定性测试：相同输入重复运行，检查结构一致、数值一致和证据定位一致。
- 基线对照：与通用模型直接阅读、人工复核和本地规则系统分别比较。

评测报告将分别给出判定准确率、错误召回率、误报率、正确覆盖率、引用支持率、失败率和平均耗时，并公开样本量、材料来源和适用范围。

## 安全、合规与第三方

系统默认在本地或受控环境运行。上传文件限制数量与大小，接口执行来源检查、限流、安全头和敏感信息脱敏。模型凭证只从环境变量读取，日志不保存密钥。

第三方依赖、模型、数据和代码集中登记名称、版本、来源、许可证和使用范围。公开披露 PDF 不默认视为可自由再分发材料；演示和复现包按实际许可控制材料分发。PyMuPDF 使用 AGPL-3.0 或商业许可，OCR 语言数据使用 Apache-2.0，最终交付将保留完整清单。

团队为北京林业大学信息学院 3 人小队，指导教师已确定，最终成员和报名信息以竞赛平台为准。

## 风险与处理

| 风险 | 处理方式 |
| --- | --- |
| 未见版式导致字段漏抽 | 明确标记缺失，转入复核；扩测新公司和报告类型，不按固定坐标猜测 |
| 模型输出不稳定 | 拆分原子主张，本地重核对，工具调用限额，失败保留并支持恢复 |
| OCR 或表格质量不足 | 保存识别依据和原文页图，相关字段统一标记待人工复核 |
| 会计政策或重述变化 | 比较前检查口径和版本，未知时阻断计算，不以旧值补齐 |
| 估值或投资判断越界 | 只检查明确输入下的内部一致性，展示假设、时点和适用范围 |
| 第三方材料许可不清 | 不默认公开再分发，集中登记并限制复现包中的材料范围 |
