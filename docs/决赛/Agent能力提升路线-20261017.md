# 决赛前 Agent 能力提升路线（2026-10-17）

> 状态：2026-10-17 P0 v2 首轮基线、P1 首批可解释停判、P2 首批抽取留出回归、P3 首批离线稳定性均已完成本地验收（各自独立分支，未推送、未合并）；P4 尚未实施。本文不改动初赛冻结标签 `submission-20261018-code`。
>
> 判断原则：现阶段最重要的不是继续加功能，而是先建立一把不偏袒自己的尺子，再按证据修系统。

## 一、现状结论

项目已经从“能演示”走到了“有真实模型链路、有确定性核查、有页码证据”的阶段，但还不能把现有固定样例成绩表述为业务准确率。

| 已有证据 | 能证明什么 | 不能证明什么 |
| --- | --- | --- |
| 168 条受控错误注入，确定性核查精确率/召回率 100% | 金额、年份、单位、同比方向等规则在注入样式中有效 | 不能证明真实研报的任意错误都能发现 |
| 2 篇研报风格样例、18 条陈述，13 条确定性判定全对 | 固定协议回放和完整链路可运行 | 报告明确说明不含真实模型请求，不是业务准确率 |
| 22/22 指标对齐、12/12 研报句 | 语义评测框架和字段口径可复算 | 金标为程序标注，未进行独立人工复签 |
| DeepSeek 连续三轮 completed、应判 8/8 | 真实接口、工具循环、检查点与失败留痕可用 | 固定 12 条重复运行不是独立留出集准确率 |
| 14 家公司、70 份年报抽取，9 个核心指标 70/70 | 现有开发集上的年报摘要表抽取已稳定 | 未见公司、半年报、季报、扫描件和复杂版式尚未证明 |

一句话判断：**工程链路已成形，可靠性证据仍集中在开发集。下一阶段主题是“泛化与可证明”，不是“功能数量”。**

## 二、优先级总览

| 优先级 | 能力 | 要解决的问题 | 为什么先做 |
| --- | --- | --- | --- |
| P0 | 真正的留出集评测 | 现在的分数可能受开发集和固定样例影响 | 没有可信尺子，后续改进无法判断真假 |
| P1 | 公司、期间、单位、归母/合并口径解析 | `unresolved_company` 仍可能出现，错误绑定比拒答更危险 | 这是当前最接近真实业务错误的风险 |
| P2 | 未见材料与字段抽取泛化 | 14 家年报之外的版式、期间和扫描件未测 | 决定现场换一份材料还能不能工作 |
| P3 | 真实模型稳定性与失败可解释性 | 超时、限流、长文档、工具错误和重复运行仍需系统量化 | 决定现场网络和设备不理想时能否收场 |
| P4 | 决赛现场可运行性 | 需要最终报告、Web/CLI、源码说明、现场样例和答辩 | 能力必须能在评委机器上复现 |

执行顺序：**P0 → P1 → P2**。P3 与 P4 可以从 P0 完成后并行，但不得反过来用增加功能掩盖评测缺口。

## 三、P0：先建立可信的留出集评测

### 3.1 目标

建立一套在开发时没有参与规则设计、没有进入提示词、没有进入开发集的公司、报告版式、公告和研报草稿。金标必须在运行 Agent 前冻结，运行后不得根据结果回改答案。

没有独立审核人员时，这套数据只能称为“留出集回归”，不能称为“独立盲测准确率”。

### 3.2 第一批建议规模

- 至少 2 家未出现在现有 14 家开发集中的公司。
- 至少 4 份未参与开发的材料，覆盖年报摘要表和至少一种其他材料。
- 至少 30 条原子陈述，包含正确句、确认错误句、口径冲突句、缺证句和不应强行判定的句子。
- 每句同时冻结：结论、原因类别、允许的证据材料、必须命中的页码/字段，以及是否允许弃答。

后续再扩到 3 家以上公司、6 至 10 份材料、60 条以上陈述，并增加半年报、季报和公告。

### 3.3 必须落实的隔离规则

1. 留出集材料与开发集按文件 SHA-256、公司代码、文档 ID 三重去重。
2. 金标文件先计算 SHA-256 并登记，再运行 Agent。
3. 草稿、提示词和客户端不得读取金标；金标只进入评分函数。
4. 运行前固定代码提交、模型名、服务地址、提示词版本、规则版本和数据集版本。
5. 首轮运行后若修复缺陷，必须升版本并全量重跑，不能只重跑失败项。
6. 任何样本泄漏或运行后改金标，整轮结果作废并记录原因。

### 3.4 必须分别报告的指标

| 指标 | 定义 | 不混入什么 |
| --- | --- | --- |
| 判定准确率 | 所有金标原子陈述中，最终结论正确的比例 | 不把未运行算正确 |
| 错误召回率 | 金标确认错误中被找出的比例 | 不把“需复核”算发现错误 |
| 误报率 | 金标正确句中被误判为确认错误的的比例 | 与漏报分开 |
| 正确覆盖率 | 金标句中得到明确判定或合理弃答的比例 | 必须另报正确判定数 |
| 引用支持率 | 结论带有效 evidence_id、页码和可回查位置的比例 | 仅有文字引用不算通过 |
| 合理弃答率 | 缺证、口径冲突或材料未加载时明确停判的比例 | 与模型失败分开 |
| 失败率 | 超时、协议错误、工具异常、程序异常的比例 | 不伪装成弃答 |
| 平均耗时与 P95 | 每次运行及单条陈述的耗时 | 分开记录模型和本地计算时间 |
| 重复运行一致性 | 同版本、同数据的多次结果完全一致比例 | 不把固定 12 条说成新样本泛化 |

### 3.5 新会话第一批任务

- 在独立 worktree 或新分支上从冻结标签开工，不碰当前未提交的初赛材料。
- 新增评测协议文档，固定样本准入、金标冻结、泄漏检查、版本记录和报告模板。
- 新增留出集 manifest 与金标文件，记录来源、SHA-256、公司、期间、文档类型和拆分原因。
- 扩展现有评测器，统一输出上述指标；保留原始逐条结果，报告默认只展示摘要和失败明细。
- 增加“金标不可见”和“开发集/留出集无交集”的自动测试。
- 先跑离线回放与真实模型各一次，确认评测器能分清正确、错误、弃答、超时和工具失败。
- 生成首份报告后只做缺陷归因，不立即调参刷分。

### 3.6 P0 完成标准

- 数据隔离有自动检查，泄漏为 0。
- 金标在运行前冻结并可由文件哈希复验。
- 三类结果明确分开：真实错误、合理拒判、执行失败。
- 同配置连续运行三次，能输出一致性与差异明细。
- 报告明确写明适用范围；没有独立审核时不得出现“盲测准确率”字样。
- 首轮可以不设人为准确率门槛，但必须形成稳定基线；后续目标由基线、业务风险和团队拍板共同确定。

## 四、P1：把公司、期间和口径解析做成“可解释地停判”

### 4.1 现状

`agent/audit/claim_check.py` 仍会在无法唯一定位公司时返回 `unresolved_company`。已有“草稿前文唯一公司可解析”“任意材料公司可解析”“无对应材料仍停判”等测试，但还缺少完整的候选解释和冲突分层。

### 4.2 需要区分的场景

- 草稿前文能唯一定位公司，应解析。
- 本次没有加载对应公司材料，应拒判并提示先加载什么。
- 一句出现多家公司，应列出候选，不得由模型字段强选。
- 两个候选公司无法唯一确定，应拒判。
- 期间冲突，例如年度句引用了半年度数据，应拒判。
- 单位冲突，例如“元”与“千元”不一致，应拒判。
- 归母与合并口径冲突，应拒判并说明冲突字段。
- 模型输出公司与原文公司冲突，应优先原文并留痕。

### 4.3 目标结构

建议把结果从单一错误码扩展为可解释对象，至少包含：

- 解析状态：唯一解析、候选、材料未加载、多公司歧义、期间冲突、单位冲突、口径冲突。
- 候选公司：代码、名称、匹配依据。
- 冲突原因：原文证据、模型字段、上下文来源。
- 下一步动作：加载材料、补全公司名、选择期间或转人工复核。

字符串错误码可以继续保留兼容，但前端和报告必须能展示上述信息。

### 4.4 P1 验收

- 新增 20 条以上的公司/期间/单位/口径对抗样例。
- 所有“无法唯一定位”场景都安全停判，不允许静默绑到第一家或上一次公司。
- 所有停判都有候选或明确缺失原因。
- 现有草稿上下文解析与真实材料解析继续通过。
- 把“静默错绑”作为独立指标，目标为 0；拒判率上升本身不视为失败，错误确认才是失败。
- 首批验收：25 条对抗样例、静默错绑 0、非唯一解析缺动作 0；证据见 `docs/决赛/P1解析停判验收-20261017.md`。

## 五、P2：未见材料和字段抽取泛化

### 5.1 现有底板

已覆盖 14 家公司、2021-2025 共 70 份年报。9 个核心指标 70/70；扣非基本每股收益、扣非加权平均净资产收益率、每股净资产仍有缺项；营业总收入 0/70。缺项有的来自摘要表本身没有该行，因此不能简单归因于程序失败。

### 5.2 需要扩测的材料

1. 未见公司的年报摘要表。
2. 半年报和季报，重点看“本期/上期”“年初至报告期末”等期间口径。
3. 跨页续表、复杂表头、多单位混排。
4. 扫描件与 OCR，且必须保留原页和人工复核状态。
5. 金融企业报表，避免把普通工商企业规则硬套到银行、保险和券商。

### 5.3 抽取通过口径

不能只看“抽到了一个数”，要联合验证：

- 数值正确。
- 单位换算正确。
- 公司与期间正确。
- 指标别名和归母/合并口径正确。
- 页码、标签原文和 bbox 可回查。
- 不确定项带 issue 或转复核，不得静默写出错误值。

### 5.4 P2 验收

- 建立独立抽取留出集，不用现有 14 家公司调参。
- 每个命中同时核对值、期间、单位、页码和标签。
- “有值但无位置”“位置对但值错”“值对但口径错”分别统计。
- 第一阶段目标是把所有不确定项显式标出；静默错误值在小型留出集中应为 0。
- OCR 先作为可解释转复核通道，不急着承诺任意扫描件自动准确。

### 5.5 首批验收结果

- 首批已完成本地验收：2 家未见公司、4 份材料、20 个目标事实；数值、期间、单位、页码、标签和 bbox 均为 20/20，静默错误 0、材料失败 0。
- 首轮季报/半年报因期间表头安全失败后，仅补显式日期区间、时点表头和折行表头等通用能力；没有按公司或材料写特判。
- 这四份材料在首次基线前已冻结，但之后用于检查并修通用表头，因此只能称留出回归集，**不得称盲测**；当前无独立人工复核。
- 扫描件仍未实现自动 OCR，继续显式转人工复核；详细证据见 `docs/决赛/P2抽取留出集验收-20261017.md`。

## 六、P3：真实模型稳定性与失败可解释性

现有真实 DeepSeek 运行已证明固定样例能完成，但还需系统覆盖：

- 请求超时。
- 429 限流。
- 返回 JSON 截断或格式错误。
- 模型名变化和工具协议失败。
- 长文档分块与跨块引用。
- 断点恢复、重复运行和中途取消。
- 工具报错、单句失败和部分成功。
- 用量、耗时、成本与认证失败。

验收重点不是“全部成功”，而是每种失败都能被归类、保留已完成结果、给出用户可理解状态，并且不把失败伪装成弃答或正确。日志不得包含密钥、认证头或敏感原文片段。

### 6.1 首批离线验收结果

- 首批已完成本地验收：统一失败码、分块失败状态、检查点和部分结果保留路径；8 个离线故障场景 `8/8 PASS`。
- 覆盖超时、429 重试、401 不重试、坏 JSON、截断 SSE、模型身份变化、部分成功和密钥安全；无真实模型调用、无真实密钥。
- 全量 `498 tests` 通过、`2` 跳过；工具异常归类为 `tool_failed`，超时不计入弃答。
- 真实网络、真实服务商限流和真实模型稳定性尚未验证；当前无独立人工复核，详细边界见 `docs/决赛/P3稳定性验收-20261017.md`。

## 七、P4：决赛现场可运行性

官方决赛需要最终报告、可运行 Web/CLI、完整源代码和说明、现场可处理的样例数据，以及展示答辩。

决赛前必须完成：

- 一条命令启动 Web 与 CLI，并在干净环境复现。
- 一键导入自带样例，不依赖现场网络。
- 外部模型作为可替换通道，保留离线回放或确定性降级路径。
- 演示数据同时包含正确句、错误句、缺证句和口径冲突句。
- 页面能展示结论、证据页码、原页定位、运行状态和失败原因。
- 准备现场网络失败、模型超时和材料格式异常三个故障演示。
- 提供源代码目录说明、依赖清单、许可证状态、复现步骤和答辩口径。

现场目标：评委换一份材料时，系统即使不能全自动判对，也必须明确说出“查到了什么、缺什么、为什么停判”。

## 八、明确不做什么

- 不在 P0 完成前继续堆会计政策变化、估值模型、附注和汇率等新功能。
- 不为了让留出集分数好看而在运行后修改金标。
- 不把固定样例三轮重复称为独立盲测。
- 不把程序标注金标称为人工复签。
- 不为了“显得智能”取消安全拒判。
- 不把模型思维链展示给用户；只展示可核验结论、证据和失败原因。
- 不在未审查情况下合并分叉的 FinScope v4.1.1 提交。
- 不在仓库、日志、截图或演示材料中写入真实 API Key。

## 九、新会话启动方式

> 按 `docs/决赛/Agent能力提升路线-20261017.md` 开始 P0。先建独立分支，完成留出集协议、泄漏检查、指标统一和首轮基线；本轮不调 Agent 业务规则，不推送、不合并。

第一批只做评测与归因，不同时改公司解析、抽取器和前端。集合稳定后，再按 P1、P2 分批进入。
