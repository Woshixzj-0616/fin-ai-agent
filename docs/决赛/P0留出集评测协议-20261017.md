# P0 留出集评测协议（2026-10-17）

> 适用范围：本仓库的 Agent 端到端回归与后续能力提升批次。
> 本协议只定义评测和留档口径，不修改 Agent 的公司解析、抽取器或核查规则。

## 一、结论边界

1. 没有独立人工复核时，结果只能称为“留出集回归”。
2. 不得使用“盲测准确率”“独立准确率”等表述。
3. 重复运行只证明同一配置下的稳定性，不证明对新材料、新公司的泛化能力。
4. 首轮基线不设人为刷分门槛；先得到可复算的稳定结果，再按错误类型讨论改进。

## 二、样本准入

留出集至少满足：

- 2 家未参与开发的上市公司。
- 4 份未参与开发的公开材料。
- 至少 1 份年报摘要，以及至少 1 种其他材料。
- 至少 30 条原子陈述，覆盖正确、确认错误、口径冲突、缺证和不应强行判定。
- 每条陈述记录结论、原因类别、允许的材料、允许的页码/字段和是否允许弃答。

材料必须登记公司代码、文档 ID、公告 ID、来源 URL、文件 SHA-256、页数、材料类型、期间和拆分原因。

当前批次使用中国移动 `600941` 与紫金矿业 `601899`，共 4 份材料、30 条陈述。

## 三、开发集隔离

运行前必须通过三重去重：

1. 公司代码不得出现在开发集快照中。
2. 文件 SHA-256 不得与开发集材料相同。
3. 公告 ID 不得与开发集材料相同。

开发集基准文件：

- `data/scope.csv`
- `data/manifest.csv`

自动检查入口为 `agent/holdout_eval.py::verify_dataset`。检查结果中的 `leakage.ok` 必须为 `true`，`issues` 必须为空。任何一项泄漏都使整轮结果作废。

## 四、金标冻结

留出集目录固定包含：

```text
data/holdout/
├── manifest.json
├── facts.json
├── gold.json
├── dataset.sha256
└── materials/
```

冻结规则：

1. `manifest.json`、`gold.json`、`facts.json` 三份文件共同决定数据集版本。
2. `dataset.sha256` 使用 `sha256sum` 兼容格式登记三份文件：

```text
<manifest.json hash>  manifest.json
<gold.json hash>      gold.json
<facts.json hash>     facts.json
```

3. `dataset_version` 是三个文件哈希按固定顺序再次计算 SHA-256 的结果，写入 `raw.json` 和报告。
4. 运行前和目标运行结束后都检查 `dataset_version`；发生变化则本轮结果作废。
5. 金标只能进入评分函数。Agent 运行输入只包含草稿、`claim` 解析项和冻结的 `facts`。
6. 运行后不得根据结果修改金标。确需修复数据构造缺陷时，必须升版本并全量重跑。

`facts.json` 是运行事实，不是评分答案。每条事实必须包含 `evidence_id`、`document_id`、有效页码、`source_file` 和与 manifest 一致的 `source_sha256`。

## 五、运行隔离

每次运行固定记录：

- 代码提交和分支。
- 模型名与服务地址。
- 提示词版本哈希。
- 规则版本哈希。
- 评测器版本哈希。
- 数据集 ID 和 `dataset_version`。
- 运行方式（离线回放或真实模型）。
- 实际运行轮数。

Runner 必须在调用 Agent 前执行结构检查：运行输入序列化后不得出现 `expect`、`allowed_document_ids`、`allowed_evidence`、`reason_category`、`abstention_allowed` 或 `GOLD_ONLY` 标记。

## 六、结果分类

每条陈述只能落入以下类别之一：

| 类别 | 含义 |
| --- | --- |
| 明确判定 | 系统给出“证据支持”或“确认错误” |
| 合理弃答 | 系统按金标允许的原因给出“证据不足”或“口径冲突／需人工复核” |
| 漏拆 | 没有产出对应原子陈述 |
| 超时 | 执行预算、时限或请求超时 |
| 失败 | 协议错误、工具异常或程序异常 |
| 非判定轨迹 | 模型轨迹或非最终判定，不折成正确 |

未运行、漏拆、超时和失败都进入准确率与失败率分母，绝不按正确计算。

## 七、统一指标

| 指标 | 分子 | 分母 |
| --- | --- | --- |
| 判定准确率 | 金标结论正确的陈述 | 全部金标陈述 |
| 错误召回率 | 金标确认错误中被确认错误 | 金标确认错误陈述 |
| 误报率 | 金标正确句中被确认错误 | 金标正确陈述 |
| 正确覆盖率 | 正确明确判定或合理弃答 | 全部金标陈述 |
| 引用支持率 | 带 evidence_id、文档、页码和可回查位置 | 明确判定 |
| 合理弃答率 | 应弃答且正确弃答 | 应弃答陈述 |
| 失败率 | 超时或失败 | 全部金标陈述 |
| 漏拆率 | 未产出原子 | 全部金标陈述 |
| 平均耗时 | 模型时间、本地时间、总时间分别统计 | 有效耗时记录 |
| 总耗时 P95 | 单条陈述总耗时 | 有效耗时记录 |
| 重复运行一致性 | 同配置多轮中状态、原因和引用完全一致 | 有至少两轮的金标陈述 |

“正确判定数”必须和“正确覆盖率”同时报告，避免把弃答算成明确判定。

## 八、重复运行

1. 正式基线默认同配置连续运行 3 轮。
2. 报告必须显示实际运行轮数，不能把单轮冒烟写成“三次一致性”。
3. 少于两轮时不计算重复运行一致性，只记录“本次不足两轮”。
4. 一致性签名包含结果类别、状态、原因码和排序后的 evidence_id。
5. 差异明细必须写入 `differences.json`，并保留每条陈述的逐轮签名。

## 九、命令与产物

离线回放：

```powershell
python -B scripts\eval\run_holdout_baseline.py --mode replay --runs 3 --output-dir results\holdout\<run-id>
```

真实模型：

```powershell
python -B scripts\eval\run_holdout_baseline.py --mode live --runs 3 --from-travel-env --output-dir results\holdout\<run-id>
```

每次正式运行必须输出：

- `summary.md`：只展示统一指标、实际轮数、一致性和结果边界。
- `raw.json`：完整版本记录、逐轮指标和逐条结果。
- `differences.json`：多轮差异明细。
- 真实模型模式的 `live-run-*` 目录：运行事件和检查点。

密钥只从环境或本机凭据文件读取，不写入报告、日志或仓库。

## 十、作废与升版本

出现以下任一情况时，整轮结果作废：

- 开发集与留出集存在公司、文件或公告 ID 泄漏。
- 金标在运行前未冻结或运行后发生变化。
- 运行输入包含评分侧字段。
- 已确认金标构造错误。
- 运行器与数据集版本记录不完整。

作废目录必须放 `INVALID.md`，写明原因、v1 留档位置和正式替代版本。v1 数据原文保存于 `data/holdout/versions/v1/`，不得覆盖。

## 十一、报告模板

报告至少包含：

1. 数据集 ID、`dataset_version`、运行方式和实际轮数。
2. 是否有独立人工复核；没有时固定写明“不能表述为独立盲测成绩”。
3. 全部统一指标。
4. 分轮指标表。
5. 重复运行一致率和差异条数。
6. 失败、漏拆、错误归因和待拍板事项。
7. 证据入口：summary、raw、differences 和真实模型运行目录。

## 十二、P0 验收

- 数据隔离自动检查通过，泄漏为 0。
- 三项数据集文件哈希和组合版本可复验。
- 评分侧字段不进入 Agent 运行输入。
- 正确、确认错误、合理弃答、漏拆、超时和失败分开统计。
- 同配置正式基线完成 3 轮，并输出一致性和差异明细。
- 报告不含“盲测准确率”表述。
- 首轮只做基线归因，不调 Agent 业务规则。
