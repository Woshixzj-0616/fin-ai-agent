# 模块五独立工作台交接

## 运行方式

- 本机地址：`http://127.0.0.1:8105`
- 一键启动：仓库根目录 `打开模块五工作台.cmd`
- 启动脚本：`启动模块五工作台.ps1`
- 前端由本目录 FastAPI 服务托管；同源 `/api` 请求只进入本任务服务。开发模式代理目标默认也是 `127.0.0.1:8105`，不再指向 V3.0.1 的 8007。
- 启动器先检查 8105；端口被其他程序占用时明确退出。如果本工作台已经运行，则直接打开现有页面。
- 上传文件、SQLite 历史、运行记录、日志和本机 `.env` 都落在本任务目录。启动脚本将 `FINLAB_CONFIG_PATH` 指向任务目录 `.env`。密钥值不打印。

## 模块五接入

- `backend/module_registry.py` 注册本分支的 `solvency` 入口和 v2.1.1 版本。
- 上传固定提交 `analysis_module=solvency`。
- 后端只在 `solvency` 分析时对 PDF 提取债务相关表格布局，并由 `backend.modules.solvency.retrieval.select_initial_pages` 选择首批页；专业 agent 接收含 `PDF_TABLE_LAYOUT` 的选中页，保留自身工具和分析流程。
- 页面分别呈现任务运行状态与 `analysis_status`；计算、覆盖状态、事实语义、证据文字匹配和人工复核状态各自显示。
- 追问每轮附带模块五专业指导、当前事实账本、六类专题、覆盖状态、计算和限制，使用年报搜索/读页工具；引用未读页时标记为未核实。
- 点击事实证据的页码可读取已提取原文；也可打开本次上传的 PDF。

## 合并时需要审查的公共改动

- `backend/app.py`：模块五注册调用、固定模块入口兼容、表格布局提取、专业选页路由、追问分发、健康信息和模块白名单。
- `backend/module_registry.py`：新增模块五 registration。
- `frontend/src/App.jsx`：本工作台入口替换为独立模块五页面；合并时应按模块路由接入，不能覆盖其他模块页面。
- `frontend/vite.config.js`：开发 API 代理不再指向 8007，改用环境变量或 8105。
- 新增的 `SolvencyWorkbench.jsx` 和 `solvency-workbench.css` 可以作为独立模块页面组件接入。

## 验收边界

- `analysis_status=complete/partial/insufficient_data` 表示分析结果自评状态；HTTP 任务 `completed` 只表示运行函数结束，不代表分析完整。
- 证据文字或数字匹配不等于表格行列、单位、会计含义及事实真实性已经人工核验。
- 本地页面可用性和任务流程接通不代表真实模型结果质量验收通过。最新稳定模块结果的版本、状态、事实和计算需与分析记录交叉核对；因 DeepSeek 网络连接错误而无结果的运行必须标为失败/资料不足，不能当作通过。
