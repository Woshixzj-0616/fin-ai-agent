## 3. 本模块必须回答什么

用户应能读懂：公司负债由什么构成；哪些义务需要付钱、何时付；现有资金有多少可用；经营和融资提供了什么支持；主要压力及不能确认的部分在哪里。

下列是专业分析维度，不是固定六次模型调用或六个同样的发现卡。DeepSeek 根据公司资料决定专题、顺序和深度。

| 分析维度 | 查找材料与具体工作 | 给用户的结果 |
| --- | --- | --- |
| 负债和融资结构 | 合并资产负债表、借款/债券/租赁/应付票据/其他应付款附注；拆融资性与经营性负债 | 两期结构对照、借款债券核心口径及含租赁扩展口径、主要融资方式 |
| 到期和再融资 | 一年内到期项目、债券条款、流动性风险到期表、回售/违约披露 | 原披露时间段内的付款结构、近一年负担、可提前偿付条件和未知期限 |
| 资金可用性 | 货币资金构成、受限资产、现金及现金等价物调节、存款/理财条款 | 从账面资金到已识别限制的解释；能确认的资金口径与不确定部分 |
| 盈利和现金支持 | 合并利润、利息费用/资本化利息、现金流、偿还债务和取得借款 | 适用的利息保障、历史现金保障、借还款规模及口径限制 |
| 其他付款与融资条件 | 资本承诺、担保、授信、抵押质押、重要融资约束、期后事项 | 已确认支付义务、条件性义务和潜在来源分别展示 |
| 公司重点专题 | 由证据选取，如现金和借款并存、短债增加、供应商资金占用、受限资金多、外币/浮息负担 | 带证据的解释、替代解释及后续核实问题 |

合同负债的履约义务、递延所得税等不能直接算作一年内需付现的债务。担保余额、计划性投资和未使用授信也不能机械加进到期债务/现有现金。资产变现质量交模块三深入，利润变化交二，现金形成原因交四，审计/事项性质交六；模块五自己仍核对支撑当前结论的年报事实。

## 4. 专业数据与证据

模块内维护自己的事实、债务项目、资金项目、期限记录和计算记录，不等待公共层先建设完整指标数据库。

数值事实至少含：事实 ID、报告哈希、原科目/指标、期间或时点、合并/母公司范围、币种、原值原单位、十进制规范值、计量口径、证据组和待核状态。没有披露或未找到的数值不是零。

债务项目增加：债务类别、报表列示位置、母项/子项关系、是否融资性、计息身份、是否含当期部分、金额性质（本金/账面价值/含息合同付款）、到期区间、利率/币种/抵押条件及出处。

资金项目增加：存款/现金/金融资产类别、是否在货币资金或现金等价物中、限制金额与范围、可动用时间、赎回条件和持有主体。不能默认集团资金可供母公司直接偿债。

证据可由多个片段共同支持表头、单位、科目、金额和条款，并保存物理页码。程序文字匹配、金额出现、表格身份核对和人工核对分别记录；不得把任一匹配标志包装成结论正确。

到期数据优先保留原时间段。只有“一年以内”时不拆造月份；跨本模块展示区间的金额不按比例摊分。未确定到期部分单列，不放到最远期限。报告披露的期限表缺行或部分项目遗漏时，不把已识别合计说成全部负担。

## 5. 计算规则和不能省略的限制

计算由程序使用 Decimal 执行，模型决定使用什么分析和如何解释。每项计算保存输入事实 ID、公式版本、组成项目、结果、适用性和不能计算原因。共同的 `record_calculation` 只是记录工具，不是现成的财务计算引擎。

### 5.1 债务分类与去重

1. 核心融资债务采用已确认融资性借款/债券等账面金额；租赁融资另列，并给含租赁的扩展合计。融资性票据或其他应付款须有身份依据。
2. 主表长期借款/应付债券通常与一年内到期部分分列；附注可能包含全部剩余余额。必须确认来源是总额还是非流动部分，再取互斥项目合计。
3. “一年内到期的非流动负债”合计需读组成，不能默认全是借款，也不能把合计与其明细都相加。
4. 商业应付款、票据、税费、合同负债分别解释。会计总负债和融资债务是两个指标。
5. 账面利息、待付本金和合同本息现金流不同。可比合计各自建立，勾稽差异说明包含利息、折现/摊销等已证实原因；不靠自动残差项目补平。

### 5.2 资金口径

同时保留货币资金、现金及现金等价物、已经识别的受限项目。只有限制金额属于相同总额且不重复时，才计算“货币资金减已识别受限部分”；限制披露不完整时明确这个差额不是全部可用资金的认证。

现金等价物、理财、交易性金融资产、定期存款分别判断，不按科目名全部计作随时可用现金。用已经排除某项限制的现金等价物余额时，不再次扣除相同限制。

净债务 = 指定融资债务口径 - 指定资金口径。资金不同分别命名，负值保留为该口径下的净现金。权益为零或负时不计算通常意义的净负债率，不给误导性的负百分比。

### 5.3 指标目录

| 指标 | 程序公式及要求 | 解释限制 |
| --- | --- | --- |
| 资产负债率 | 同时点合并总负债 / 合并总资产 | 是资本结构指标，不能单独判定债务危机 |
| 流动比率 | 同时点流动资产 / 流动负债 | 不假设流动资产均可立即变现 |
| 速动比率（简化版） | (流动资产 - 存货) / 流动负债，注明组成 | 预付等非快速变现项目仍可能包含；有完整组成时另算严格口径，禁止混名比较 |
| 已识别资金对短期融资债务比 | 明确资金口径 / 已识别近一年融资债务 | 部分披露则标为部分口径；不等于所有付款义务的覆盖 |
| 短期融资债务占比 | 同口径近一年融资债务 / 融资债务合计 | 只有分类完整且互斥时给完整比例 |
| 历史经营现金保障 | 全年经营现金流 / 两端平均流动负债；另可算期末版本 | 分母口径写明；负经营现金流保留；缺更早期初数时不硬算上年平均版本 |
| 利息保障倍数（费用化利息口径） | (利润总额 + 对应费用化利息支出) / 对应费用化利息支出 | 财务费用不等于利息；本金偿付和现金支付能力另看；利息为零/未知不输出无穷大 |
| 净债务与净负债率 | 指定债务减指定资金；再除同范围总权益 | 缺项、资金限制和主体差异显式说明 |

资本化利息、实际支付利息、利润表利息费用分别保留；有完整资料时才提供另行定义的含资本化利息分析，不强制互替。财务费用包含利息收入、汇兑、手续费等，负财务费用并不意味着没有借款或利息负担。

程序对金额的时间、范围、币种和口径进行适用性检查。外币只能用报告给出的人民币折算值纳入人民币合计，不能自行编造汇率。百分比变化和百分点变化分开，负基期的变化优先展示金额并说明同比解释限制。

### 5.4 资金与付款对照

期末资金与未来一年到期负担可作静态对照，名称为“期末资金对照”，不能写成现金流预测或违约判定。历史经营现金已形成的部分不能再加到期末资金中重复计算；未来经营现金、续贷、资产出售、未用授信不自动视为已确定来源。

若设置情景分析，单独保存用户/模型提出且明确标记的假设。只在期限、义务、增量未来现金和承诺重叠处理足够清楚时算条件性余额；不在第一版强行生成一个完整资金缺口数字。未使用授信说明有效期、条件和主体，不能用授信总额减借款总额直接推算可提用额度。

未折现期限表本来已含利息或租赁支付时，不再另加相同付款。担保只在明确触发/已确认承担支付义务时纳入相应情形，其他担保作为条件性义务展示。计划性资本开支与已签合同承诺分别处理。

## 6. DeepSeek 实际工作方式

入口 `run(context)` 调用本模块流程，返回 `{"result": ..., "trace": ..., "read_pages": ...}`，符合现有网页和 CLI 取得工作流结果的方式。模型自身不记得上一请求；调用方维护本轮消息、工具反馈和已取得事实，并在请求中带上适用的专业指导与上下文。

模块有清楚的目标和工具，但不固定按相同次数/顺序做分析。建议形成以下可回查的循环：

1. 定位合并主表和关键附注，形成负债、资金和期限的初步全貌。
2. DeepSeek 自主选择重点并请求检索、读页、连续页和补查；模块专用选页覆盖货币资金、借款、债券、租赁、流动性风险和承诺。不能使用旧概览候选页作为完整证据集。
3. 模型提交事实与组成关系；程序检查引用、单位、口径、重复/冲突。需要修正时把具体原因反馈给模型，不把冲突静默丢掉。
4. 模型选择适用计算；程序执行并登记。欠缺事实触发补查，查不到则保留具体限制。
5. 模型解释结构、期限、资金和支持来源的关系，区分公司披露解释和分析推断，根据新证据修订专题。
6. 提交与复核最终结果，保留有效新增专题及表格。限制最终输出格式，只限定软件可接入的外层和证据关系，不限制发现数量和叙事顺序。

工具至少支持：页检索、完整页/相邻页读取、提交/修订事实与债务组成、列出当前事实、专业计算、保存专题与进度。通过 `context.call_model` 发出请求，通过 `context.record_tool`/`record_calculation` 保存实际输入输出。访问页应独立维护，确保 `read_pages` 对应本次真正读取的年报页。

循环有可配置的页数、轮次、输入量和请求预算；逐步保存中间事实和结果。达到预算时交付已有有效内容及未解决事项，不伪装成完整审查。网络/鉴权/限流/模型格式错误与专业缺项区分；中断的中间材料仍可在 artifacts 复核。阶段续跑暂不要求公共层自动支持。

## 8. 结果与用户能看到的内容

专业结果拟含：`company`、`period`、`analysis_as_of`、`headline`、`debt_structure`、`maturity_profile`、`funding_sources`、`cash_availability`、`support_metrics`、`obligations`、`findings`、`additional_sections`、`evidence`、`calculations`、`limitations`、`handoff_questions`。字段随真实样例细化，额外有效专业内容不因白名单丢弃。执行完成与资料完整分别表达。

界面默认先给读者一句有依据的主要判断和最重要变化，再按内容提供：

- 借款/债券/租赁及经营负债结构和两期对照；合计可展开组成及未识别项。
- 原披露时间段的付款时间线，注明账面余额或合同本息、未明确期限部分。
- 资金构成/限制说明与相同主体资金和义务的对照；不足以确认全部可用资金时显示限制。
- 利息和历史现金保障的指标解释、公式、输入行、未计算原因。
- 本公司重点专题和条件性义务，不强迫每份报告生成同样专题。
- 来源跳转、待核问题和跨模块交接问题。

3. **计算与深度。** 实现组成去重、资金限制、期限身份和适用计算，把具体核验错误交回模型补查；完成自主专题及结果复核，保存限制。
4. **真实样例核对。** 使用产品内 DeepSeek 完整运行一家公司，再以另一家迁移检查；根据取数/计算/推理/展示原因分别改进。不是训练模型权重，也不把开发助手写的结论当正式运行成果。
