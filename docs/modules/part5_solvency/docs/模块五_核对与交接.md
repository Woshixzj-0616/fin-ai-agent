## 结果入口

`entry.run(context)` 返回现有工作流字典，结果位于 `result`。固定字段包括：

- `module_id`、`module_version`、`report_id`
- `analysis_status`、`headline`、`findings`
- `facts`、`data_coverage`、`calculations`、`limitations`、`evidence_review`
- `debt_structure`、`maturity_profile`、`funding_sources`、`cash_availability`、`support_metrics`、`obligations`
- `handoff_questions` 和模型可增补的 `additional_sections`

前端应逐项显示事实、计算、模型解释和待复核边界。`facts[].validation.status` 的含义是：

- `quote_and_number_matched`：摘录和数值出现在所引页文字中；不代表表格行列、单位、范围、期间或会计含义已核对。
- `quote_matched`：文字摘录匹配；通常用于非数值事实。
- `unmatched`：至少一项来源匹配失败，引用它的结论必须进入待复核。

新增字段 `facts[].source_context` 记录模型对表格行名、列标题、单位和语义的核对声明；`facts[].validation.calculation_eligible` 决定事实是否可进入计算。列归属不清时保留事实并标成 `ambiguous`，计算工具会拒绝使用。核心事实的 `data_coverage` 可显示 `captured_semantics_confirmed`、`captured_needs_review`、`not_yet_captured`、`not_found_after_search`、`not_disclosed`、`ambiguous`、`not_applicable`。后四类模型判断需附说明和本次完整读过的页码；程序不验证全文检索是否穷尽。`not_yet_captured` 只表示尚未登记，不能显示成“年报未披露”。

初筛页只作为查找线索。`result.read_pages` 现在仅记录完整读取过的页；事实摘录必须来自这些页面。压缩后的模型工作账本会保留已读页片段、事实证据、语义状态和核心清单，避免依赖已经从模型上下文中移除的旧对话。

同一 `fact_key` 可用于修订现有事实，程序保留 `fact_id` 并增加 `revision`，不另造重复项。

`evidence_review.status` 为 `automatic_source_text_match_only` 时，页面应显示“来源文字已匹配，财务语义待人工复核”。不要把它渲染为“已核验”。

## 计算接口

模型提交事实后，由程序执行 `calculate_solvency_metric`。目前支持：

`debt_total`、`operating_liability_total`、`cash_after_restrictions`、`net_debt`、`net_gearing`、`short_debt_share`、`asset_liability_ratio`、`current_ratio`、`quick_ratio`、`operating_cashflow_to_current_liabilities`、`interest_coverage`。

所有计算用 `Decimal`，保存输入事实 ID、公式、结果、适用性和失败原因。`calculations` 同时保留成功结果及 `not_applicable` / `not_calculated` 尝试；前端应把计算失败的具体口径缺口保留下来，不用一条总摘要覆盖。

```powershell
  --config 'D:\ChatGPT项目\金融AI智能体_V3.0.1\.env'
```

运行记录写入本任务的 `data/开发运行/<run_id>/`，该目录已忽略，不随代码提交。最近一次伊利 2024 年报运行 ID 为 `f42aeae4cfb84f4e93f874286b1d73b3`，状态为 `partial`：14 条事实、9 项计算尝试（7 项成功，2 项未计算）、6 条发现。工具最终提交已正常完成，引用被整理为 `evidence_fact_ids` 和 `calculation_ids`；文本/数字匹配不等于人工财务语义核验。

既有样例曾计算资产负债率、流动比率和一组以部分登记债务事实为输入的债务指标；其中融资债务合计缺少 2024 年末应付债券事实，相关净债务和占比不能视为已核实的完整口径。新版本把这类金额明确标作所列项目小计，并会阻止未确认语义的事实进入计算。受限资金、经营现金流保障和利息保障仍需在新运行中核验。

本轮稳定性改动已完成本地验收：初筛能覆盖三张合并报表；比较表中只提取到一个金额的应付债券行会标为列归属歧义并被计算工具拦截；有双列金额且语境锚点齐全的短期借款仍可计算；压缩上下文保留已读页片段和事实摘录。`compileall` 与 `git diff --check` 通过。

余额恢复后使用同一份伊利 2024 年报实跑。第一次成功请求（`49e05218afc1442c9aa797ed1f26e38a`）确认接口可用，但结果暴露两处实现缺陷：模型把应付债券期末余额误读为零；被预算拒绝的查页请求仍消耗总工具额度，导致后续计算被挤出。该轮状态为 `partial`，不能作为通过验收的结果。

据此增加三项护栏：表格只有一个金额且来源同时有期末/期初列标题时，将列归属标为歧义；没有明确数值的表格事实不能进入计算或被当作零；总工具额度只统计实际执行的调用，被拒绝的查页不再挤占计算额度。同时补齐所有者权益核心覆盖匹配。

修正后第二次运行 ID 为 `e08f46b621894f9f9c167930469f320c`，状态仍为 `partial`：读取 15 页，保存 56 条事实、11 项计算尝试（10 项成功、1 项因受限现金口径不清而未计算）和 13 条发现；资产负债率、流动比率、简化速动比率、经营现金流对平均流动负债保障倍数、费用化利息保障倍数均已计算。权益覆盖已正常识别。应付债券 35.41 亿元和部分一年内到期负债被保守标为 `captured_needs_review`，未进入债务合计或比率；因此结果没有再把债券说成零。余额恢复后接口没有返回 402 或网络错误。

该轮仍触及工具额度上限，检索额度也已耗尽；模型报告用量为 443,182 prompt tokens、99,649 completion tokens。它证明主要分析流程能运行，也表明完整年报反复查页的调用成本和歧义项收口仍需继续优化。运行记录保存在本任务 `data/开发运行/<run_id>/`，该目录已忽略，不随代码提交。

DeepSeek 请求中断时，入口会尽量保留已登记事实、计算尝试和错误阶段，返回 `partial` / `insufficient_data`，不把部分材料标成完整分析；预算耗尽后仍会尝试用更小的最终提交请求保存结论。
