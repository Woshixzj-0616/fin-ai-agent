# 模块六展示与合并交接

## 模块身份

- 模块 ID：`disclosure`
- 模块版本：`模块六_披露可信度与特殊事项_v3.6.2`
- 入口：`backend/modules/disclosure/entry.py::run(context)`
- 结果主对象：`workflow["result"]`

## 前端展示建议

模块六是一份可单独阅读的“审计与披露影响说明”。建议从审计意见摘要开始，再按模型发现的实际专题展开，最后展示对其他模块的具体影响和本次覆盖/未覆盖范围。

| 结果字段 | 展示位置 |
| --- | --- |
| `executive_summary`、`audit_profile` | 模块顶部摘要与审计报告原文入口 |
| `findings[]` | 独立专题卡/章节；按 `importance` 与结果顺序显示，不套固定发现数 |
| `findings[].disclosed_facts`、`analysis`、`known_effects`、`uncertainty` | 专题正文的原文披露、分析、影响和局限 |
| `findings[].evidence[]` | 物理页码、摘录、支持内容及程序引用检查状态 |
| `impacts[]` | 跨模块复核表：目标模块、科目/期间/范围、需核查的内容和建议动作 |
| `coverage[]` | 检查范围状态；不得把 `searched_no_hit` 显示为“没有此事项” |
| `limitations[]`、`reading_guide` | 本页末尾的限制及模块间阅读方法 |
| `calculations[]` | 金额差额公式、两端披露基础、单位/范围、来源页以及基数状态 |

应明确显示：引用文字匹配、金额在摘录中出现、金额在报表行列身份正确、会计处理正确和模型因果解释，是不同层次。当前公共记录/引用核验只自动检查物理页和摘录；不能将其美化成所有层次都已验证。

补充字段供前端保留质量边界：

- `report_context.identity_evidence`：报告身份的原文页与摘录；身份来源不等同于文件名推断。
- `findings[].evidence[].verification` / `evidence_status`：例如摘录匹配、部分匹配、未匹配或使用省略号。未匹配证据应醒目标为待人工核对，不可作为已证实事实。
- `impacts[].evidence_status`：影响证据状态；仅链接到某专题的线索不表示该专题已逐项证明所有影响字段。
- `run_quality.critical_gaps`：结果完整性门槛未满足的缺项；`quote_verification_counts`：引用核对计数；`request_chars_by_turn`：每轮上下文大小诊断，不是财务结论。
- `quality_flags[]`：程序发现的关键口径矛盾，例如原文写“每10股派息45.53元”、分析文字写“每股45.53元”。关键矛盾会阻止正常结束；若仍未修正，结果状态为 `partial`。
- `audit_profile.opinion_verification_status`：必须同时核对审计意见摘录与意见类型。审计师签字、事务所名称等虽能在原文找到，也不能代替审计意见证据。
- `coverage[].verification_status`：除检查引文是否能回到原页，还检查引文是否涉及该覆盖主题；“无其他应披露事项”这类有限范围表述不能据此概括该主题完全没有事项。
- 结果外层 `status`：`completed`、`partial` 或 `failed`。`partial` 必须和完整分析分开展示，并列出已完成和未完成部分。

意见类型和审计关注点不是公司评级。对于无重要事项的正常结果，完整显示实际检查过的范围与“未命中/明确无事项”的区别；不要生成红色风险面板凑内容。

## V3.6.2 独立工作台实现

- 独立页面组件：`frontend/src/DisclosureWorkspace.jsx`；`App.jsx` 只做入口接线。上传页不显示模块选择器，默认并固定提交 `analysis_module=disclosure`。
- 运行服务：`启动模块六工作台.ps1`，地址 `http://127.0.0.1:8106`；Vite 开发代理也指向 8106。健康检查核对模块 ID 和版本，避免误把 8007 或其他进程当成本服务。
- 本机隔离：本目录 `.env`、`data/app/`、构建目录、日志均属于 V3.6.2。本机 Key 不提交；上传 PDF 不进入 Git。
- 结果页面按字段展示审计意见、所有实际 `findings[]`、`impacts[]`、`coverage[]`、`calculations[]`、限制、质量标记和可展开原文。运行状态与完整性/复核状态分开显示；`partial`、`insufficient_material`、`failed` 不作为完整分析。
- 部分结果由 `disclosure_checkpoint.json` 适配，保留中断原因、已提交专题/影响/计算、已读页和门禁问题。检查点文字不会被包装成门禁通过。
- 追问将本次模块结果、模块六专业指导、最近问答与新检索并读取的年报页一并提供给模型；对引用页和摘录做本地匹配，并明示摘录匹配不是专业结论证实。
- 当前只连接本目录服务。合并时应单独审核新增状态字段、静态入口、`/api/settings/deepseek-key`、追问的 `ReportContext` 重建以及上传路由默认模块；不得覆写总基底里的同名公共文件。
