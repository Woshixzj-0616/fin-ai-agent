## 页面与能力

本模块可直接上传一份年报 PDF，不要求先运行模块一。若未来公共 API 提供模块一结果，它只能作为可选背景；利润事实、复算、证据核验和结论仍以本模块读取的年报为依据。

结果页按模块二结构展示：

1. 归母净利润金额变化、盈亏方向和跨越零点的状态。
2. 营业毛利率以及销售、管理、研发、财务费用率等程序复算指标。
3. 归母利润变化桥：目标变化、已识别会计贡献、未分类差额、是否重复纳入及出处。
4. 营业利润、利润总额、净利润、归母和扣非利润的勾稽。
5. 利润表收入、成本、费用和其他损益原始事实，保留年报科目名、分析归类、两期金额、核验状态和 PDF 回查。
6. 分业务收入、成本、毛利率和报告口径；非经常性损益逐项展示。
7. 盈利变化解释、覆盖状态、待核事项、分析限制和模型读取页码。
8. 继续追问：请求携带本次模块二结果及专业规则，可检索和回读同一份年报。

运行结束与分析完整度分开显示。模块状态包括完整、完成但待核、部分完成、资料不足；服务异常时显示运行中断，并尽可能恢复已保存的事实。空值用未提取/未披露呈现，不默认改成零。原文片段匹配只说明能够回查，不代表专业判断已经证实。

## 隔离边界

- 后端仅接受 `profit` 模块，健康信息会返回模块 ID 和版本；页面启动时核对这一标识。
- API 请求使用本服务同源 `/api`。开发代理默认是 `127.0.0.1:8102`，不连接旧工作台的 `8007`。
- 上传、数据库历史和本地文件位于本任务目录的 `data/app/`；运行日志写入本任务 `logs/`，均被 Git 忽略。
- DeepSeek 配置读取本任务根目录 `.env`，由启动文件设置 `FINLAB_CONFIG_PATH`。网页保存的 Key 也写入这个文件。配置文件不提交；密钥不输出到界面日志或交接说明。
- 启动文件会先清除启动 shell 继承的 DeepSeek 配置变量，再由本任务 `.env` 加载本工作台配置，避免被其他工作台的进程环境覆盖。
- 前端依赖复用本机已安装的依赖副本，复制到本任务 `frontend/node_modules/`；不会改写原基底依赖目录。
- 端口已在启动时检查。若 8102 正被不同服务占用，启动文件会停止并提示，不会终止或接管其他服务。

## 后续集成时需一起检查的文件

模块算法、独立界面和服务隔离目前都在本任务分支。后续合并时，建议按文件责任拆分检查，而不是只挑页面或 API：

- 模块逻辑与状态：`backend/modules/profit/engine.py`、`backend/app.py`
- 模块二页面和共享页面的少量接线：`frontend/src/V2Workbench.jsx`、`frontend/src/ProfitWorkbench.jsx`、`frontend/src/App.jsx`、`frontend/src/styles.css`
- 独立构建和本地服务目标：`frontend/.env.profit`、`frontend/vite.config.js`、`frontend/package.json`
- 独立启动入口：`启动模块二工作台.ps1`、`打开模块二工作台.cmd`
- 边界回归：`tests/test_profit_workbench.py`

`V2Workbench.jsx`、`app.py` 和 `engine.py` 属于共享文件，集成时要检查目标分支上的任务 01、任务 07/08 改动，再按冲突逐段合并。专用页面通过 `VITE_WORKBENCH_MODULE=profit` 选择；非 profit 模式仍沿用原通用入口。模块二运行约束不要复制到总控服务，否则会限制其他模块。
