## 5. 数据与证据处理

### 5.1 事实分开保存

一条事实表达一个明确期间、范围、维度与口径的值，本期和上期独立核验，再按需要配成对照行。模块内部至少保留报告身份、指标和原名、原值/单位、币种、实际期间、报表范围、调整口径、业务维度、来源、核验状态与修订版本。

区分：原文披露值、程序推导值、未提取、报告明确未披露、空白、零、冲突和不可比。缺上期不抹掉有效本期数据，也不能仅因检索失败就声称未披露。

先使用模块内部的 `profit:` 身份和引用保存关联，不声称已建立全系统公共事实库。总控提供公共身份时通过适配映射，保留原关联。

### 5.2 证据是可独立回查的真实片段

金额所在行、表头的期间/单位/范围、附注解释可来自不同片段，每段单独保存物理页码和原文。页码说明、模型解释和省略号不插入原文片段。

核验区分原文片段是否存在、数值是否出现、项目与列头的关联是否清楚、单位与范围是否支持计算。文字匹配成功只能确认出处片段，不自动证明全部语义正确。需要更多表格上下文时让模型重新读页并提交定位；仍不清楚就保留待核。

支持空白/换行等机械差异，保留原件定位。不能把长引文随意删改成通过匹配，也不能只查数字出现就认定该值属于正确年度和科目。

### 5.3 合并与母公司、业务维度分别处理

先限定目标期间、范围、币种、指标和调整口径，再选候选值。同口径重复披露保留多个来源；真实冲突进入定向补查。母公司数据作为单独视角，不能因与合并不同而阻断合并计算。

业务专属结构保存业务身份和分类维度、收入、成本、披露毛利率及程序毛利率，各值有自己的期间和来源。产品、地区、渠道维度不混合求和；可配对才计算业务毛利和变化。比例走比例处理，不换算成人民币金额。由四舍五入的增减比例推得的历史金额不能冒充披露原值。

非经常性损益按表的实际税前项目、税影响、少数股东影响和归母净额定义保存，不机械套入普通合并利润行结构。

## 6. 产品中的实际执行流程

1. **定位与初始提取**：通过基底全文检索、读页和初筛资料寻找主表、续表、业务毛利、费用、特殊项目及对应附注。保存完整模型原始响应。
2. **核验与初次计算**：程序整理事实、处理选数和配对，返回明确问题；计算能使用的数据，不等待所有资料齐全。
3. **事实修复补查**：向 DeepSeek 传入具体阻断原因，返回新增/修订事实及证据；核验后更新底表和受影响计算。保留新旧值与修订理由。
4. **专业专题调查**：DeepSeek 根据可靠计算和已读原文选择重点，查阅相关附注、业务资料及公司解释。专题可能再次提出事实修订或新增计算。
5. **解释与结果组织**：每次调用附当前专业指导、任务状态、相关原文和必要事实。解释关联事实和计算，不由模型重新心算贡献总和。保存专属正文、表格/图形建议、限制及交接问题。
6. **阶段保存与交付**：提取、计算、每轮修订和解释完成即保存模块阶段材料与状态，返回现有工作流结构以及新专业结果。

重点补查分为“修复计算所需数据”和“解释重要变化”，避免用大量文字原因掩盖底表还未建立的问题。先处理关键目标利润、收入成本及贡献阻断，再根据影响和材料决定重点。

用有限的模型调用、工具轮数、累计上下文及输出预算控制任务。首轮实现可采用最多两轮事实修复，其余专题按总预算自主选择；该默认可调整，不意味着必须读两轮或分析达到某轮便准确。每轮保存进展与缺口，预算耗尽返回部分成果，避免无限循环。首次实跑后根据真实用量和补查效果调整默认值。

上下文按专题挑选相关证据，不按页号从前往后填满；保留完整字段，不直接截断 JSON。每次调用具备当前阶段需要的指导和材料，不依赖前次请求的记忆。失败调用已取得的材料继续保留，网络错误与专业缺口分别记录。

## 7. 程序计算清单

| 计算 | 必要口径与处理 |
| --- | --- |
| 两期金额和变化 | 单期可用与两期可比分开；上期零/负数保留金额变化，不硬算普通增长率 |
| 利润层次勾稽 | 营业利润→税前→合并净利润→归母，原表实际加减关系，父子项目不重复 |
| 毛利与利润率 | 营业收入配营业成本，营业总收入/总成本不能冒充；净利率明确是合并/归母/扣非分子及分母 |
| 业务毛利 | 相同期间、业务定义、维度和范围配对；不能据毛利说产品净利润 |
| 毛利因素 | 数据满足时：Δ毛利=(R1−R0)×m0+R1×(m1−m0)，说明替代顺序；收入规模项不能自动称销量影响 |
| 费用和占比 | 费用变化的利润影响、费用/同范围营业收入、百分点变化；负财务费用按原符号 |
| 贡献桥 | 目标利润明确，按范围和层次分解，保留父子细节及未分类残差 |
| 税负及归属 | 用实际所得税费用；税前为正等条件满足才计算有效税负；少数股东负值不得误反号 |
| 扣非调节 | 归母−扣非与非经常性损益归母净额核对，税前项目、税及少数股东影响按原表关系 |

所有已定义计算使用 Decimal，记录输入身份、公式/版本、范围、期间、状态及出处。精度容差来自单位、显示精度和参与项，不用任意百分比掩盖差额。模型可提出其他有资料支持的计算，声明公式和条件后由程序计算，不能无限开放代码执行。

旧版正确规则继续使用；改动集中在真实阻断和缺失能力。精度内勾稽通过代表算术关系成立，经营原因仍需对应证据。

## 10. 按成果推进的实施与验收

### 步骤一：建立可复核参照并整理专业代码

按基底样本清单核对输入身份；对伊利旧任务逐条登记引用、行列、符号、范围、单位、角色和阻断原因。人工参照从原 PDF 得到，模型旧输出作为候选。将模块二实现逐步整理到专属目录，旧入口兼容，明确专业方法与原页映射。

完成标准：知道关键错项及空计算的具体原因，兼容入口和独立入口都连接真实实现；迁移本身不改变原专业结果。

### 步骤二：取得可靠且可用的盈利数据

实现多片段证据、逐期间核验、目标范围选数、业务资料专属结构、非经常性损益口径和明确状态。

完成标准：关键合并利润、收入成本与归母/扣非逐项对得上；母公司不误阻断；业务金额保留在结构化结果；未核值不冒充确认值。

### 步骤三：落实适用计算和差额解释

完善计算清单及回归检查，记录公式与来源，将不同利润目标及各层次分解讲清楚。

完成标准：伊利原来的空利润桥与零指标有实际修复结果；确认数据的关键勾稽和适用计算完成；不具备条件的计算给出具体拒绝原因，不以凑数量验收。

## 14. 2026-10-08 跨公司边界与利润方向修订

继续复核宁德时代、隆基 2024 年报后，新增两类真实报表边界处理。以下原件页码均为年报印刷页码；专项回归使用从原件核对后转录的表格片段，属于确定性事实与计算验证，不是重新调用 DeepSeek 的完整端到端报告验收。

- **跨越盈亏零点：**隆基归母净利润从 2023 年的 10,751,425,556.38 元转为 2024 年的 −8,617,528,506.44 元，金额变化 −19,368,954,062.82 元。原年报列有 −180.15% 的变化率；程序现在在由盈转亏、由亏转盈等跨零场景下不生成普通同比百分比，而是显示两期金额、金额差和方向，并提示不可按普通增减幅度解读。模型解释提示词也要求优先说明方向和金额，不将跨零百分比当作普通同比。
