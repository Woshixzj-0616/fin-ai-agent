# 产品与系统规划：DeepSeek 财报分析工作台

日期：2026-09-28。本文件规定最终产品要做成什么样，以及各部分如何配合。阶段一已实现单份财报上传、候选页抽取、DeepSeek 调用代码、任务记录和基础结果页；多轮分析、研报核查和证据侧栏仍属于后续阶段。真实 API 请求需要在本机配置密钥后联调。

## 1. 产品一句话

用户上传财报和研报 PDF，系统调用 DeepSeek 按固定流程读材料、分析财务变化、核查研报说法，在好用的网页上给出结构化结果、原文出处和不确定项。DeepSeek 是核心分析者；小程序是它的文件入口、会话管理器、工具执行器和结果界面。

## 2. 用户实际操作

1. **新建任务**：拖入一份或多份财报，研报可选；输入公司或由模型识别；选择“分析财报”“核查研报”或两者一起。上传后先显示文件名、页数、公司、期间和披露日期供用户核对。
2. **运行中**：页面显示“识别材料 → 查找关键数据 → 分析 → 核查 → 整理结果”的实际进度。长任务能看到已完成部分、正在查哪份材料以及失败原因；刷新页面可返回已有结果。
3. **看结果**：顶部是三四句重点摘要和关键指标卡；“财务数据”“财报分析”“研报核查”三个标签页展示细节。数值旁标明单位、期间及来源；分析段落按“事实 / 公司披露解释 / 模型判断”区分；核查列表显示原句、结论、原因与修改建议。
4. **核对依据**：点击结果旁的出处，在侧栏打开对应 PDF 页并定位相关文字。证据不足时显示“待复核”，用户可追加材料或提出追问。
5. **带走结果**：导出带来源的 HTML/PDF 报告及结构化数据；历史任务可重新打开，标明当时使用的文件版本和模型配置。

初赛先做单用户本地网页，重点保证一次任务从上传到结果完整可用。用户登录、团队协作、复杂权限和大规模并发放到后续。

## 3. 程序的五个部分

| 部分 | 职责 | 首期做法 |
| --- | --- | --- |
| 网页前端 | 上传、任务进度、结果阅读、PDF 对照、导出 | React 单页界面，减少页面跳转；先保证桌面端清晰可用 |
| 文件层 | 保存原件、页码、版本和可读材料 | Python 读取 PDF 文字和渲染必要页面；无本地金融模型 |
| AI 接口层 | 调用 DeepSeek，处理超时、错误、用量与模型选择 | 服务器持有 API Key；统一接口供所有步骤使用 |
| 工作流层 | 装配上下文、给模型工具、执行多轮调用、保存中间结果 | 版本化流程指令 + 有上限的查页/计算工具调用 |
| 结果层 | 保存结构化数据并渲染页面、导出文件 | SQLite 保存任务和结果；网页从结构化字段生成，不直接堆一大段模型原文 |

Python 后端沿用现有的 PDF 工具和数据代码。网页负责可用性；DeepSeek 负责财务含义与文字结论；普通程序负责文件格式、精确计算和状态保存。

## 4. 每次调用怎样保持上下文

DeepSeek 对话 API 无状态，程序需要保存本次任务，并在**每一次请求**中重新组装模型要用的信息：

```text
固定流程指令（版本号、角色、步骤、输出要求）
+ 本次任务范围（公司、期间、财报/研报文件 ID、可用版本）
+ 当前阶段的目标（提取、分析、核查或补查）
+ 该阶段已经取得的事实、证据 ID 和必要对话/工具结果
+ 当前检索到的 PDF 页内容
+ 允许调用的工具定义
→ DeepSeek 的下一步或结构化结果
```

程序保存模型回复和工具结果，下一次调用再带回相关内容。带工具的思考模式需要按官方要求回传历史 `reasoning_content`，否则可能收到接口错误。不同用户任务相互隔离，不能串用材料。文档很长时，不把整本财报和全部历史对话反复塞入：保留原件和结构化状态，按需送入相关页；流程指令每次都带上。

“产品 skill”就是版本化的流程指令加上工具的使用约定。它属于成品运行逻辑，不是开发者个人的 Codex/ChatGPT skill。修改流程后可以用固定样例比较效果。

## 5. 结构化结果怎样变成好看的页面

模型返回固定字段，例如 `summary`、`facts`、`analysis_sections`、`findings`、`evidence_ids`、`uncertainties`。后端先检查字段和证据引用，再交给前端；原始输出仍保存供排错。

- **摘要**：只放最值得看的结论，附“已查多少项 / 待复核多少项”，不声称整份材料全对。
- **指标卡**：本期数、上期数、变化方向与单位；点击查看财报原页。
- **分析段落**：标题、判断、依据和限定条件分开显示，便于新手读懂。
- **核查清单**：逐条列研报原句、状态、财报依据与建议；支持按错误/待复核筛选。
- **证据侧栏**：左右对照研报页与财报页，避免用户来回翻文件。
- **失败状态**：文件不可读、API 失败、超出支持范围都在页面明确提示，不展示预写的假结果。

## 6. 开发与验收顺序

按可运行版本递进的建设顺序与各阶段验收条件见 [分阶段建设路线](分阶段建设路线.md)。先建立真实的上传、调用和展示主链；随后加入连续会话、结构化分析、研报核查、完整交互和跨材料评测。每个阶段都交付可操作的版本。

官方接口依据：[多轮对话与无状态 API](https://api-docs.deepseek.com/guides/multi_round_chat)、[工具调用与思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)、[结构化输出与流式响应](https://api-docs.deepseek.com/api/create-chat-completion/)。
