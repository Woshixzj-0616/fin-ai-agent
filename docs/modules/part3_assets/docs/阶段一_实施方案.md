# 阶段一实施方案：上传财报，获得真实 DeepSeek 财务概览

状态：代码主体已实现；还需要在本机配置 DeepSeek API Key，才能进行真实模型联调。阶段一建立第一条产品主链：**用户上传一份财报 PDF → 程序准备带页码的材料 → 调用 DeepSeek → 网页展示针对该文件生成的概览**。它是后续能力的底座，不承担完整财报分析或研报核查。

## 1. 用户看到什么

一个本地网页，分为三块：

1. **首次配置**：尚未配置 API Key 时，首次打开网页会弹出配置窗口。密钥由本机服务写入项目 `.env`，网页不将密钥存入浏览器缓存；顶部模型状态可重新打开配置窗口。
2. **上传区**：拖放或选择一份 PDF。选择后立即显示文件名和大小；上传后，处理区会显示 PDF 总页数及准备提交给模型的页码。单文件限制为 25 MB。
3. **运行区**：依次显示“接收文件、读取页面、准备关键页面、请求 DeepSeek”。等待时按钮禁用；出错时显示可理解的原因。要重试时重新选择同一份 PDF。
4. **结果区**：公司与报告期、关键财务事实、简短概览、“模型未找到或无法确认的信息”，以及本次送入模型的 PDF 页码。结果按卡片与段落显示，并提供打开本机原始 PDF 的入口。

网页从第一版就有清楚的层级和反馈，但先不做复杂图表和完整 PDF 双栏定位；这些属于后续阶段。

## 2. 一次点击背后的处理链

```mermaid
flowchart LR
  A[上传 PDF] --> B[文件校验与保存]
  B --> C[按页读取文字]
  C --> D[选取封面与财务指标候选页]
  D --> E[组装固定流程指令和带页码片段]
  E --> F[DeepSeek API]
  F --> G[校验结构化返回]
  G --> H[网页卡片与状态]
```

**文件入口**：后端只接收实际为 PDF 的文件，限制单文件大小，随机生成文件 ID 并保存原件，不把原文件名直接当路径。记录 SHA-256 和页数；文本提取失败时显示“当前版本无法读取该 PDF”，保留失败原因。

**材料准备**：PyMuPDF 只负责读取文字、保留 PDF 页序，不运行任何本地金融模型。先定位封面和含“主要会计数据和财务指标”“营业收入”“归属于上市公司股东的净利润”等通用词的候选页；限制送入模型的页数与文字量。发送的每段文本标明文档 ID 和 `PDF 第 N 页`。如果候选页不足，模型必须说明它看到了哪些页以及哪些结论无法确认。这个阶段称为“财务概览”，不宣称读完了整本年报。

**模型调用**：后端从 `DEEPSEEK_API_KEY` 环境变量读密钥，调用官方 OpenAI 兼容接口，首选 `deepseek-flash`。每次请求都重新加入 `财务概览_v1` 固定指令、当前文件信息、选中的页内容和输出要求。第一阶段只做一次模型请求；多轮查页和追问在第二阶段接入。当前 [Files API](https://api-docs.deepseek.com/guides/files_api/)只列出图片格式，因此此处传带页码的文字片段，不假设可由我们的程序直接上传 PDF 给 API。

**结果格式**：要求 DeepSeek 输出 JSON 对象，字段至少为 `company`、`period`、`summary`、`facts`、`uncertainties`、`read_pages`。`facts` 中每项有指标名称、原文数值、单位、期间和所引 PDF 页码；未知项留空并说明。后端检查 JSON 格式与页码是否属于本次实际提供的页面，再将字段返回前端。JSON 格式合格不代表事实已独立验证；第二阶段再加入计算和证据回查。

**任务记录**：保存文档 ID、文件指纹、选中页码、提示词版本、所用模型、请求状态及结果。第一阶段可以只支持本机单用户和最近任务，数据结构要能继续扩展到多轮会话与研报核查。

## 3. 技术落点

| 层 | 首期选择 | 理由 |
| --- | --- | --- |
| 网页 | React + Vite | 上传交互、加载状态和结果卡片可逐步扩展为工作台 |
| 后端 | Python + FastAPI | 复用仓库已有 Python/PyMuPDF 基础，提供上传与分析接口 |
| PDF 读取 | PyMuPDF | 机械读取文字和页码；财务理解交给 DeepSeek |
| 模型 | DeepSeek 官方 API | 服务器保存密钥；界面只接收后端整理后的结果 |
| 本地记录 | SQLite + 原始 PDF 文件 | 保存一次任务所需信息，后续能加历史、证据和多轮状态 |

实际文件位置：`frontend/` 放网页；`backend/app.py` 放上传、任务和原文件查看接口，`backend/pdf_reader.py` 放页面读取，`backend/deepseek_client.py` 放模型调用及返回格式整理，`backend/prompts/财务概览_v1.md` 放流程指令，`backend/database.py` 管本机任务记录。原始上传文件与本地数据库加入 `.gitignore`；`.env.example` 只列配置项，真实密钥只放在本机 `.env`。

项目提供 `启动阶段一.ps1`，会检查 Python 3.12+、准备依赖、构建网页并启动本机服务。没有 API Key 时也能打开网页并显示配置弹窗；保存后可立即使用，无需重启服务。

## 4. 实施顺序

1. **已完成**：建立 React + FastAPI 应用骨架，提供单 PDF 上传校验、任务状态查询和本机 SQLite 记录。
2. **已完成**：加入 PyMuPDF 页面文字提取、关键页排序、页数/文本量限制，并在运行区和结果区显示实际页码。
3. **已完成**：加入版本化提示词、DeepSeek OpenAI 兼容接口调用、JSON 结果整理和页码范围检查。
4. **已完成**：完成首次 Key 配置弹窗、上传、等待、失败、结果界面；增加本机原 PDF 打开入口和启动说明。
5. **待本机联调**：配置 API Key 后，用项目中的年报逐项确认模型实际调用、页码与原件对应、结果呈现正常，并记录失败情况。当前环境没有 API Key，因此尚未完成真实模型请求。

## 5. 阶段一完成的标准

- 代码路径已接通；配置 API Key 后，用户在网页上传新的可读财报 PDF，应能触发真实 DeepSeek API 请求并看到针对该文件生成的概览。此项仍待本机联调确认。
- 页面清楚显示模型读到的页码；公司、期间或指标无法确定时不会编造。
- 换文件得到新的任务记录与结果；没有 API Key、网络失败、无效 PDF、文字不可读、模型返回不合格式时均有明确反馈。
- 原始 PDF、密钥和结果各有正确存放位置；刷新页面能重新打开最近任务。

阶段一代码已落地，真实 API 联调和财报样例验收完成后再进入 [阶段二](分阶段建设路线.md)：增加多轮上下文、按需查页、精确计算、结构化财报分析和证据定位。

API 依据：[首次调用](https://api-docs.deepseek.com/guides/harness)、[对话补全与 JSON 输出](https://api-docs.deepseek.com/api/create-chat-completion/)、[无状态对话](https://api-docs.deepseek.com/guides/multi_round_chat/)。
