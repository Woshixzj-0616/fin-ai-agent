# 阶段三实施方案：V3.0 研报逐条核查

编制日期：2026-09-29。当前状态：V3.0 已进入实现和联调；原始目标与验收条款继续作为本阶段验收标准，实际完成情况见文末“执行记录”。本方案依据 V2.0.1 代码和已有材料清单制定，按能力递进，不按天数排期。

## 1. 交付目标

用户上传同一家公司的原始研报 PDF 和对应年报 PDF，确认材料身份后启动核查。DeepSeek 提取可核查说法、查阅财报并判断；程序管理证据、精确计算、检查引用及保存结果。网页逐条展示研报原句、核查状态、财报依据、计算过程和建议改法，支持针对某条结果追问。

阶段三完成方向 1、2、5 的基本流程：提取财务数据 → 理解与分析 → 核查研报。可靠性提升的程度须由实际评测说明，不能只凭加入工具就宣称优于直接调用模型。

## 2. 输入与支持范围

- 正式输入：可提取文字的中文原始研报 PDF，以及同一公司的年度财报 PDF。先支持一家公司的一个目标年度、一个研报；年报可以包含原版及修订版供时点选择。
- 四个核心指标：营业收入、归母净利润、扣非归母净利润、经营活动现金流量净额，核查目标年度、可比上期及其变化。营业收入和营业总收入分别保留身份，不自动混用。
- 六类检查：数值、单位、期间、指标或报表口径、计算、所引财报是否支持表述。引用检查限于上传材料。
- 研报中的预测、评级、目标价、估值合理性和行业外部信息保留原句，标为超出当前范围。材料缺失的范围内历史事实标为证据不足。
- 真实研报里的季度数据不拿年度数据比；本阶段仅支持年度核查，季度说法列为范围外并说明所需材料。
- 扫描件 OCR、复杂跨页表格的全面识别、互联网自动补材料、自动修改研报原 PDF 留待后续。抽取异常必须显示，不静默跳过。
- 粘贴文本可作为补充入口和模拟草稿载体，原始 PDF 是正式验收输入。原件不修改，模拟错误样例单独保存并明确标识。

## 3. 在 V2.0 上如何扩展

现有后端为 FastAPI + SQLite，前端为 React，PDF 文字提取使用 PyMuPDF，分析调用 DeepSeek。继续沿用这套结构。

现状及必要改动：

1. `runs` 目前直接保存一份 PDF 路径，`run_pages` 以任务和页码定位。V3 改为任务关联多份文档，页码必须同时带文档 ID，避免两个 PDF 的第 6 页混淆。
2. V2 的指标展示最多保留 12 项，不能把这张概览表当成完整核查依据。V3 为每条说法独立查证，复用已取得的原文证据。
3. V2 的单页工具最多传入 4,800 个字符。V3 增加页内分段读取，返回起止位置、是否读完及续读位置，防止页尾表格被截断。
4. V2 的摘录匹配只证明文字出现过。V3 还必须检查公司、期间、指标、合并或母公司口径、单位、历史或预测属性及版本。程序匹配通过不等于财务解释正确。
5. V2 服务重启会把在途任务标为失败。V3 增加逐批保存和显式继续处理入口，保留已经完成的核查项。

## 4. 用户实际操作

1. 新建任务，分别上传财报和研报。材料卡显示文件名、公司、年度、研报机构及日期、财报版本和文字可读情况。
2. 模型识别的信息附来源，允许用户修正。日期缺失时不能把 PDF 文件创建时间当作披露时间；未知状态保留，并限制依赖时点的判断。
3. 用户确认材料后开始。页面显示：读取研报 → 整理待核查项 → 查阅财报 → 核对计算与依据 → 汇总。
4. 结果页显示已提取项、已完成项、一致项、错误项、待复核项、范围外项和未完成项。
5. 点击某条，看到完整原句、拆分出的具体主张、双方 PDF 页序及摘录、计算输入和建议。支持切换打开双方原页；精细高亮及完善的并排阅读放入阶段四。
6. 可针对某条追问“为什么判错”“依据是什么”。追问记录绑定核查项，补查结果单独保存；重新核查生成新修订，保留旧判断。

## 5. DeepSeek 核查流程

### A. 核对材料身份

识别公司、目标年度、研报发表日、财报披露日及版本。上传日期不能代替披露日期。可信元数据来自原文、已有来源登记或用户明确确认，并记录来源。

用户选择适用版本；在可确认时间的前提下，程序禁止用研报发表后披露的财报作为判错依据。多个当时已公开的版本有调整关系时保存版本依据，不能简单以文件修改时间或最大的文件名选择。

如果只有较晚修订版，显示需要补充原版；日期或版本无法确认的相关项暂列待复核，不给出确定错误结论。

### B. 分段抽取研报说法

按页及页内段落依次处理，保留少量相邻上下文。模型返回原句、位置、公司、指标、数值、单位、期间、口径、事实或预测类别。表格中的说法保留行标题、年度列标题及单位出处。

一句话含多个主张时拆开，保留共同原句，例如收入数值、同比及利润数值分别核查。去重依据来源位置及主张身份，不能把原本互相矛盾的两处数字合并掉。

程序记录哪些页及分段已处理、哪些失败或不可读。所有提取项均保留去向。限额造成的剩余项显示为未完成，不能伪装成范围外。页面读取完成也不等于模型提取到了全部说法；实际提取召回率另用人工样例评估。

### C. 按需找证据

先复用同任务已确认身份的证据，再按指标原名、别名、年度及关键语句检索财报。DeepSeek 决定补读哪些页和片段；程序执行受限工具并保存实际交付的内容。

工具沿用并扩展为带文档 ID 的搜索、分段读页、单位换算、差额及同比计算。检索命中只是候选，最终证据必须包含足以确认数字身份的表头、数值和单位。必要时读取相邻页；仍有歧义则待复核。

### D. 比较与形成判断

先核对比较对象，再比较数值。数值采用 Decimal；按研报实际显示精度处理四舍五入。正常舍入不判错。前期为零或负数时不机械套普通同比；无法确认口径就不给确定百分比结论。

结论采用四类：

| 状态 | 条件 | 输出要求 |
| --- | --- | --- |
| 已核对一致 | 上传材料支持该具体主张，比较身份明确 | 双方依据和适用范围 |
| 发现错误 | 同公司、同期间、同口径、适用版本下存在明确冲突 | 原句、冲突、正确依据、建议改法 |
| 证据不足 | 缺少证据、身份不明、日期版本不明或抽取有歧义 | 缺什么、为何不能定论 |
| 超出当前范围 | 预测、投资意见、外部信息或未支持的指标期间 | 说明范围原因 |

另设处理状态：待处理、运行中、完成、失败。调用失败不等于证据不足，未处理不等于一致。

### E. 程序检查并保存

结构化输出须通过字段校验。每个引用须属于当前任务、文档和实际交付给模型的片段。研报原句及财报引文按明确的空白或排版规范化规则匹配；不改写成看似原文的句子。

有问题的输出允许一次定向补查或修正；仍失败则保留为失败或待复核，不能作为确定判错结果。一次通用重问不能替代缺失的证据。每条结果分别存储模型判断、程序检查状态及人工复核状态。

每次模型调用重新带上：版本化流程指令、当前任务材料范围和时点、当前核查项、必要事实及证据、近期相关问答。人工参考答案不进入产品请求；PDF 内的指令文字始终作为材料内容。

## 7. 长任务与成本控制

V3.0 开发版每次继续处理最多核查 4 条，每条最多 3 轮工具交互；每轮最多输入 160,000、输出 18,000 tokens。单条核查按最坏情况分别预留 50,000 输入、6,000 输出 tokens；研报每个抽取分段分别预留 20,000 输入、最多输出 5,000 tokens。单任务最多读取前 40 页、提取 80 条。达到单轮边界后保存已完成项，剩余条目由用户显式继续。Token 总量随任务显示。该限制控制单轮调用量，不是整个任务的总费用上限。

按文档指纹及片段缓存提取文字；同一调用不重复塞入整本财报或全部历史对话。累计记录模型用量、耗时及读取范围。

每批成功后写入数据库，刷新页面可继续查看。断网或重启保留已完成结果，用户可继续未完成项；重试不能重复生成同一主张或误把旧结果当新结果。用户停止时在可中断边界停止后续调用并保存当前成果。

## 9. 验收材料与标准

已有 `data/cases/case_sources.csv` 可提供样例配对路径；开发前逐份核对文件存在、版本与披露日期，不把清单备注直接当作核查答案。

- 宁德时代：已收集的国信证券 2024 年年报点评及其对应年报，作为首条完整流程样例，重点检查历史值与预测列。
- 隆基绿能：原年报、后续修订版及已收集研报，验证时点限制、负基数和季度混入问题。具体时点再次依据原件及来源记录确认。
- 从其他已收集公司选一组保留材料，不依据其答案定制提示；冻结指令后用于检查跨公司流程。
- 另建至少 24 条清楚标注的模拟主张，六种检查类型各有正确与错误情况，并增加缺证、范围外、舍入、混合正误句等边界样例。模拟样本和真实研报统计分开，不宣称券商原报告含有人工植入的错误。

人工答案以年报原件为依据，记录双方页码、身份、计算和预期状态。由队员复核，涉及有争议的财务口径请具备相应知识的人确认；未复核答案不算金标准。人工核对只服务于评测，不参与应用每次生成结论。

阶段完成标准：

1. 至少两组真实 PDF 完成上传、提取、查证、结果与追问，其中一组未针对其答案调试；另完成版本边界场景。
2. 所有确定错误项都能打开双方原文、解释比较身份并给出有依据的修改建议；不允许伪造引用或越权引用其他任务文档。
3. 冻结样例中已发现的舍入、预测、期间、口径与版本误报修复后重跑；尚有争议的项列为待复核，保留失败记录。
4. 逐页处理覆盖、提取遗漏、未完成核查分别记录，不能用已提取项的完成比例代替全文覆盖率。
5. 刷新、调用失败、进程重启后不丢已完成项；继续处理不重复计算已有完成项。
6. 输出实际统计：主张提取召回、错误检出和误报的数量及分母、待复核比例、耗时和 Token。小样本不换算成夸大的整体准确率。
7. 保存本地 V3.0 代码版本、启动说明、样例运行记录和已知问题。集中界面美化、完善导出和大规模模型对照留给后续阶段；基础评测从本阶段开始。

## 10. 最终可演示流程

上传原始年报及研报 → 确认材料及日期 → 展示待核查说法 → 逐条产生结果 → 点击一个疑似错误查看双方页码及计算 → 查看建议 → 对该项追问 → 刷新后记录仍在。

真实研报可能没有范围内的错误，应如实显示一致和待复核项。需要演示错误定位时，另展示标明人工改动的模拟草稿，保留原句及改动来源。
