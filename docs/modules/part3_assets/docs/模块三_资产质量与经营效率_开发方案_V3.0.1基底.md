## 3. 模块内的五个分析板块

这是模块三内部的专业方向，非新增五个顶层模块。页面保留这些阅读入口；材料不适用或缺失时给出具体说明，不伪造充实内容。

### 3.1 整体资产占用与变化

读取合并资产负债表及必要附注，列出流动/非流动资产、主要净额科目、两期结构和增减金额。货币资金和金融投资资产也进入结构视图，避免分析仅覆盖制造业的应收和存货。

先按金额、资产占比、变化幅度、业务性质及已披露事项识别值得深入的科目。大额稳定科目也可能重要，低金额但披露异常的科目不因为排名靠后被排除。具体深入数量随报告决定，不设统一风险分数。

结果：主要资产占用表、结构变化、需要继续阅读的附注，以及经营背景如何帮助理解这些变化。科目净额增减只能先描述账面变动，不直接称为现金投入或现金回收。

### 3.2 应收及其他资金占用的回收质量

核心应收：分别读取应收账款账面余额、减值准备、账面价值；账龄分布、单项/组合计提、客户集中度、计提/转回/核销、期后收款及信用政策（限实际披露）。

销售形成的应收票据、应收款项融资、合同资产单独识别。票据及融资项目保留承兑类型、追索/终止确认或受限信息（如披露）；合同资产关注收款权的条件。它们可以组成显式命名的扩展资金占用指标，不能静默并入应收账款周转率。

预付款项、其他应收款和其他流动资产先按结构和性质筛查；重要时追查对象、用途、账龄、关联关系及回收信息。不能把其他应收款当作销售应收，也不能凭“关联方”标签认定违规占用。

必须能够区分：余额因收款下降、因减值导致净额下降、因核销下降、因重分类或合并范围变化下降。没有足够数据时并列已知事实和未解决解释，不把表面周转改善写成已证实的回款改善。

结果：应收总额—准备—净额对照、可比较的账龄变化、主要回收线索及专题。账龄与逾期不同，账龄桶边界改变时先说明不可直接比较。

### 3.3 存货结构、周转和减值

读取存货总额、跌价准备、净额及公司自己的分类：原材料、在产品、库存商品/产成品、发出商品等；不能把所有企业硬映射成相同分类。即使合计稳定，也比较分类增减和构成。

关联营业成本、业务产销量、订单、采购、产品价格及管理层解释（报告实际披露的部分）。关注分类跌价准备、计提/转回/转销、库龄或滞销说明。缺少库存明细、订单或分类对应成本时，说明无法验证哪些解释。

产成品占比上升可以提出备货、交付延迟、销售放缓或产品结构变化等方向；是否展开以及优先查哪项由证据决定，不能自动判为滞销。没有分类成本时不按总成本随意分摊计算分类周转。

结果：分类变化表、准备和净额变化、适用的周转指标，以及有证据支撑的主要解释。

### 3.4 长期资产投入、使用和价值线索

核心：固定资产、在建工程及重要项目。读取原值、累计折旧、减值和净额；在建工程期初/期末、本期增加、转固、其他减少、项目预算与进度等实际字段。

按证据联系投产、产能利用、停建/延期、处置、减值和折旧变化。固定资产净额下降可能来自折旧、处置或减值；在建工程增长可能来自合理扩张。项目预算完成比例和工程进度分别保留，不能直接互换。

公司存在重要的商誉、无形资产、使用权资产、长期股权投资或其他投资资产时，开相应专题：来源、账面变化、与业务联系、披露的减值/估值条件及限制。商誉和无形资产分别记录；投资资产账面收益不等于收到现金。不能用全公司收入增长证明某一个项目的投资回报。

结果：重要长期资产和项目表、投入使用变化、资产价值线索，以及对利润、现金或披露模块的具体交接问题。

### 3.5 经营效率及其变化来源

在期间、范围和金额基础可比的情况下计算应收、存货、固定资产、流动资产及总资产周转。相关说明和具体判断随公司性质选择。

增加“每 100 元营业收入对应多少资产占用”的解释：先看总体，再定位应收、存货、固定资产、货币资金等变化。使用同一收入分母和互不重复的净额科目时，可以对占用变化进行加法分解，给出未覆盖科目的剩余项。

此方法描述会计关系和变化所在，不能自动证明商业因果，也不是现金循环天数。存货管理周转用成本分母；资产占用分解用收入分母，名称和计算分开，不能相加混用。

结果：可计算的效率指标、变化对照及占用变化来源。若上一期缺少更早期初数，本期可计算，上期不硬算成可比周转。

## 4. 数值与证据设计

### 4.1 模块自己的事实结构

模块内保留独立 `fact_id`，一条事实对应一个指标、期间/时点、范围和维度。事实含原科目名、规范名、日期、合并/母公司范围、总额/准备/净额等测量基础、币种、原值/原单位、规范化十进制字符串、重述身份、来源和可用状态。

公司/年度身份从正文核实；文件哈希仅确认原件身份。不同范围、账龄分类、净额口径或重述版本不自动合并。其他模块数据作为带来源的候选，出现差异保留两条来源并回查。

关键数值可以用多段证据分别支持科目、表头日期、单位和金额；每段记录 PDF 物理页、摘录及其作用。读取续表及相邻页，不要求本期和上期在同一条摘录出现。本模块不继承旧辅助函数中 360 字/三页以及数字共现的限制。

分开记录：页码是否有效、文字是否匹配、数值是否出现、表格行列及口径是否确认、程序是否完成计算、勾稽是否成立。数字出现或勾稽成立不能自动升级为财务事实已完全核实。

一个数字有问题，只限制依赖它的计算或判断；其余有效内容保留。候选数值可显示为待核，不能无标识进入正式计算。勾稽容差根据披露精度和单位决定，保存差额和容差，不设置跨单位通用固定金额。

### 4.2 首批计算规则

程序使用 `Decimal`，金额规范化为元；比例传比值，显示时转百分比。下表是拟定规则，由公式案例及真实年报核对后固化为模块版本。

| 计算 | 公式/基础 | 必要限制 |
| --- | --- | --- |
| 资产占比 | 同时点科目净额 / 总资产 | 同范围、币种；父子科目不重复加总 |
| 增减与增长率 | 期末减期初；可比且期初为正时再除期初 | 期初为零、负数或不可比时保留差额和原因 |
| 总额—准备—净额 | 总额 − 对应准备 = 净额 | 附注确认同科目、时点和分类；不将准备余额等同本期减值损失 |
| 准备率 | 同时点准备 / 总额 | 显式说明科目与分类；不能只看比例断言计提充分 |
| 账龄/存货分类占比 | 分类余额 / 同基础合计 | 总额/净额和桶边界一致；披露不全则说明覆盖范围 |
| 两端平均余额 | (明确期初 + 期末) / 2 | 两端平均近似；季节性和合并范围变化可影响可解释性 |
| 应收账款周转次数 | 营业收入 / 平均应收账款总额 | 优先总额；只能得到净额时另命名净额近似口径；使用收入替代赊销额时明示近似 |
| 存货周转次数 | 营业成本 / 平均存货净额 | 净额默认口径、明确减值影响；总额补充口径独立列示 |
| 固定/流动/总资产周转 | 营业收入 / 对应平均资产余额 | 固定资产用明确净额；租赁、折旧与业务模式影响解释 |
| 周转天数 | 365 / 对应周转次数 | 初版采用固定 365 日约定并注明；不是实际逐笔回收时间；原披露 360 日指标单列，不静默互比 |
| 每百元收入资产占用 | 100 × 对应平均净额资产 / 营业收入 | 分解用统一收入分母和互不重叠科目；无法平均时可单列期末占用近似，不能和平均口径混比 |

资产占用变化分解只有两期都具有相同口径的平均资产及收入时才比较；缺更早期初余额时可给本期占用构成，或明示的两期期末近似构成。占比变动用百分点，金额增长用百分比，独立记录。

减值准备滚动及在建工程滚动，按年报真实字段和符号建立勾稽，保留核销、转回、转销、汇率、处置或其他变动；不能仅以期末减期初声称得到当期计提额或投资支出。

适用数据齐全时应执行已有公式并展示结果。缺项时说明所缺数字、搜索情况及影响，不留一个没有解释的空图表。模型可提出新指标；简单有明确口径的计算通过模块十进制工具执行并留痕，尚未核准的复杂新公式标为待复核，不让模型生成代码后任意执行。

## 5. DeepSeek 怎样真正执行专业方法

### 5.1 总体流程和自主空间

建议流程：建立资产地图与身份 → 选择并深入专题 → 调用程序计算 → 结合证据解释与补查 → 复核并整理结果。它是默认组织方式，模型可以在专题中反复检索、调整假设和重新计算。

先完成应收、存货、主要长期资产和整体结构的基本检查，再按重要性深入。普通企业没有某类资产时说明不适用；没有找到披露不能直接写成“没有问题”。不设固定发现数量、统一标题或每个专题必须给同数量替代解释。

每次模型请求重新装配本轮专业指导、报告身份、工具说明、已核对事实、必要原文、程序计算结果、未解决问题和当前阶段目标。可保留本模块工具消息历史；跨阶段由程序明确传递状态，不假设独立 API 请求自动记住此前内容。

### 5.2 模块工具

- 原文：使用 `context.search_pages()`、`context.read_page()`，自主补读附注、表头、相邻页；短搜索摘录仅作定位，不作为完整表格。
- 资产候选页：在本模块实现科目/章节候选索引及资产专用初筛。`context.initial_pages` 只是参考，不依赖基底的通用概览选页覆盖资产。
- 事实与证据：模块内登记、查看和修订候选，记录修改原因。所有实际读取页进入运行记录。
- 专业计算：金额/单位核对、结构变化、两端平均、周转、准备与净额、项目滚动及占用变化；通过 `context.record_calculation()` 记录输入事实、公式版本、结果/失败原因。
- 模型：使用 `context.call_model()`；自己组织提示词、工具循环和结果，不从模块一专业实现导入分析逻辑。
- 过程：工具调用用 `context.record_tool()`，阶段用 `context.progress()`，关键事实与专题中间态用 `context.save_artifact()`，形成可回查记录。

基底的 `record_calculation()` 只保存记录，不负责自动核对财务口径或执行全部公式。本模块负责计算实现及其适用性。共享搜索的 `limit` 在传入自定义搜索回调时未保证生效，本模块按需求处理候选，不依靠放大参数解决召回。

运行预算、单次请求超时和输出长度可配置；关键中间态及时保存。部分事实缺失时尽量交付有效分析。模型/网络失败时使用安全错误与明确失败阶段，不把网络正常当作 API 必然可用。基底尚无通用阶段续跑，本模块不承诺已有自动恢复能力。

## 6. 返回什么，以及用户怎样看到

### 6.1 接入外层

`run(context)` 返回可序列化工作流：`result` 为完整专业结果，`read_pages` 为实际读取页，`trace` 可选。报告/模块身份、版本、执行状态等沿用现有独立运行封装。

共同独立入口将正常返回标为 `completed`，含义是执行完成。模块在自身结果中另外记录分析完整程度和具体缺口，不能将完成状态展示为财务结论全部验证。未知字段、长解释和新增专题完整保存。

### 6.2 本模块专业内容

建议分组为资产结构、应收专题、存货专题、长期资产专题、效率与占用、进一步发现；用事实/证据索引和计算结果关联具体数字。字段和专题可扩展，允许有实质内容的新段落、表格和图形数据，不要求所有公司都填同样长度。

每个重要判断应能区分：报告披露事实、管理层解释、程序计算、模型推断和未解决问题。应收回款改善、存货滞销、项目效益等强判断需要对应证据；不能用“同页有数字”充当因果证明。

### 6.3 给任务 08 的明确展示要求

| 用户阅读区域 | 首选展示 | 必须保留的细节 |
| --- | --- | --- |
| 本模块主要发现 | 简明结论及可展开专题 | 发现依据、具体影响、限制和追查结论 |
| 资产占用 | 两期结构/变化表，可选构成图 | 日期、单位、范围、剩余项和来源 |

## 8. 验证素材与完善方式

本模块的学习与改进是：教材方法 → 原始年报关键事实参考 → 产品内 DeepSeek 真运行 → 分析错误类型 → 改专业指导/工具/计算 → 换企业再核验。本轮不做模型参数微调，也不把开发助手的分析当作产品输出。

### 8.1 真报告素材

首先使用共同清单中伊利 2024 年报做完整闭环，以宁德时代 2024 年报检查迁移。样本位于 `金融AI智能体/data/raw/`，使用前核对共同清单 SHA-256。不能预先规定某家公司必然有某种风险或一定出现某类发现。

从每份报告建立关键事实参考表，记录主表/附注物理页、表头单位和日期、主要资产、应收总额/准备/净额、存货分类、重要长期资产、收入成本、适用公式及关键解释。参考表保存可验证数值和判定边界，不强迫模型使用唯一叙述。完整四公司集成验证由总控组织。

素材是用户真实上传年报的使用场景。定向选择不同资产结构、分类变化、减值披露、项目变化及资料缺项等情况；场景是否存在以原报告为准，必要时登记新增真实报告。

### 8.2 实施时的边界核验

- 本期/上期/更早期初混淆，只有期末数却误算平均余额。
- 合并/母公司、元/万元、调整前/后、总额/净额混用。
- 减值或核销使应收净额下降，却被解释成收到现金。
- 存货总额稳定，但分类显著变化；产成品增加被无依据判为滞销。
- 账龄不等于逾期；账龄桶改变；分类成本未披露。
- 跨页表头/单位/续表，数字出现但行列错误；出处缺陷仅影响有关事项。
- 长期资产净额变化不等于资本开支；项目预算比例不等于投产进度。
- 零基数、负数、占用分解科目重叠、部分科目不全及四舍五入差额。
- 无前序模块、模型格式失败或预算耗尽时，保留已有证据和具体限制。

合成数值只用于公式和程序边界核验，明确标注；专业解释和演示以真实年报及产品实际调用结果为准。本次制定方案不运行这些测试。

## 9. 分段实施，不按天数承诺

### 第一步：确认教材方法、关键事实和入口

产出首批方法卡、公式/口径表、两份样本的关键事实参考，以及可独立调用的 assets 最小入口。先把整体资产结构和一个应收专题跑通，形成可保存的模型输出。

### 第二步：建立结构与回收分析

实现资产地图、多段证据、应收总额/准备/净额与账龄分析，重要其他占用专题；打通相关程序计算和补查循环。复核净额下降与回款不能混淆的真实案例或明确边界案例。

### 第三步：补齐存货、长期资产与效率解释

加入分类/准备变化、主要长期资产项目、适用周转指标及统一收入分母的资产占用变化。用真实报告选择专题，不把所有方向变成必须输出长段落的填空题。

### 第四步：用真运行完善专业流程

伊利完整运行、宁德时代迁移；逐项回查关键数字、计算和主要解释。区分未披露、检索未找到、定位待核、计算不适用、模型调用失败，按实际问题修改。

### 第五步：提交并接入展示

保存模块提交、方法版本、报告身份、运行路径、核对记录、已知限制；向 00/07 交入口和注册需求，向 08 交真实样例和内容映射。正式界面与导出对照真实结果核查；遗留问题按责任修正后登记集成完成。

## 10. 完成标准

1. assets 入口独立可运行，专业分析由嵌入的 DeepSeek 完成，模块一、二缺失不阻断本模块。

3. 数据具备期间、范围、单位、净额/总额和证据身份；适用核心计算实际完成，不用期末余额假装平均；数值核对与推断可靠性分开。
4. 至少一份完整真运行与另一企业迁移记录，关键数字和公式经核对；不能仅以 API 成功证明财务分析正确。

本模块的特色是从整体占用追到科目内部结构，分清账面变化与真实回收，再解释经营效率发生变化的具体位置。项目竞争力最终还需要真实样例证明，不能以提示词长度、指标数量或图表数量代替。
