# DeepSeek 嵌入方案：财报分析与研报核查工作台

日期：2026-09-28。本文规定完整产品的模型调用与核验方案。阶段一已经接通单次 DeepSeek 调用代码并完成基础页面；由于本机尚未配置 API Key，真实 API 请求和财报样例验收仍待完成。多轮取证、精确计算和研报核查尚未实现。

## 1. 成品如何使用 AI

成品在用户发起任务时由后端调用 DeepSeek API。DeepSeek 负责理解财报表格、提出取证需求、解释财务变化、抽取研报中的可核查说法、判断证据能否支持说法并撰写结果。代码只负责接收 PDF、按页读取或渲染原件、提供检索与计算工具、记录版本和展示结果；不运行本地金融模型，也不在代码里写死财务分析结论。人的任务是制定支持范围与核对评测答案，不参与每次实际运行。

把分析流程写成**产品自己的指令与工具清单**，可以称为产品的 skill：先阅读材料身份与时点，再抽取说法、按需查看原文、核算数字、形成带出处的结论，缺证时标记待复核。指令文件本身不会替模型读文件或执行工具；小程序负责把这些能力交给 DeepSeek 并执行它提出的工具调用。

不能把开发者在聊天中写好的分析结论当作系统输出；演示时应让模型根据当次选定的原始材料实时生成分析，并在界面显示本次调用的证据与状态。

## 2. 从 PDF 到结果的完整流程

```mermaid
flowchart LR
  A[用户上传财报 PDF + 研报 PDF] --> B[程序按页提取文字或渲染图片]
  B --> C[带页码的材料读取工具]
  C <--> D[DeepSeek + 产品分析流程：理解、取证、分析、核查]
  D --> E[程序：重算数字、核对引用、检查材料时点]
  E -->|需补证| D
  E --> F[分析及核查结果：结论 + 双方页码 + 不确定项]
  F --> G[网页工作台与导出]
```

1. **接收与转换**：用户上传 PDF。PyMuPDF 只做机械工作：读取带页码的文字、截取或渲染页面图片。它不是本地 AI，不负责理解财务表格。公司、报告期和披露日期可先由 DeepSeek 从封面识别，再由程序记录并复核；每份原件保留 SHA-256 和版本身份。
2. **材料读取**：程序按页提供文字或图片，让 DeepSeek 决定重点阅读哪些页。文本可用于检索和引用；密集表格读不清时把相关页图片交给视觉模型再判断。发给模型的材料保留文档 ID 和 PDF 页码。
3. **模型推理**：DeepSeek 读取候选证据，决定是否要继续查找；识别“事实、公司解释、分析师预测/判断”的界线；形成带证据 ID 的结构化结果。
4. **程序核验**：用 Decimal 重算同比、单位换算与舍入，核对证据 ID 和原文是否真实存在；版本选择按研报发表时点约束，不能用未来的更正公告证明过去的说法。证据不足时保留“待复核”。
5. **呈现**：财报分析给出关键变化及有依据的解释；研报核查逐条列出原句、判断、年报证据、计算过程及修改建议。点击证据定位到 PDF 页。

代码的核验步骤是给模型结果加可审查的边界，并不预先写死分析结论。模型仍是分析与核查的核心推理引擎。

## 3. DeepSeek API 接入

- 先采用官方 OpenAI 兼容的 `https://api.deepseek.com/chat/completions`。开发期先用 `deepseek-flash` 跑通全链路，之后在同一评测集上比较 `deepseek-v4-pro` 的分析质量、耗时与实际用量，决定正式演示配置。模型名、调用参数和提示版本写入每次运行记录。
- 后端从本机 `.env` 读取 `DEEPSEEK_API_KEY`；首次打开网页时由配置弹窗接收密钥并交给本机后端保存，密钥不存入浏览器缓存、代码、日志或 GitHub。没有密钥时显示配置窗口，不展示伪造的分析结果。
- 初版用有限轮次的工具调用，例如 `search_evidence(query, document_scope)`、`read_evidence(evidence_id)`、`calculate(metric, period_a, period_b)`。程序校验模型传来的参数后执行，再把工具结果交回 DeepSeek。工具调用不是模型直接读本机文件或执行任意代码。
- 要求模型返回 JSON 对象，程序再按我们定义的字段和状态进行校验；API 的 JSON 模式只保证语法有效，不保证事实正确或字段齐全。工具调用与最终结果都要在本地验证。
- DeepSeek **网页聊天产品**有文件上传；截至 2026-09-28，公开的 **API Files 接口**支持 JPEG、PNG、GIF 和 WebP 图片，没有列出 PDF 格式，不能把网页功能当作 API 的 PDF 直传能力。阶段一按页抽取文字后交给 DeepSeek；后续遇到扫描版或复杂表格，可把选定页面渲染为图片交给具备视觉能力的模型。这里不使用本地金融模型。如果官方 API 后续支持 PDF 直传，可替换输入层而保留产品分析流程和工具。
- 记录任务 ID、文档指纹、模型版本、输入证据 ID、工具请求和返回、最终结果、耗时与用量。对外展示必要的证据与计算依据，不依赖展示模型内部思考文本。

官方依据：[首次 API 调用](https://api-docs.deepseek.com/guides/harness)、[Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)、[工具调用](https://api-docs.deepseek.com/guides/tool_calls/)、[Files API](https://api-docs.deepseek.com/guides/files_api/)、[视觉输入](https://api-docs.deepseek.com/guides/vision/)。接口和模型名以实际开发时的官方文档为准。

## 4. 第一条真实运行样例

输入：宁德时代 2024 年年报和国信证券《2024 年年报点评》原始 PDF。用户点击“分析并核查”。

预期系统行为：DeepSeek 从研报抽取若干可核查的数值及解释；按需请求年报页；对营业收入、归母净利润等作事实核对；解释“收入下降、利润增长”所对应的事实和公司披露说明；把分析师预测与历史事实分开；给出带双方页码的核查结果。系统不得因为只核对了几条数字就声称整份研报正确。

第二条样例：隆基绿能 2024 年原年报与 2025-05-03 民生证券点评。2025-05-06 的年报修订版属于后续材料；核查这份研报时必须使用截至发表日可获得的版本。该样例检验版本时点、亏损和同比口径。

## 5. 按实际成品验收

- 断开开发者聊天窗口后，系统仍能通过自己的 DeepSeek API 配置运行并生成新结果。
- 同一界面展示原 PDF、模型分析、所用证据、程序计算和待复核项；不存在由人预写好的“标准答案”替代实时运行。
- 用相同模型和相同材料做一组“直接把内容交给 DeepSeek”对照，统计本系统在页码追溯、数值/单位、版本时点、误报和漏报上的表现。成绩只对已人工核对的样例负责。
- API 调用失败、缺少密钥或材料不足时显示原因；已保存的演示回放应明确标记为历史运行，不冒充当次实时调用。
