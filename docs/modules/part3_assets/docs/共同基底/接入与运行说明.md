# V3.0.1 共同基底：接入与运行说明

## 这层底座负责什么

共同基底只处理模块都会需要、且能帮助复核的一小组事情：识别本次报告、提供全文页和模块初筛页、按需读取/检索原文、调用模型、登记工具和程序计算、记录进度与结果。

模块自己的分析步骤、提示词、专题计算、判断标准、输出字段和页面内容仍由模块自己决定。模块可以使用上下文提供的工具，也可以保留自己的处理方式；注册入口只要求能接收 `ReportContext` 并返回当前模块的工作流结果。

## 代码入口

| 位置 | 用途 |
| --- | --- |
| `backend/core/context.py` | 一次报告分析的上下文，以及原文、模型、记录、计算和进度工具 |
| `backend/core/recorder.py` | 追加式事件记录、输入/输出材料、计算记录和结构化结果保存 |
| `backend/core/model_io.py` | DeepSeek 客户端创建及实际请求、响应记录；不会把认证头或 API Key 写入运行记录 |
| `backend/core/config.py` | 本版本 `.env` 的读取位置 |
| `backend/module_registry.py` | 真实可运行模块的登记表 |
| `backend/modules/<模块名>/entry.py` | 模块适配入口；在此保留专业流程并接入共同能力 |
| `backend/run_module.py` | 不依赖网页的单模块运行入口，供开发和集成时独立调用 |

## 模块收到的上下文

`ReportContext` 当前包含：

- `report_id`、`file_name`、`file_sha256`、`page_count`：本次输入报告的身份信息。
- `pages`：程序提取的全文页文字；`initial_pages`：调用方按模块类型初筛出的候选页。
- `recorder`：保存事件、原文/检索结果、模型请求响应、计算输入输出和模块完整结果。
- `read_page(page_number)`、`search_pages(query)`：按需读原文和搜索全文，并记录实际访问。
- `call_model(...)`：通过共享模型记录器调用 DeepSeek。
- `record_tool(...)`、`record_calculation(...)`、`progress(...)`、`tool_activity(...)`、`save_artifact(...)`：模块可选使用的记录和进度工具。
- `related_results`：前序模块愿意交给后续模块的结果线索。模块自行决定是否读取、怎样解释和核实。

不要求所有模块都使用所有字段。某个模块需要更适合自己的内部流程或数据结构时，可以放在自己的模块目录里；共同基底不会把它改写成统一分析步骤。

## 注册方式

在 `backend/modules/<模块名>/entry.py` 提供模块 ID、模块版本和 `run(context)`，再在 `backend/module_registry.py` 登记。入口返回现有工作流字典即可，至少应能让调用方取得模块结果；若已有 `trace` 和 `read_pages`，也一并返回。模块结果内部不要求与其他模块同构。

当前实际登记的两个入口：

- `business`：模块一“业务与经营背景”。
- `profit`：模块二“盈利来源与变化”。

网页单独运行模块一/模块二和“完整财报分析”均通过注册表调用这两个入口。完整分析把模块一结果放入模块二的 `related_results`；模块二仍须回到年报核实自己的事实。旧的通用概览入口作为兼容流程保留，当前不算作已注册的专业模块。

## 在命令行单独运行

在 V3.0.1 项目目录打开 PowerShell：

```powershell
$Python = '..\金融AI智能体\.venv\Scripts\python.exe'
& $Python -m backend.run_module --module business --pdf '..\金融AI智能体\data\raw\600887_伊利股份_2024年年度报告.pdf' --config '.env'
```

模块二把 `--module business` 改成 `--module profit`。运行后终端只显示任务 ID、状态和记录目录；完整模型输入输出保存在本机运行目录，不打印 API Key。

参数：

- `--module`：注册表中已有真实入口的模块 ID。
- `--pdf`：年报 PDF 路径。
- `--output`：记录目录，默认 `data/开发运行`。
- `--config`：本机配置文件路径，默认项目根目录 `.env`。

只复制提示词或空注册项还不能算模块已接入；必须能从该入口跑到它的真实分析实现并返回模块结果。

## 网页运行

运行 `启动V3.0.1.ps1` 或双击 `打开V3.0.1工作台.cmd`。本版使用本地端口 `8007`，API 版本为 `3.0.1`，本机 Key 从本目录 `.env` 读取。启动脚本在本目录准备前端依赖并构建网页；没有可用本地 Python 环境时会复用同级的 `金融AI智能体` 依赖环境。

## 一次运行保存什么

网页任务的运行记录位于：

```text
data/app/run_records/<run_id>/
├─ events.jsonl
├─ manifest.json
├─ result.json
├─ artifacts/
├─ business/attempt-0001/
├─ profit/attempt-0001/
└─ turns/<turn_id>/
```

实际目录只包含这次任务涉及的子目录。根记录包含报告身份和完整结果；模块尝试目录单独包含模块版本、事件、模型请求与响应、工具输入输出、计算输入输出、原文页和模块结果。`sha256` 可用于校验材料是否被替换。失败调用也会留下事件和错误类型。

PDF、可提取页面文字、模型请求响应、API Key 和 SQLite 任务数据不会提交到 Git。页面文字会按照产品流程发往 DeepSeek；它在本机的运行记录中用于复核。本地运行目录已加入 `.gitignore`。

## 当前边界

共同基底解决模块接入、模型与工具调用记录、计算记录和运行结果保存；它不证明模型结论正确，也不替代人工标准答案评测。当前只登记模块一和模块二；其他专业模块完成后再各自接入，不预先伪造“已可运行”的入口。
