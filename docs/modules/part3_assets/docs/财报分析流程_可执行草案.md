# 财报分析流程：从年报到可核查的发现

状态：产品设计草案。依据上交所《读懂上市公司定期报告》和肖星《一本书读懂财报》的阅读方法整理；具体指标口径、判断条件仍需用原始年报和指导老师复核。这里规定程序该怎样分析，不把教材或年报原文整本放入提示词。

## 一、最终交付什么

用户上传一份年度报告后，产品应交付一份「财报诊断页」，而不是对三张报表逐章复述：

1. **公司靠什么赚钱**：主要业务及收入结构；只写年报明确披露的产品、地区或业务板块。无法拆分时写明。
2. **本年最值得注意的 3—5 个发现**：每个发现依次给出观察到的变化、对照数据、可能解释、已经核对的证据、尚未证实的部分和下一步该看什么。
3. **利润、资产、现金的勾稽图**：把盈利变化与应收、存货、投资、负债和现金变化连起来。连不起来时展示缺口，不编造原因。
4. **数据与证据表**：数值都能回到年报的具体页、表、期间、单位和口径；计算过程可以展开查看。
5. **明确的局限**：缺少往年报告、附注、同行资料或管理层解释时，说明因此无法判断什么；不自动给出买卖建议或造假结论。

一张「发现卡」的固定字段：`问题/一句话发现 → 本期与上期事实 → 程序计算 → 公司原文解释 → 模型推断及替代解释 → 反证/缺口 → 判断状态 → 证据页码`。事实、计算、公司说法、模型推断在界面上使用不同标记。

## 二、第一遍：统一底表，先弄清数字

DeepSeek 负责定位并解释；程序保存和校验抽取结果。每个数值记录：年报文件及版本、披露日期、PDF 页码、表名、报表期间、合并/母公司、元/万元/亿元、原文片段、原始数值。优先取合并报表；不同口径绝不直接相除。

| 数据组 | 至少取得的数据 | 为什么要取 |
| --- | --- | --- |
| 业务 | 主营业务描述、分业务收入/毛利率（如披露） | 确定收入和利润来自哪里 |
| 利润 | 营收、营业成本、毛利、期间费用、减值、投资收益、归母净利润、扣非归母净利润 | 区分销售增长、毛利变化、费用变化和一次性因素 |
| 资产与负债 | 应收账款、合同资产、存货、应付账款、货币资金、有息债务、固定资产/在建工程 | 看利润和增长占用了多少资金，偿债压力在何处 |
| 现金 | 经营现金流净额、销售商品收到的现金、投资现金流、购建长期资产支付的现金、筹资现金流 | 判断盈利是否转化为现金，扩张资金从哪里来 |
| 说明 | 审计意见、管理层讨论、重要附注、非经常性损益、重大变化解释 | 给异常寻找解释与限制 |

至少比较本年与上年；若同一份年报有两年比较列可以先开始，若要判断趋势则取得更早年度。查不到的数据保留「未披露/未找到」，不能填零。程序计算同比、毛利率、费用率、经营现金流/归母净利润等，遇到亏损、零基数、报告口径变化时改用绝对变化和文字说明。

## 三、第二遍：用问题触发追查，而非平均写五章

下面的“触发”只表示值得查，不代表已经判定好坏；同时记录未触发或缺数据的原因。不存在一条适合所有行业的统一警戒百分比。

| 观察到什么 | 随后必须查什么 | 有证据后能交付什么；证据不足时怎么写 |
| --- | --- | --- |
| 收入增长，归母利润没有同步增长；或利润增长远快于收入 | 分业务收入与毛利率、营业成本、销售/管理/研发/财务费用、资产减值、投资收益、所得税、少数股东损益 | 用可核对项目说明利润变化的主要贡献；解释不了的部分明确列成缺口 |
| 归母利润增长，扣非归母利润没有同步增长 | 非经常性损益表、政府补助、资产处置、投资收益及其持续性说明 | 指出增长有多少来自已披露的一次性项目；不能把“扣非”直接等同真实利润 |
| 利润增长，经营现金流下降或持续显著低于利润 | 销售收现、应收账款与合同资产、存货、应付账款、经营现金流补充资料和管理层说明 | 说明现金转化是否变弱、哪些营运资金项目可能造成差异；无附注支持时只提出待核查原因 |
| 应收、合同资产或存货增长快于相关业务收入 | 账龄、坏账准备、存货跌价、客户集中度、信用政策、预收/合同负债、相关业务变化 | 区分业务扩张、结算周期变化和潜在回收/跌价压力；不能凭增长率判定坏账或虚假收入 |
| 固定资产、在建工程和资本开支明显上升 | 项目进度、产能/利用率（如披露）、投资现金支出、借款、后续折旧 | 解释扩张投入、资金来源及未来需要验证的回报，不预测必然成功或失败 |
| 货币资金、短期有息债务和经营现金流出现紧张组合 | 受限资金、债务到期表、授信、筹资现金流、重大承诺 | 描述短期资金压力的证据与未知项；账上有现金也要核对是否可用 |
| 非标准审计意见、会计更正、合并范围/会计政策重大变化 | 审计意见正文、更正公告、调整前后口径与披露时点 | 将受影响指标标记为需人工复核；避免把两个版本直接做同比 |

选出最有证据且影响最大的 3—5 个发现。对关键差异至少写两种可能解释，再用附注、管理层讨论、现金流和历史记录逐一核对；无法排除的解释保持开放。同行比较只在取得同行同口径原始资料后进行。

## 四、用一组假设数据检验流程

以下数字完全虚构，只用于说明产品应该给出什么结论：某公司营收从 100 亿到 120 亿，归母净利润从 10 亿到 14 亿，经营现金流从 12 亿到 5 亿，应收账款从 15 亿到 27 亿。

程序算出：营收增长 20%，归母净利润增长 40%，经营现金流下降约 58%，应收账款增长 80%；经营现金流/归母净利润从 1.2 降至约 0.36。于是触发「利润与现金背离」和「应收增长快于营收」两条追查路径。

**合格的发现卡**：本期盈利增长，但现金流入没有同步增长，且应收账款增加较快，利润的现金实现程度下降。下一步应核对销售收现、应收账款账龄、坏账准备、信用政策变化、合同资产与存货，以及管理层对现金流变化的解释。当前数字只能支持“需要追查回款与营运资金”，尚不能证明坏账、收入虚增或未来必然亏损。真实报告中每个数字必须附来源页，若查到附注能解释变化，再把已证实的原因补入卡片。

**不合格的输出**：“业绩很好”“现金流不好”“可能财务造假”或一长段三张报表定义。这些话没有追查过程，也不能指导用户下一步。

## 五、把教材变成产品能力的顺序

1. 从教材每次只抽一个可执行问题，例如“利润增加为什么没有带来现金”；写成「需要的指标、到年报哪里找、怎样计算、可能有哪些原因、不能下什么结论」知识卡，并标注教材章节。教材用于确定分析问题，年报用于核实公司事实。
2. 用一份真实年报手工完成该问题的发现卡，保留每个数据出处和人工不确定处；请组员/指导老师复核。这是产品输出的参照样例，不把模型自己生成的答案当标准答案。
3. 将这一张知识卡变成程序流程：抽取底表 → 程序复算 → 判断是否触发 → DeepSeek 带着指定问题查年报附注/管理层讨论 → 再核对引用 → 输出发现卡。
4. 在另一份未用于设计的年报上检查：数据和页码是否真实、口径是否一致、结论是否被证据支持、重要的相反证据是否遗漏、证据不足时是否会停下。把失败例子回填知识卡，再扩展下一条问题。

**第一个最小闭环**就做「盈利增长是否变成现金」：底表只需收入、归母利润、经营现金流、应收/合同资产、存货、销售收现和必要附注。让它在一份年报上输出一张可信的发现卡，再做利润来源、扩张投入、偿债和行业差异。这样每扩展一项，用户能多回答一个实际问题。

## 六、程序与 DeepSeek 各做什么

- **程序**：保存 PDF 与版本、拆页和定位原文、保存用户分析记录、统一单位和期间、做确定性计算、校验引用页与原文是否匹配、展示发现卡与证据。必要时人工更正抽取结果并保留修改记录。
- **DeepSeek**：按当前知识卡提出查找问题，识别年报中的解释，提出相互竞争的原因，写成用户能懂的发现。每次调用都传入该步骤的任务、已核实的底表和相关年报片段；不能假设模型记得上一次请求。
- **人**：审阅有争议的财务口径、行业例外、重大风险措辞；对用户可见的结论保留“已核实 / 有依据的推断 / 证据不足”状态。

这份草案只定义分析流程；正式实现前，先用真实年报和团队复核样例定下第一批字段、触发条件与界面文案。
