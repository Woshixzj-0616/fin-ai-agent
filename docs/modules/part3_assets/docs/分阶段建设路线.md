# 从草本到参赛成品：分阶段建设路线

本路线按**能力递进**组织，不按天数排期。每一阶段结束都应有一个能打开、能操作、能展示真实 DeepSeek 结果的版本。阶段一代码已接通，配置 API Key 并完成人工样例验收后，才算通过阶段一。后续阶段在前一阶段的可运行成果上增加功能，不另起一个孤立项目。

## 始终不变的产品主线

用户上传财报 PDF，选择分析任务；需要核查时再上传研报 PDF。程序管理文件、会话、工具和页面，DeepSeek 负责理解、分析及判断。结果始终围绕“说了什么、依据在哪一页、哪里仍不确定”呈现。

系统从第一版起统一保存四类基础对象：**原始文档**（文件与版本）、**任务运行**（模型调用和状态）、**证据**（文档及页码）、**结果**（结构化分析与核查项）。后续功能都接在这些对象上，避免每加一个页面就重写数据流。

## 阶段一：能跑的草本

具体实现见 [阶段一实施方案](阶段一_实施方案.md)。

**已实现**：一个本地网页可上传一份可提取文字的财报 PDF；程序按页读取并筛选候选页、随请求附上固定流程指令、调用 DeepSeek API，并保存任务状态；页面显示概览、所用页码和运行错误。原 PDF 保存在本机，所选页面文字会发送给模型。API Key 只配置在后端的本机 `.env` 文件。

**用户能看到**：上传 → 点击“分析” → 页面出现针对这份 PDF 的回答。界面先保证清楚、可靠，容许只有一个页面和少量样式。

**剩余验收**：配置 API Key 后，用至少两份不同公司的财报完成真实请求；核对报告身份、指标、引用页码和错误反馈。当前代码尚未用真实 Key 发起 API 请求，因此整条链路还不能记为验收通过。

## 阶段二：可连续工作的财报助手

**要做**：把产品工作流程写成版本化指令，让 DeepSeek 分步识别材料、提取关键财务事实、分析变化并说明依据。程序保存任务状态，每次 API 调用重组固定流程、文档范围、已取得事实和必要历史消息；提供按页查看原文和精确计算工具。模型输出从一大段文字变为有固定字段的数据。

**用户能看到**：材料确认、步骤进度、四项核心指标的卡片、简明分析和出处页码；刷新后能继续看这次运行。可针对本次材料追问。

**过关条件**：一次多轮任务能完成，下一次调用能接上同一任务的事实与工具结果；指标、单位、期间和页码可查；证据不足时会说清楚。此阶段形成方向 1 与方向 2 的最小成品。

## 阶段三：加入研报核查

**要做**：允许同时上传财报和研报。DeepSeek 从研报中找出可以核查的说法，向程序请求财报证据，再逐条给出“一致、冲突、证据不足、超出范围”的判断。程序复核数字运算、文件身份和报告时点，保存每一条结论对应的研报页与财报页。

**用户能看到**：研报原句、核查结果、依据和修改建议组成的列表；可以筛选问题项，点开双方原文。宁德时代做首个完整样例，隆基绿能用于验证原年报与修订版的时点问题。

**过关条件**：上传此前未用于编写页面内容的真实研报，系统也能产生逐条核查结果；不能把未查过的段落宣称为正确。此阶段打通方向 1、2、5 的完整闭环。

## 阶段四：把原型做成好用的工作台

**要做**：在已有闭环上改善上传引导、材料确认、进度反馈、错误恢复、页面层次、PDF 并排阅读和结果导出。财务数据、分析、研报核查分成清晰的视图；保留历史任务与追问入口。长内容按摘要、卡片、图表、可展开细节逐层呈现。

**用户能看到**：第一次使用也知道该上传什么、当前在做什么、哪些结论可信、如何回看出处；可把结果导出供讨论或提交。界面风格与交互在每个前置阶段逐步改善，这一阶段集中打磨完整体验。

**过关条件**：不了解内部代码的队友能够独立完成上传、运行、检查证据、追问和导出；出现失败也知道怎样继续。

## 阶段五：从“能演示”到“有竞争力”

**要做**：用现有多家公司年报和七份券商研报扩充样例；建立人工核对答案，按数字、口径、期间、版本、引用分别统计正确、误报、漏报和待复核。让同一模型直接分析同一材料，作为对照；根据失败案例调整流程指令、工具、检索和界面。记录耗时与 API 用量。

**用户能看到**：系统在不同公司材料上的稳定表现，哪些类型能处理、哪些需要人工判断。项目展示有真实运行记录和可复核的数据，而非挑选一次成功输出。

**过关条件**：能力边界、效果提升和典型失败有证据支持；新材料进入系统时不会依赖某一家公司的硬编码结论。

## 阶段六：封装最终作品

**要做**：整理安装与运行入口、模型密钥配置说明、示例材料、可复现运行记录、项目计划书、真实演示视频和源码。根据竞赛阶段要求交付对应文件。把功能范围、已知限制和第三方依赖写清楚。

**过关条件**：另一台符合环境要求的电脑按说明能启动程序、上传材料、触发 DeepSeek 并得到结果；展示视频能让评委看见真实操作、模型分析、证据回查及项目特色。

## 推进原则

- 每次只选一个能贯穿上传、模型调用、保存、页面展示的增量；先跑通再扩范围。
- 每增加一种能力，就同时增加相应的页面反馈与人工核对样例。
- DeepSeek 的流程指令和模型配置标版本；评测结果对应具体版本。
- 任何阶段都可以停下来展示已有成品；下一阶段的工作从实际失败和用户使用体验中确定优先级。
