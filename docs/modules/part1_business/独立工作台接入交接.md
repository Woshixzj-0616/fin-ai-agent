# 模块一独立工作台接入交接

## 运行入口

- 本地地址：`http://127.0.0.1:8101`
- 一键启动：项目根目录 `启动模块一工作台.cmd`
- PowerShell 启动：`启动模块一工作台.ps1`
- 模块显示版本：模块一独立工作台 V1.0
- DeepSeek 专业流程版本：每次结果仍显示 `prompt_version`；不与工作台外壳版本混为一谈。

启动脚本先构建本目录 `frontend/dist`，再将已有模块一运行记录接到本任务数据库，随后启动只监听 `127.0.0.1:8101` 的 FastAPI 服务并打开浏览器。端口被其他服务占用时不会杀进程或改连其他端口。

## 已接通的使用流程

1. 上传可提取文字的年报 PDF，前端固定提交 `analysis_module=business`。
2. 首次没有 Key 时弹出 DeepSeek 配置窗口；Key 保存到本任务根目录 `.env`。启动脚本把 `FINLAB_CONFIG_PATH` 固定到本目录，并清除子进程继承的 DeepSeek Key/模型环境变量，防止误读其他工作台配置。
3. 页面轮询当前任务，展示运行状态、分析覆盖和待复核状态。模型解释阶段中断时，既有模块流程会保留第一阶段已经抽取的事实；结果页能与失败/阶段状态同时显示已有结果。
4. 完成后逐项展示业务画像、经营链条、行业背景、战略与竞争、收入合计与分部、增长驱动、行业经营指标、依赖集中度、重大变化、风险、动态专题、未映射解释、覆盖状态、原文和后续核查问题。
5. 证据页码链接打开本工作台本地保存的 PDF；追问接口仍走模块一 `answer_business_question`，携带模块一专用问题提示词、当前模块结果、最近问答，并可检索/读取本任务保存的全文页。
6. 历史列表只显示本模块任务；失败记录、运行中记录与完成记录分别标记。

## 页面和状态边界

- 收入分组优先按 `table_id` 隔离；无 `table_id` 时以原表名、维度和现有口径作为保守分组键。同名业务行不会跨表合并。
- 展示原表名、拆分维度、标题文字匹配状态、总额来源、分项完整度、逐角色证据、计算证据和单位证据。标题文字匹配不会称为“整表已核验”。旧结果若没有保存合计来源，会显示“合计来源未记录，需复核”，不会猜成年报列示值。
- 收入分部表还展示本期/上期占比变化百分点；对程序推导的合计展示组成分项、页码和与年报合计的勾稽状态。若有 `revenue_metric_bridges`，单独显示同表不同收入口径、原单位、差额、证据状态和依据页；差额不被解释成具体会计构成。
- `topics[]` 按结果顺序逐项展示问题、观察、分析、替代解释、限制、交接事项和证据；不限定专题数。
- `interpretation_review_items[]` 总是有单独区域。字段缺失的旧历史结果显示“未保存该字段”，字段存在且为空才显示“本次没有待映射项”。
- 运行结束、分析完整性、资料不足、部分完成、失败和待复核分别显示。页面说明文字匹配或模型输出不等同于专业判断已证实；空值显示未披露，不当作 0。
- 页面会显示已有专业结果字段；空列表仍显示该节无结果/资料缺口，不从模型之外补造事实。
