## 先定目标

第一步要交付的不是一个塞满 PDF 的文件夹，而是一套**能追溯、能学习、能用来核验系统**的材料：

1. **原始财报库**：公司正式披露的年报及其更正记录。它是事实和数字的首要依据。
2. **分析案例库**：经过筛选的公开分析报告，以及我们对其分析方法、证据和局限的拆解。它帮助团队学习“如何分析”，不自动成为事实标准答案。
3. **金融知识卡**：从交易所投教资料、教材和规则中提炼的口径、公式、前提与例外，标明出处。它帮助团队定义规则。
4. **人工核验样本**：由团队对原始财报逐页核对出的字段和分析事实。这才是系统评测的参考答案；分析师结论不能直接充当答案。

优先做一个窄而可靠的样本闭环：**同一家公司的年报 → 关键数据 → 对应分析案例 → 团队复核记录 → 可用的分析与核查样题**。扩大下载量要服从这个闭环。

## 一、财报从哪里来，选哪些

### 来源与顺序

以 [巨潮资讯网公开信息](https://www.cninfo.com.cn/new/commonUrl?url=data%2Fgongkai) 为统一检索入口，并用 [上海证券交易所上市公司公告](https://www.sse.com.cn/disclosure/listedinfo/announcement/) 和 [深圳证券交易所信息披露](https://www.szse.cn/disclosure/) 交叉核对公告。优先留存上市公司正式披露的**年度报告全文**，不把摘要、第三方转载、新闻稿混入原始年报。每份文件记录来源页面、公告链接、披露日期和下载时间。

检索到“更正”“修订”“补充”时，**保留原版和后续版本**，建立它们的关系。系统默认分析哪个版本，必须由披露时间、公告性质和人工核对决定，并在结果中显示；不能简单拿最早一个 PDF，也不能默默覆盖原文件。某份分析报告若发表于更正之前，还要按其当时可获得的版本判断，避免用未来的信息倒查过去。

### 选样矩阵

首批只做**中国 A 股、非金融企业、中文年报、2023—2025 财年**。金融机构的报表和指标定义差异大，先列为后续压力样本。2025 财年年报的实际披露与可下载情况逐家公司核实。不要为凑数下载数百份相似公司报告。

| 维度 | 首批覆盖原则 | 为什么需要 |
| --- | --- | --- |
| 行业 | 消费、制造、医药/医疗、软件/科技、公用事业等至少 4 类 | 检查表格和经营叙述的差异 |
| 财务状态 | 增长、下滑、亏损、利润与经营现金流背离 | 给分析和核查提供不同问题 |
| 文档形态 | 不同交易所、版式、单位、跨页表；至少 1—2 组更正/重述 | 检查提取和版本识别能力 |
| 时间 | 每家公司尽可能连续 2—3 年 | 支持跨年对比，避免只看单年 |

**阶段数量**：先把现有 3 家、9 份年报作为开发材料；再选 9—12 家公司，共约 30—40 份年报形成可用第一批。若下载和核验稳定，再扩至约 20—30 家公司、60—90 份。上述数量不是比赛要求，也不是准确率目标；做不完时优先保住行业差异和人工核验深度。已用于开发的 3 家不得再当独立盲测样本。

### 下载与登记流程

1. 建公司清单：证券代码、简称、交易所、行业、选入原因、目标财年、是否开发/冻结评测样本。
2. 查询公告：按代码、财年、公告类型检索，保留全部候选结果；人工确认全文、摘要、更正、英文版及披露时间。
3. 下载原件：限速、失败重试、可续跑；保留原始文件名和公告 ID，不覆盖同年度其他版本。
4. 验文件：HTTP 状态、文件头是否为 PDF、大小、页数、能否解析文字、SHA-256；重复文件按哈希识别。扫描页或无法提字页单独标记。
5. 写总索引：一行一份**具体公告版本**，记录代码、财年、报告类型、标题、披露时间、公告 ID、来源 URL、版本关系、下载时间、本地路径、哈希、页数、解析状态、使用条件备注。索引随增量更新，不能因为重跑小批次而丢失旧记录。
6. 人工抽检：每家公司核对封面年度、审计报告、主要会计数据表、合并口径财务三表及更正公告。任何数字用于展示前都能指回原 PDF 页码。

**对当前脚本的改造点**：`scripts/data/fetch_reports.py` 目前写死 3 家公司，查询候选数有限，并排除了“更正”等标题后选最早公告。第一轮要改为清单驱动、候选分页/复核、版本并存、文件验证和断点续跑。现有 9 份 PDF 保留原样并补索引；不能假设现有抽取 CSV 的数字已经人工核对。

## 二、优秀分析案例怎么找、怎么学

“优秀”不能只看机构名或下载量。先从两条路径找：

- **中文 A 股案例**：证券公司或研究机构官网公开的年报点评、公司深度报告；优先与财报库的公司和财年配对。只记录合法公开可访问的原文链接、作者、机构、发布日期、覆盖的财年和免责声明。找不到机构官方原件时，将第三方镜像标记为“待核来源”，不直接收入正式案例库。
- **结构标杆**：[CFA Institute Research Challenge 历届优胜报告](https://www.cfainstitute.org/insights/events/research-challenge/past-champions) 的公开报告。用于学习论证结构、风险呈现和来源标注。它们是学生研究作品，部分为境外公司，不能直接套用到 A 股会计口径，也不能当作“专业判断必然正确”的证明。

第一批人工精选 **6—8 篇中文案例＋2—3 篇 CFA 案例**；如时间允许扩至约 12—20 篇。每篇按统一评分表筛选：公司与年报是否匹配、数字能否回溯、事实与判断是否区分、计算及假设是否写清、是否讨论反例/风险、发布日期是否明确、授权与可使用范围是否明确。案例不满足关键项就只作普通阅读材料。

每篇产出一张**案例拆解卡**，只摘录必要的短句并记录所在页：

| 栏位 | 记录内容 |
| --- | --- |
| 关键主张 | 如“收入增长但现金回款趋弱” |
| 主张类别 | 年报披露事实、计算结果、分析师推断、预测 |
| 依据 | 财报页码/附注、所用数据、公式和可复核计算 |
| 可取的方法 | 先对比什么、怎样解释、怎样表达不确定性 |
| 可能的错误 | 口径混用、旧版数字、跳过反例、因果推断过强 |
| 可变成的样题 | 正确表述、故意改错的草稿句子及其核查依据 |

案例库供团队学习和少量人工标注使用；公开可读不等于允许整库复制、再分发或拿来训练模型。资料的具体使用条件逐项记录，产品里只展示必要的引用和来源链接；授权不清晰的全文不进入交付包。

## 三、零基础团队的最短学习路径

**共同入门资料**：[上交所《读懂上市公司定期报告》问答手册](https://edu.sse.com.cn/attention/c/5699160.shtml)；它按概述、财务、非财务三个部分讲解 A 股定期报告。团队边读边打开同一家公司的年报，不脱离原文背概念。

**一本主教材**：张新民、王秀丽《[财务报表分析（第四版）](https://xuanshu.hep.com.cn/front/book/findBookDetails?bookId=5e73a5a4b0b2bda7c523c6e3)》（高等教育出版社），通过学校图书馆或正规渠道取得。只精读与本项目直接有关的财务三表、财务数据口径、现金流、分析方法和案例章节。英文能力允许时，参照 [CFA Institute 的财务报表分析导论](https://www.cfainstitute.org/insights/professional-learning/refresher-readings/2026/introduction-financial-statement-analysis) 理解报表、管理层讨论与审计意见的分工。教材和 CFA 资料是方法参考，不替代特定公司的正式披露。

**首批 20—30 张金融知识卡**，每张限定一个概念：定义、用途、计算方式、不能使用的条件、易混口径、例子、书/手册章节与页码、审核人。先覆盖营业收入、归母净利润、扣非归母净利润、经营现金流净额、同比、合并/母公司、单位、上期调整、非经常性损益、审计意见等。尚未核准的卡片标“待审核”，不能作为产品自动给出确定结论的依据。教材原文不大段复制进仓库或模型提示词。

**教学顺序**：先会找报表与页码 → 再会辨认单位、财年、合并口径 → 再做四个核心字段和同比 → 再读公司披露的原因 → 最后读分析师如何推断及其局限。团队成员不必先学完完整的金融课程再开始开发，但至少一位懂财务的人应复核高风险口径和案例卡；若尚未找到，就把这些结论标成待确认。

## 四、把材料变成系统可用的数据

四类内容分开存放并通过 ID 关联：

```text
原始年报 document_id → 公告版本、文件哈希、页码
人工标注 fact_id → document_id、页码、原文位置、指标、数值、单位、财年、口径、复核人
案例主张 claim_id → 案例来源、作者/日期、主张类型、对应 fact_id、核验状态
知识卡 rule_id → 概念/公式/适用条件、参考书或官方资料章节、审核状态
```

每条分析/核查结果只可引用已核实的事实、规则或明确标注的公司说法；展示时区分“公司披露”“程序计算”“分析师观点”“系统推断”。不支持的因果解释输出“依据不足”，不能为了像研报而编一个理由。

从第一批材料中手工做好 **3 家完整样例**：每家至少 2 个年度、四个核心字段、1 条公司披露原因、2—3 条分析结论、3—5 条真假混合核查句子。再选 **2 家未参与开发的公司**作为冻结评测候选；其参考答案单独保存，开发时不据此调规则。所有人工答案至少双人复核；有争议的指标留争议记录，不强行统一。

## 五、分工、时间和验收

| 时间 | 工作 | 可交付成果 |
| --- | --- | --- |
| 9/26—9/28 | 选公司矩阵，修下载与索引；对现有 9 份补充来源/版本检查 | 30—40 份目标清单、可续跑下载流程、有效 PDF 索引；未达数量要列缺口 |
| 9/29—10/1 | 人工精选配对分析案例，阅读投教手册和教材关键章节 | 首批 6—8 篇案例及拆解卡、首批 15 张知识卡 |
| 10/2—10/4 | 完成 3 家手工闭环样例，复核 2 家冻结样本；按问题决定是否扩库 | 人工核验字段、问题清单、知识卡约 20—30 张、盲测样本封存 |

三人团队建议：一人负责公告检索/下载及版本，一人负责案例筛选与知识卡，一人负责人工标注与交叉核验；三人都参与至少一家公司完整闭环，避免只有一人懂数据。若实际时间被开发挤占，优先完成有效来源、版本关系和 3 家闭环，延后单纯扩充篇数。

**第一步验收标准**：抽一份年报能说清来源与版本；抽一个数字能定位 PDF 原页并说明单位/口径；抽一条分析能分清事实与推断；抽一条错误研报句子能拿出对照证据。只做到“下载了很多 PDF”不算完成。
