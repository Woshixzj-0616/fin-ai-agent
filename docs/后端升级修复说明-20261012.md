## 二、逐项修复

### 1. 跨公司比较漏传方向；单项失败保留已完成分块

- [claim_check.py](../agent/audit/claim_check.py)：比较分支把已验证的 comparison_operator 传进 compare_companies，并把工具异常转成明确的「证据不足」检查行，不再让 TypeError 冲掉整次运行。
- [service.py](../agent/audit/service.py)：分块异常从只捕获 LLMError/ExecutionLimit 扩到业务边界；失败块写 error_type/reason 与未完成句，已完成块原样保留；text_checks.json、text_report.md 照常生成，运行状态为 partial，不把失败吞成成功；failed_chunks 汇总进结果包。
- [webui_pipeline.py](../agent/webui_pipeline.py)：核查中途抛错时读回本次运行已写出的 text_checks.json，页面层返回 failed 但保留已完成检查行。
- 复现探针：full_check_text_cross_company_failure 由「TypeError、最终产物未写出」变为「partial、1 块完成 1 块失败、最终产物已写出」。

### 2. 公司错配：句内明确主体优先，公司与期间保留定位依据

- [grounding.py](../agent/audit/grounding.py)：新增 resolve_subject / resolve_period / explicit_companies。绑定顺序为「句内实体 → 引文上下文 → 段落主体 → 最近可定位上文 → 整篇草稿 → 模型补全」；句内已明确另一主体时，模型字段与前文继承都不能覆盖它，并对模型字段冲突留下标记。短别名（茅台、招行、美的等）可能与普通词同形，只有模型字段与之一致时才作为句内依据。年度继承只在「段落或最近上文唯一一个年度」时生效，相对日期仍然不猜。
- 检查行新增 grounding（公司/期间的绑定路径、命中的原文、冲突标记），定位依据可复核。
- 复现探针：company_name_from_other_paragraph 由「用茅台证据判证据支持」变为「绑定句内五粮液（000858）、model_company_conflict=true、只用 wly 证据」。

### 3. 工具贯通报告类型、精确期间与材料 ID；正文按材料身份索引

- [evidence.py](../agent/audit/tools/evidence.py)：find_evidence 增加可选 report_kind、period_start、period_end、document_id；命中多候选仍返回 ambiguous，指定精确条件后没有候选明确返回 empty，不静默改用其他期间；返回项带公司、报告类型、期间起止、材料 ID、文件与页码。
- [compare.py](../agent/audit/tools/compare.py)：compare_claim 不再固定 period_kind=annual，按命中证据的报告类型裁决；compare_companies 双侧各走一次精确取证，两侧期间不一致时明确拒比。
- [compute.py](../agent/audit/tools/compute.py)、[specs.py](../agent/audit/tools/specs.py)：同比、趋势同样接受报告类型/材料 ID；工具规格与旧调用兼容（新参数全部可选）。
- [search.py](../agent/audit/tools/search.py)：正文索引改为「公司_年度::材料ID」，同年季报、半年报、年报各自独立；旧「公司_年度」键仍可读，但只在候选唯一时使用，多候选未指定期间时返回 ambiguous 并列出候选；命中携带公司、期间、文件与页码。[webui_pipeline.py](../agent/webui_pipeline.py) 写身份键，[routes.py](../agent/api/routes.py) 与 [webui_http.py](../agent/webui_http.py) 未指定材料时逐份检索并给每条命中标注来源。
- 复现探针：tool_half_amount_with_one_correct_fact 由「period_kind 不明确」变为「evidence_supported，报告类型 half、期间止 2025-06-30」。

### 4. Windows 页面加载与测试统一换行口径

### 5. 无数字方向核查；跨报告可比性三态

- [claim_check.py](../agent/audit/claim_check.py)：direction 主张复用已有证据与增长计算判上升/下降/持平，能算就给出确定性结论与修改建议；缺唯一证据或基期不可比时明确「证据不足」并写原因码，不再落进「无数值约束」的模型判断。
- [periods.py](../agent/periods.py)、[finance.py](../agent/finance.py)：新增逐维度三态 comparability（满足 / 冲突 / 未知）。同一披露比较表的内部算术不要求跨报告依据；跨报告派生在政策、合并边界、重述版本缺声明时为「未知」，**不默认一致**：返回 not_comparable，同时保留操作数、来源与被阻断的尝试值（attempted_value）。analyze 把被阻断的派生单列 blocked_derivations，结果包新增 qoq_blocked。默认约数容差 2%、显式上限 5%、预测只标记、证据质量限制均未改。

## 五、剩余缺口（本轮未做）

1. **真实模型未测**：所有评测都是离线固定协议回放或本地桩，没有模型拆句、工具循环与恢复的真实数据；至少三次重复运行后的业务结果、盲测隔离与人工复签仍未完成。
2. **非数值与复合句语义**（评审第二批 5）：定性、原因关系、会计事件、口径一致性与引用归属仍需独立证据类型；本轮只把无数字方向做成确定性核查。
3. **可比性依据来源**：三态已分清满足/冲突/未知，但抽取侧还不会从附注取 accounting_policy_version、consolidation_basis、restatement_version，因此真实材料之间的跨报告派生目前多为「未知」，显示为被阻断的尝试。
4. **字段与附注**（评审第三批 7、8）：成本、费用、合并净利润、应收/存货/负债等字段、会计事件台账、非经常性损益与现金流调节专题尚未补齐；指标目录仍为 14 项。
5. **通用关系**：增减金额、百分点、倍数、区间等仍未进入自然语言核查协议。
6. **交付工程**：本轮只给 agent/README.md 补了评测入口一行（其余仍以旧入口为主）；依赖安装哈希、干净机器演练与保留策略未补。
7. 本机回归在 Windows 与 Python 3.13 下执行；CI 矩阵为 3.11/3.12，尚未看到 CI 实际运行回执。
